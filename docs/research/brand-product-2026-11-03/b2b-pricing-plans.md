# B2B 요금제 설계 조사 — 390,000 · 690,000 · 990,000원 (월, 엔터프라이즈 B2B)

> 조사일 2026-11-03. 대표 결정: 세 금액은 고정. 이 문서는 **각 플랜에 무엇을 넣을지와 과금 방식**을 설계한다. 모든 숫자는 제안값이고, 확정은 대표 결정이다. 가격·법령은 공식 페이지를 직접 열어 확인했고, 못 연 것은 "미확인"으로 표시했다. 환율 1,400원/USD(docs/PLATFORM-2.0.md §9 기준).

## 0. 결론 먼저

1. **추천 1안 = 기능 중심 티어 + 월 제작 한도 + 초과분은 선불 크레딧 팩.** 세 금액이 이미 해외 셀프서브 상위 티어(Krea Business $200≈28만원, Creatify Business $136~195≈19~27만원, Omneky Pro $249≈35만원)보다 높다. 생성 횟수로는 정당화가 안 되고, **브랜드 학습(고정 층)·마감(그레이딩·사운드·업스케일)·사람 PD 시간·납기**로 가른다. 순수 크레딧 중심(2안)은 TWINGS를 범용 생성 도구로 보이게 해 AGENTS.md §5 포지션과 어긋나고, 기능 차단 고객의 플랜 가치를 설명할 수 없다.
2. **원가 대비 마진은 세 플랜 모두 100% 소진 가정에서 60~62%, 세금계산서(카드 수수료 0) 결제면 64~65%.** 엔진 원가는 플랜 가격의 25~33%에 불과하고, 가장 큰 변동비는 **PD 시간**이다(시급 50,000원 가정). 실제 소진율이 50%면 마진은 78~80%로 올라간다.
3. **과금 방식: 부가세 별도 표기 + 세금계산서 후불(계좌이체)을 기본, 카드 자동결제(토스 빌링)는 390,000원 플랜 셀프서브용으로 추가.** 토스 빌링은 "리스크 검토 및 추가 계약" 뒤에만 쓸 수 있고(공식 문서), 지금 계약(docs/TOSS-CONTRACT.md)에는 빌링이 없다. 법인은 전자세금계산서 의무발급 대상이라 세금계산서 경로는 어차피 필요하다.
4. **가격은 정할 때까지 비공개(BRAND-ENGINE §7-5).** 공개 페이지에는 플랜 3개의 이름과 "무엇이 들어있나"만 두고, 금액은 "문의 → 견적 → 계약"으로 전달한다. 셀프서브(카드 자동결제·즉시 개통)는 390,000원 플랜만, 그것도 토스 빌링 승인 + B2B 약관 별지 + 세금계산서 자동 발행이 갖춰진 뒤.
5. **기능 차단 고객(경쟁사 겸 고객)은 엔진 플랜을 팔지 않는다.** 기존 캠페인·운영 워크스페이스 계약(견적 기반, 제4조의2)으로 남기고, 계약서 별지에 "제공 범위"를 명시한다. 플랜 매트릭스는 전 고객 동일, 차단은 계약 별지와 조직 deny-list로만.

## 4. 예외 정책 — 기능 차단 고객(경쟁사 겸 고객)

- **기본값은 전 고객 전체 기능 개방, 차단은 조직별 deny-list**(`generative_media`, `sound`, `color_grading`)로만 한다. 훅 지점은 repo-brand-surface 보고서(`lib/brands/entitlements.ts` 제안)를 따른다.
- **플랜 가치 조정 방식 (추천 a).** 차단 고객에게는 §3.2 엔진 플랜을 **팔지 않는다.** 지금처럼 캠페인·크리에이터 운영·2차 활용 워크스페이스 계약(약관 제4조의2, 견적 기반)으로 둔다. 플랜 매트릭스가 공개되어도 "같은 돈에 기능이 빠진 플랜"이 생기지 않고, 차단 사실을 가격표에 드러내지 않아도 된다.
- 대안 b: 같은 금액에 차단 기능을 **운영 가치로 치환**(PD 시간 +1h, 캠페인 리포트, 좌석 추가). 원가가 줄어 마진은 오르지만 "왜 우리만"이라는 질문을 부른다.
- 대안 c: 별도 SKU "운영·협업 플랜"(엔진 없음, 낮은 가격). 공개 가격표가 복잡해지고 경쟁사가 가격을 추정하기 쉬워진다.
- **계약서 문구 예(법무 검토 전 초안):** "회사가 고객에게 제공하는 기능의 범위는 별지 A(제공 범위)에 한정한다. 별지 A에 기재되지 않은 기능(생성형 미디어 제작, 사운드 마감, 컬러 그레이딩을 포함하되 이에 한정하지 않는다)은 본 계약의 제공 범위에 포함되지 않으며, 회사는 이를 제공할 의무를 지지 않는다. 고객은 해당 기능의 미제공을 이유로 대금 감액, 손해배상 또는 계약 해지를 주장하지 않는다. 회사는 고객의 요청 시 별지 A의 변경을 협의할 수 있으나 이에 응할 의무는 없다."
- 약관규제법 제9조(해지권 배제 무효)와 충돌하지 않게 "미제공을 이유로 한 해지"만 막고, 다른 사유의 해지권은 남긴다.
- 운영 규칙: 차단은 **관리자 오퍼레이션**(`lib/admin/operations.ts`)으로만 바꾸고, 변경 이력을 남긴다. 알림 메일·내비·API까지 한 함수를 부르게 한다(repo-brand-surface 제안).

## 5. 가격 노출과 구매 경로

### 5.1 공개 여부
- BRAND-ENGINE §7-5: **정하기 전에는 가격 노출 금지.** 대표가 §3의 구성을 확정해도, 1차는 **플랜 이름 + 포함 기능 표만 공개하고 금액은 숨긴다**(Typeface·Adobe·Pencil Pro·Higgsfield Enterprise 방식). 이유: (1) 토스 빌링·약관 개정 전에는 결제가 없어 가격만 노출되면 "문의만 늘고 전환은 없다" (2) 경쟁사 겸 고객이 가격표를 본다 (3) 첫 5~10곳은 견적 협상으로 실제 지불 의사를 재는 편이 낫다.
- 공개 시점 후보: 계약 5곳 이상 + 토스 빌링 승인 + B2B 약관 별지 적용 → 390,000원만 공개하고 상위 2개는 "문의".

### 5.2 문의 → 견적 → 계약 경로 (지금 코드로 되는 것 위주)
1. brand.twings.app 플랜 페이지: 플랜 3개 카드(금액 없음) + "견적 문의" 폼 — 기존 브랜드 의뢰 폼(약관 §8-5, 관리자 문의함) 재사용, 필드에 **플랜 선택·브랜드 수·좌석·월 예상 제작량·결제 방식(세금계산서/카드)** 추가.
2. 스튜디오가 견적 발행: 2차 활용의 견적 흐름(`lib/brands/usage/service.ts`, 총액·세금 기준·유효기한·조건 PDF)을 **플랜 견적**으로 확장. 세금 별도 견적은 안내용, 결제용은 세금 포함 총액 — 지금 규칙 그대로.
3. 계약: 조건 PDF(별지 A 제공 범위, 별지 B 한도·초과·이월) 공유 → 수락.
4. 결제: (a) 세금계산서 후불 — 월말 사용량 확정 → 익월 10일 전 발행(팝빌 API) → 계좌이체 입금 확인 → 다음 달 개통 유지. (b) 카드 — 토스 빌링키 발급 → 매월 승인(스케줄러 자체 구현).
5. 개통: 조직 생성(`brand_organizations`) + 플랜·한도·deny-list 기록(새 테이블, repo-billing-b2b 제안 참조) + 온보딩 PD 세션.

### 5.3 셀프서브 최소 조건 (390,000원 Core만)
