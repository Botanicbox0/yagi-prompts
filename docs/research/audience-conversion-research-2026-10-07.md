# TWINGS: 브랜드·크리에이터 전환 구조 조사

조사일: 2026-10-07. 대상: Brandazine, Insense, Billo, HeyGen. TWINGS의 기존 포지션과 스튜디오 운영 모델을 유지하면서 공개 탐색, 로그인, 작업 복귀, 모바일 웹·앱의 역할을 정리한다.

## 1. 결론

TWINGS는 같은 서비스 안에서 **크리에이터가 템플릿을 고르는 문**과 **브랜드가 캠페인을 의뢰하는 문**을 분명하게 보여주는 편이 적합하다. 역할 선택은 공개 페이지의 목적과 CTA를 바꾸는 탐색 수단으로 삼고, 계정 유형이나 접근 권한을 바꾸는 기능으로 취급하지 않는다.

크리에이터의 첫 행동은 `템플릿 둘러보기`, 브랜드의 첫 행동은 `캠페인 의뢰하기`가 된다. 크리에이터는 만들기·지원하기 시점에 로그인하고 선택했던 대상으로 돌아온다. 브랜드는 공개 설명과 사례를 본 뒤 의뢰하고, 실제 진행 자료와 승인 업무는 기존 브랜드 워크스페이스에서 처리한다. YAGI의 개별 영상·필터 제작은 브랜드 캠페인 아래의 보조 서비스로 배치한다.

이 결론은 경쟁사의 전환율이 높다는 실험 결과가 아니다. 아래 공식 화면·문서에서 확인한 역할 분리와 작업 구조를 TWINGS의 승인된 범위에 맞게 해석한 설계 제안이다.

## 4. Brandazine에서 가져올 구조와 가져오지 않을 전제

### 역할과 서비스의 정보 위계

Brandazine의 브랜드 홈은 브랜드가 얻는 결과를 설명하고 Creator를 별도 문으로 제공한다. 서비스 하위 구분은 브랜드 관점의 운영 방식이다. Studio Pro는 기획·모집·소통·실행을 운영사가 맡는다고 설명하고, Studio와의 차이를 따로 비교한다. TWINGS 브랜드 랜딩에는 이처럼 **누가 무엇을 하는지**가 먼저 보여야 한다. [브랜드 홈](https://www.brandazine.com/en), [Studio Pro](https://www.brandazine.com/en/studio-pro)

TWINGS에 적용할 문장 구조는 `브랜드가 목표와 제품을 전달한다 → 스튜디오가 포맷과 캠페인을 운영한다 → 선정된 크리에이터가 게시한다 → 브랜드가 진행 결과를 확인한다`이다. 브랜드가 직접 크리에이터를 고르고 캠페인을 개설하는 셀프서비스를 이미 제공하는 것처럼 보이게 만들면 현재 운영 모델과 어긋난다.

### 브랜드 문의와 가입 전후의 구분

메인 담당자가 IAB에서 직접 연 `/en`의 Contact Us는 로그인 없이 열리는 문의 모달이었다. 회사·카테고리·Instagram·지역·이메일, 선택 전화번호·메시지, reCAPTCHA를 확인했다. 문의를 제출하지는 않았다. TWINGS도 브랜드의 첫 의뢰를 워크스페이스 가입보다 앞에 둘 수 있다는 직접적인 참고 사례다. [브랜드 홈](https://www.brandazine.com/en)

별도로 Studio 공개 마크업에는 브랜드명·웹사이트·Instagram·카테고리·조직 규모를 받는 단계와, 이메일을 이어받아 계정·전화 확인을 하는 단계가 있다. 완료 상태 문구와 워크스페이스 진입 버튼도 포함돼 있다. 이것은 공개 소스에 남아 있는 흐름이며, **현재 Contact Us의 실노출 문의 폼과는 구분한다.** 비노출 또는 이전 구현일 수 있고, 현재 Get Started 연결과 실제 승인 후 권한은 미확인이다. [Studio](https://www.brandazine.com/en/studio)

공식 FAQ에 따르면 워크스페이스는 콘텐츠 현황·협업 이력·성과를 확인하는 곳이며, 같은 구성원이 복수 브랜드를 운영할 수 있다. 이 구조는 TWINGS에서도 **공개 브랜드 소개**와 **로그인한 브랜드 업무 공간**을 다른 목적으로 구분할 근거가 된다. 구독·환불·라이선스 조건은 TWINGS에 전용하지 않는다. [Brandazine FAQ](https://www.brandazine.com/faq)

### 크리에이터: 탐색을 먼저 허용하고 신청 시점에 가입

메인 담당자의 IAB 직접 관찰은 다음과 같다. Creator 랜딩의 체험 CTA로 `/web`에 들어가 온보딩을 건너뛰면, 앱 설치 없이 For you·캠페인·대여 탐색이 가능했다. 캠페인 카드에서는 상세 화면으로 이동했고 리워드·일정·가이드를 읽을 수 있었다. 상세의 고정 신청 CTA와 팔로워 자격 안내를 확인했다. [Creator 랜딩](https://creators.brandazine.com/), [공개 웹앱](https://creators.brandazine.com/web), [확인한 캠페인 상세](https://creators.brandazine.com/web/campaign/01a0132b-e743-7088-b6a3-9849b48b5fc5)

신청 CTA는 `creator-signup.brandazine.com`으로 이어졌고 Instagram 시작 버튼과 필수 약관·개인정보·콘텐츠 수집 활용 동의를 확인했다. Instagram 인증 버튼은 실행하지 않았으므로 로그인 완료 뒤 원래 캠페인으로 돌아오는지는 미확인이다. **탐색 → 상세 → 가입 요청**까지는 실제 관찰이며, **가입 → 신청 완료**는 관찰 범위 밖이다. [가입 페이지](https://creator-signup.brandazine.com/)

리서치 담당자의 HTTP 요청은 Creator 페이지의 200 응답과 제목만 얻었고 웹 텍스트 추출에서는 본문이 나오지 않았다. 메인 담당자의 브라우저 확인으로 실제 공개 탐색이 가능함을 보완했다. 텍스트 추출 실패를 사이트 미작동이나 앱 설치 강제의 근거로 사용하지 않는다.

앱 개발자의 App Store 소개는 협업·제품 대여·콘텐츠 성과 확인을 설명한다. 앱 존재와 운영사 설명까지는 근거가 있지만 로그인한 내부 화면을 직접 검증한 것은 아니다. 검색에 남아 있는 `/en/new-creator/creator`는 이번 직접 요청에서 404였으므로 현재 전환 흐름의 근거에서 제외했다. [공식 앱 소개](https://apps.apple.com/kr/app/%EB%B8%8C%EB%9E%9C%EB%8D%94%EC%A7%84/id1327738051)

## 5. Insense와 Billo에서 가져올 작업 중심 구조

Insense는 브랜드의 자율 운영과 운영 대행을 구분한다. TWINGS는 두 방식을 동등한 제품처럼 나열하기보다, 현재 제공하는 스튜디오 운영 캠페인을 주력으로 설명하면 된다. 제작만 필요한 브랜드의 요청은 그 아래에서 받을 수 있다. [Insense 솔루션 구분](https://insense.pro/)

Insense 도움말의 브랜드 첫 화면은 마케팅 소개를 반복하지 않고 진행 캠페인과 새 지원·메시지·콘텐츠 검토를 보여준다. TWINGS 브랜드 워크스페이스의 재방문 화면도 `현재 진행 중인 의뢰`, `검토할 자료`, `승인 또는 확인할 항목`, `리포트`처럼 실제 후속 행동을 앞세우는 것이 맞다. 이 순서는 설계 제안이며 해당 항목이 모두 현재 구현돼 있다는 뜻은 아니다. [공식 캠페인 관리 도움말](https://help.insense.pro/4333)

크리에이터의 탐색과 진행 업무를 분리하는 점도 유용하다. Insense는 Explore와 My Work를 나누고, 후자에는 지원·선정·제작·검토·게시 단계를 보여준다. 캠페인 상세는 지원 전에 금액·배송·제품·산출물·게시 여부·기술 조건을 설명한다. TWINGS는 기존 승인된 캠페인 정보로 `내가 해야 하는 일`, `기한`, `선정 조건`, `게시·정산 조건`을 먼저 읽게 할 수 있다. [앱 구조](https://help-creators.insense.pro/4524), [캠페인 브리프](https://help-creators.insense.pro/4525)

Billo의 도움말은 브랜드 가입 후 탐색과 계획이 가능하고, 크리에이터 초대나 브리프 공개 시점에 결제가 필요하다고 설명한다. 도입할 원리는 **탐색과 실행의 경계가 명확하다**는 점이다. Billo의 선결제 모델·금액·권리 조건은 TWINGS 결제 설계의 근거로 쓰지 않는다. [브랜드 시작 도움말](https://help.billo.app/en/articles/5279357-getting-started-guide-for-brands)

Billo는 브랜드와 크리에이터의 잘못된 가입을 지원팀이 해결해야 한다고 안내한다. TWINGS의 Brand / Creator 전환은 이와 같은 계정 유형 잠금으로 만들 필요가 없다. 공개 탐색 모드와 실제 브랜드 워크스페이스의 구성원 권한을 구분해야 한다. [로그인 문제 도움말](https://help.billo.app/en/articles/6042705-experiencing-login-issues)

## 6. 템플릿 선택 → 로그인 → 작업 복귀

HeyGen 공식 문서에서 확인되는 것은 로그인 후 템플릿을 고르고 편집·검토·생성하는 일관된 작업 흐름이다. 이번 조사에서는 익명으로 고른 템플릿이 로그인 뒤 자동으로 복원되는 사례를 직접 입증하지 못했다. 따라서 아래 흐름을 경쟁사에서 검증된 기능으로 주장하지 않고 **TWINGS 자체의 완료 기준**으로 둔다. [HeyGen 템플릿 문서](https://help.heygen.com/en/articles/13466178-how-to-use-templates-in-heygen-to-streamline-video-creation)

| 사용자의 진입 의도 | 로그인 전에 보여줄 것 | 로그인 이후 이어질 작업 |
| --- | --- | --- |
| 이 템플릿으로 만들기 | 예시 영상·이미지, 제목, 필요한 사진 안내, 기존 가격·이용 안내 | 선택한 템플릿의 만들기 단계. 얼굴 준비가 필요하면 마친 뒤 같은 템플릿으로 복귀 |
| 이 캠페인에 지원하기 | 브리프·일정·기존 보상 조건·요구사항 | 선택한 캠페인의 지원 폼. 모집 종료·자격 제한이면 해당 상태와 대안 안내 |
| 내 작품 다시 열기 | 로그인 필요 안내 | 원래 작품 또는 내 작품 목록 |
| 기존 브랜드 업무 계속하기 | 브랜드 워크스페이스 로그인 안내 | 원래 요청한 업무 화면. 구성원 권한은 서버에서 검증 |
| 처음 캠페인 의뢰하기 | 서비스 설명·사례·의뢰 폼 | 기존 의뢰 접수 흐름과 정확한 접수 상태. 불필요한 선행 계정 단계 추가 금지 |

구현 검토 사항:

- `audience`는 탐색 맥락, `returnTo`는 복귀 목적지, 워크스페이스 권한은 서버의 실제 멤버십으로 각각 취급한다.
- 템플릿 slug·캠페인 slug·로케일을 인증 왕복에서 유지한다. 인증 성공 후 무조건 홈이나 계정으로 보내지 않는다.
- 명시적인 딥링크가 저장된 탐색 모드보다 우선한다. 브랜드 모드를 마지막에 봤다는 이유로 공유받은 템플릿을 브랜드 홈으로 바꾸지 않는다.
- 복귀 주소는 기존 안전한 내부 경로 검증을 유지한다. 얼굴 사진·토큰·민감 정보는 URL이나 분석 이벤트에 넣지 않는다.
- 로그인 문은 기존 제품 결정대로 짧게 유지한다. 선택한 작업을 알리는 최소 맥락과 원래 페이지로 돌아갈 경로만 보강한다.
- 공개 생성 기능이 닫혀 있으면 현재 상태를 사실대로 보여준다. 탐색 CTA를 생성 가능 약속으로 바꾸지 않는다.

## 7. 모바일 웹과 향후 앱

Brandazine은 크리에이터의 설치 없는 웹 탐색을 실제 제공하며, 브랜드 워크스페이스 쪽 공개 마크업에는 데스크톱 안내와 이메일 전달 경로가 있다. Billo와 Insense는 크리에이터 업무를 앱으로 안내한다. TWINGS는 사용자의 이번 요구대로 **탐색을 로그인·유료 결제·앱 설치로 막지 않는 모바일 웹**을 우선할 수 있다. 경쟁사가 앱을 제공한다는 사실만으로 TWINGS에도 초기 설치 장벽이 필요하다고 결론낼 수 없다. [Brandazine 웹앱](https://creators.brandazine.com/web), [Studio](https://www.brandazine.com/en/studio), [Billo 크리에이터](https://billo.app/for-creators/), [Insense 크리에이터](https://insense.pro/for-creators)

HeyGen은 모바일 앱과 웹을 별도 경험으로 설명하며 워크스페이스 전환·고급 편집 등의 차이를 명시한다. 모바일 브라우저에서 카메라·마이크를 허용하는 공식 안내도 있다. 앱 유무와 모바일 웹의 사용 가능성은 별도로 검증해야 한다. [모바일 기능 차이](https://help.heygen.com/en/articles/10207693-how-to-get-started-with-heygen-for-mobile), [모바일 브라우저 권한 안내](https://help.heygen.com/en/articles/15519101-how-to-access-your-camera-and-microphone-on-your-mobile-device)

TWINGS 권고:

1. 작은 화면에서도 Brand / Creator 진입점을 쉽게 찾을 수 있게 한다. 주 CTA는 현재 모드의 목적에 맞추고, 두 관객의 피치를 같은 첫 화면에 동등하게 섞지 않는다.
2. 크리에이터 탐색은 미디어·템플릿명이 중심이다. 세부 가격은 기존 규칙대로 상세·요금표에 두고, 캠페인 참여 조건과 작품 관리는 별도 목적지로 제공한다.
3. 상세 페이지의 주요 행동은 터치하기 쉽고 콘텐츠를 가리지 않아야 한다. 세로 스크롤, 키보드, 안전 영역, 뒤로가기, 파일 선택 후 복귀를 실기기에서 검증한다.
4. 로그인, 사진 준비, 생성 대기, 완료 작품, 캠페인 지원·현황을 모바일 웹에서 한 흐름으로 마칠 수 있게 한다. 단계 중단 시 원래 대상과 상태가 보존돼야 한다.
5. 향후 앱은 이미 열린 템플릿·작품·캠페인 링크를 같은 대상으로 연결하고, 알림·카메라·공유의 편의를 보강하는 방향으로 설계한다. 설치하지 않은 사람에게는 웹 목적지를 제공한다.
6. 앱 결제 정책·로그인 제공사·푸시·신규 가격은 별도 결정과 검증 사항이다. 현재 개편 문안에서 출시 시점이나 앱 기능을 약속하지 않는다.

## 8. TWINGS 정보구조에 대한 제안

| 관객·상황 | 공개 화면의 핵심 순서 | 주 CTA | 보조 행동 |
| --- | --- | --- | --- |
| Creator / 첫 방문 | 내 얼굴 결과 예시 → 템플릿 탐색 → 이용 절차 → 캠페인 참여 안내 | 템플릿 둘러보기 | 모집 중 캠페인 보기 |
| Creator / 재방문 | 만들던 대상 또는 작업 상태 → 내 작품 → 내 지원 현황 | 해당 작업 이어가기 | 새 템플릿 보기 |
| Brand / 첫 방문 | 스튜디오 운영 캠페인 설명 → 활용 방식·실제 사례 → 진행 방식 → 의뢰 폼 | 캠페인 의뢰하기 | 제작 서비스 보기 |
| Brand / 진행 중 | 진행 요청·승인할 항목·결과 확인 | 기존 브랜드 워크스페이스 열기 | 추가 의뢰하기 |

`캠페인`이라는 같은 단어 아래 브랜드 판매 설명과 크리에이터 모집 목록을 연속해서 놓으면 도착한 사람의 다음 행동이 불명확해질 수 있다. 두 화면의 제목·내비·CTA를 관객에 맞게 분리하고 기존 캠페인 상세·지원 URL은 보존한다. 구체적인 새 경로와 리디렉션은 기존 호스트·로케일·캐시·인증 규칙을 검토해 결정한다. 공개 브랜드 랜딩을 만든다고 기존 `brand.twings.app`의 인증 역할을 바꾸지는 않는다.

문안은 다음 제약을 유지한다: 크리에이터 포지션은 `내 얼굴로 트렌드 포맷의 주인공이 되는 곳`; 브랜드 주력은 스튜디오 운영 캠페인; 제작·필터는 보조 서비스; 공개 사례·수치는 승인분만; 얼굴 검수·계정·결제·환불 절차는 현재 약관과 일치. 새 수익 보장, 운영 일정 보장, 가격, 이용 권한을 경쟁사 표현에서 가져오지 않는다.

## 9. 구현 후 확인할 전환 기준

이 문서는 코드 변경이나 기능 검증 완료 보고가 아니다. 아래 항목은 메인 구현의 확인 기준이다.

- 익명 방문자가 데스크톱·모바일 웹에서 역할을 바꾸고 템플릿·브랜드 사례·캠페인 조건을 열 수 있다.
- 템플릿 상세에서 로그인·취소·뒤로가기를 거쳐도 같은 템플릿 맥락을 유지한다.
- 캠페인 지원 로그인 후 해당 지원 화면으로 복귀한다. 모집 종료나 접근 제한은 빈 화면 대신 현재 상태를 설명한다.
- 브랜드 문의는 기존 폼의 유효성 검사와 실제 접수 결과를 유지한다. 브랜드 워크스페이스 링크는 인증·멤버십 검증을 계속 거친다.
- URL 직접 접근·새로고침·언어 전환·기존 공유 링크가 탐색 모드 저장값 때문에 다른 대상으로 이동하지 않는다.
- 로그인 이후 기존 내 작품·내 지원·브랜드 업무 동선이 공개 랜딩으로 회귀하지 않는다.
- 작은 화면에서 가로 넘침, 미디어 포스터, 버튼 가림, 입력 키보드, 인증 왕복과 파일 선택을 확인한다.

성과 계측을 추가한다면 `역할 선택 → 공개 상세 열기 → 주 행동 클릭 → 로그인 시작/완료 → 원래 작업 도착 → 지원/의뢰/생성 완료`를 구분한다. 이는 계측 설계 제안이며 아직 관측한 전환율이나 신규 분석 수집 승인이라는 뜻은 아니다.

## 10. 남은 확인 공백

- Brandazine의 Creator 실제 인증 이후 캠페인 복귀·지원 완료, 브랜드 가입 완료·승인·첫 워크스페이스. IAB의 모바일 폭 웹앱 관찰은 실제 모바일 기기 검증과 구분한다.
- Insense·Billo의 로그인 화면 실렌더와 실제 인증 후 첫 방문·재방문 차이.
- HeyGen의 익명 템플릿 선택 및 로그인 후 그 선택 복원. 현재 근거로는 지원 여부를 단정할 수 없다.
- 모든 서비스의 실제 모바일 앱·모바일 브라우저 기능 동등성, 앱 미설치 딥링크 처리, 접근성·성능·전환율.

따라서 시각적 완성도나 마찰의 우열을 실사용 테스트 결과처럼 순위화하지 않는다. Brandazine은 역할·운영 모델, Insense는 업무 상태, Billo는 관객별 진입과 실행 경계, HeyGen은 템플릿 작업과 기기별 기능 구분의 참고 사례로 사용했다.
