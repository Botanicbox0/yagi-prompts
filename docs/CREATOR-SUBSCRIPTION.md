# 크리에이터 월 구독 — 2026-10-08

대표 최신 결정: **월 29,000원 크리에이터 / 월 49,000원 Advanced**, 부가세 포함·크레딧 기반. 환율 1,400원/USD, 계약 할인 없음, **부가세 제외 매출에서 직접비 차감 마진 8~10%** 기준을 10월 8일 확인했다. 이전 크레딧 노출 금지·19,000원 단일 플랜은 이번 직접 지시로 대체한다. PG의 크레딧 방식 수용은 미확인이다.

## 구현 상태

불변 가격 카탈로그, 가격·동의 조건 보관용 DB 스키마/소유자별 조회, 두 플랜 비교 계산기와 한영 요금표·템플릿·FAQ·메타를 구현한다. **0042 + 0127 마이그레이션은 클라우드 적용 필요**. 운영 DB는 변경하지 않았다. 준비 상태 함수는 항상 닫혀 있다.

구독 가입·승인·월 장부·갱신·해지·환불·실시간 준비 증거 판정은 미구현이다. 현재 단건 결제·생성 게이트·법무 문서는 유지한다. 구독은 출시 준비안으로만 안내하고 판매 가능한 Product/Offer를 내보내지 않는다. 계산기는 실제 잔량이 아니다. 다른 채팅의 템플릿은 임의로 수정·게시하지 않는다.

## 가격 버전과 가입 시 동의 조건

| 버전 | 월 가격 | 월 크레딧 | 상태 |

- 가격·통화·부가세·주기·월 제공량·차감/원가 규칙 버전·미이월 조건을 고정 보관한다. 기존 가격/동의 기록의 UPDATE/DELETE를 차단한다. 변경은 새 버전/동의 기록으로 추가한다. 과거 원가/차감 규칙도 덮어쓰지 않는다.
- 향후 실제 구독과 각 결제 주문은 `creator_subscription_terms.id`를 참조해야 한다. 현재 마케팅 플랜으로 갱신액·지급량·차감량을 재계산하지 않는다.
- 동의 기록은 사용자·플랜 버전·약관 버전·동의 증빙 참조·동의 시각을 보관한다. 실제 사용자 동의 기록은 없으며 runtime INSERT 권한도 아직 부여하지 않았다. 가입 구현 시 출시/실제 동의 검증 writer를 별도 추가한다.
- 조회는 사용자와 동의 기록 ID가 모두 일치해야 한다. 미등록 버전·소스/DB 불일치는 실패 처리하며 최신 요금으로 대체하지 않는다. 동의 기록 자체는 결제 성공이나 이용 권한이 아니다.
- 인상/무료→유료는 최신 법정 고지·동의 요건 및 토스 계약을 확인한 뒤 별도 동의와 적용일에 따라 청구한다. 미동의 고객에게 새 금액을 청구하지 않는다. 조건 유지/적법한 종료 정책은 출시 때 확정한다.
- 계약 자료의 보존/파기와 계정 삭제 절차는 운영 전 확정한다. 현재 FK는 임의 연쇄 삭제를 막으며 개인정보를 추가 복제하지 않는다.

## 원가와 제공량 계산

BytePlus ModelArk `dreamina-seedance-2-5-260628`, **영상 입력 없는** 사진/텍스트 참조 기준. 720p $10.70 / 100만 토큰, 1080p $11.70 / 100만 토큰. 2026-10-08 공식 가격 페이지의 렌더된 표에서 재확인했다. 할인 없이 계산하며 오디오 비용을 다시 더하지 않는다.

예상 토큰 = 출력 초 × 가로 × 세로 × 24 fps ÷ 1024. 최종 원가는 `usage.completion_tokens` 기준. 참조 영상 입력 시 입력 길이·최소 토큰·다른 단가로 재설계해야 한다. 예시 영상은 생성 입력이 아니다.

## 결제 연결 후 자동 전환 설계 — 대표 후속 지시 2026-10-07

대표는 지금 사이트를 결제 연결 전 상태로 설계하고, 결제 시스템이 붙으면 안내가 함께 갱신되길 요청했다. 아래는 **후속 구현 명세**이며 이번 요금표 배포에 자동결제나 준비 상태 판정기가 구현됐다는 뜻이 아니다.

### 준비 상태의 단일 원본

현재 `getCreatorSubscriptionAvailability()`는 항상 preparing/canSubscribe:false다. 정기결제 구현 시 서버 전용 증거 판정기로 확장한다. 가격과 이용량은 플랜 설정, 가입 가능 여부는 아래 증거의 교집합에서 읽는다. 이메일 승인 문구나 UI 플래그 하나만으로 가입을 열지 않는다.

| 판정 조건 | 확인할 실제 증거 |
| --- | --- |
| 자동결제 계약 | 해당 사업자·빌링 MID의 심사/계약 완료 기록 |
| 운영 자격 | 서버의 라이브 빌링 키 존재·환경 일치, 공개 생성 게이트 개방 |
| 이용 권한 | 운영 DB 장부/주문/갱신 마이그레이션 버전, 사용자별 접근 제어 |
| 결제 절차 | 등록 → 승인 → 월 이용량 부여, 중복 승인·실패 복구 검증 결과 |
| 구독 종료 | 다음 갱신 중단·기간 종료·실패 안내·환불 흐름 검증 결과 |
| 문안과 원가 | 대표 확정 구독 약관 버전, 실제 PG 수수료·직접비로 전량 사용 시 목표 마진 재검증 |

공개 응답에는 `status: preparing | open | paused`, 플랜 표시값, 안내 문구 버전만 포함한다. MID·키·내부 오류와 계약 증거는 서버에만 둔다. 필수 증거가 없거나 읽기에 실패하면 `preparing`을 유지한다. 운영 장애 시 신규 신청은 `paused`로 바꾸되 기존 회원의 결제/이용 기록을 삭제하거나 임의로 초기화하지 않는다.

### 한 번에 바뀌는 사용자 화면

- 요금표·템플릿 상세·FAQ·메타 문구는 같은 준비 상태와 ko/en 사전을 읽는다. `preparing`에서는 지금의 출시 전 예시와 신청 불가 안내, `open`에서는 실제 제공 조건과 구독 신청 CTA를 보여준다. 소스별로 별도 boolean을 두지 않는다.
- 가입 버튼은 실제 빌링 등록 라우트가 있을 때만 나타난다. 서버 주문 생성에서도 같은 상태를 다시 확인한다. 화면의 상태나 이용량 계산만으로 영상 생성 권한을 부여하지 않는다.
- 가입 완료 이후 계정 화면의 갱신일·해지·사용 내역은 서버 구독 장부에서 읽는다. 공개 요금표 미리보기 수치를 계정 잔량으로 재사용하지 않는다.
- 공개 페이지가 1시간 캐시이므로 전환 시 기존 카탈로그/준비 상태 캐시 태그를 무효화하고 ko/en 요금표·FAQ·관련 템플릿 상세·SEO 안내를 함께 재검증한다. 버전이 다른 페이지가 남아 있으면 전환 완료로 기록하지 않는다.
- 다른 채팅의 템플릿 작업은 카탈로그를 통해 반영한다. 미확정 가격/엔진/길이/비율은 임의로 확정하지 않으며, 구독 대상 모델의 원가가 검증된 템플릿부터 포함한다.

### 답변 추적과 후속 반영

기존 2시간 간격 회신 추적 작업은 새 토스 답변을 지정 Slack 채널에 알리고, 계약과 기능 구현의 진행 상태를 구분한다. 심사 승인만 온 경우 요구 자료·남은 구현 작업을 갱신한다. 실제 결제 통합이 완료되면 이 명세에 맞춰 공통 판정기와 연결 화면을 구현하고, 필수 검증 → PR/프리뷰 → Production → 실제 도메인 확인 순서로 반영한다. 현재 대표 지시는 이 조건을 충족한 사이트 안내 후속 반영을 승인한 것으로 기록한다. 계약 서명·가입비 결제·운영 비밀값 입력은 별도 운영 단계다.

중복 실행 방지는 `준비 상태 버전 + 플랜 버전 + 구현 커밋`으로 한다. 같은 버전은 새 PR/배포/Slack 메시지를 만들지 않는다. 원가 가정이 바뀌면 자동으로 가격이나 월 제공량을 바꾸지 않고 변경 근거를 대표에게 먼저 알린다. 새 회신이나 실행 가능한 상태 변화가 없으면 조용히 유지한다.
