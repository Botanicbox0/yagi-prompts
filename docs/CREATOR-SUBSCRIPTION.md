### 수정 API 비용과 가격 합리성

49,000원에서 영상 이용량을 전부 쓰면 수정 전 마진은 9.20%다. 추가 수정 API 비용이 월 **약 536.66원 이하**이면 전량 사용 마진 8% 이상, **약 1,873.02원 이하**이면 5% 이상이다. 계산은 `순매출 × (수정 전 마진 - 목표 마진)`이며, 제공량에 숨은 재생성비나 임의 운영비를 다시 넣지 않는다. 참고 이미지 분석 비용도 실제 수정비에 포함한다.

실제 모델과 요청/출력 길이를 정하기 전에는 수정 횟수나 비용을 확정할 수 없다. 출시 전 실제 API 사용량으로 요청당 비용을 측정하고 월 한도·최대 입력/출력 토큰·템플릿별 수정 범위를 정한다. 예산이 부족하면 먼저 호출 길이·캐시·구조화된 변경안을 최적화한다. 무제한 수정과 결과 품질 보장은 하지 않는다. 다른 회사의 비공개 마진율이 상위 플랜에서 낮다고 가정해 사업성을 증명하지 않는다.

Opus 4.6의 공개 요금표 검토: 게시 차단 문제는 없고, 프리미엄은 편당 가격 할인만으로는 차별이 약하므로 맞춤 수정과 함께 출시하는 편이 설득력 있다. 따라서 **24,900원/49,000원과 영상 제공량은 유지**한다. 프리미엄은 맞춤 수정 원가·범위·실제 동작 검증까지 완료한 뒤 판매한다. 구독 공통 준비 상태만 충족했다고 미완성 맞춤 수정이 포함된 프리미엄 판매를 열지 않는다. 이 검토에 내부 소스·원가·마진·보안 구현은 전달하지 않았으며, 원가 산식은 저장소 테스트로 별도 검증한다.

이미지·Seedance 2.0의 짧은 영상은 원가 검증 없이 이 2.5 견적에 포함하지 않고 '구독 포함 여부 확인 중'으로 표시한다. 15초를 넘는 기존 2.0 템플릿은 실제 렌더처럼 2.5로 계산한다. adaptive 비율·알 수 없는 모델·지원 밖 길이는 견적을 내지 않는다.

## 실제 판매 전 필요한 작업

1. 토스 계정 접근 오류 해결 및 자동결제 추가 심사·계약. 상담 접수와 승인은 구분한다.
2. 빌링 전용 키·등록창·별도 공개 플래그·암호화한 빌링키 저장·사용자 동의 기록. 서버가 플랜 ID로 24,900원 또는 49,000원을 결정하고 브라우저의 금액을 신뢰하지 않는다.
3. 승인 확인 후에만 월 이용량 부여. 중복 등록·승인·갱신은 같은 주문으로 복구한다.
4. 생성 예약 시 월 장부를 원자적으로 잠그고 사용량 차감, 실패 시 한 번만 복구. 얼굴·제공사 검수는 단건과 동일하다.
5. 자동 갱신 일정·해지 시 다음 결제 중단·이용기간 종료·미이월·결제 실패 안내. 불명확한 결제는 재조회한다.
6. 대표가 정기결제·해지·갱신 고지·환불 문안을 확정하고 약관·환불·개인정보 문서와 UI를 함께 갱신한다. 단건 환불을 구독 전체 환불로 재사용하지 않는다.
7. 클라우드 장부 마이그레이션, 테스트 결제·실패·환불·해지·갱신 검증, 라이브 빌링 키 확인 후 신청 버튼을 연다.

## 결제 연결 후 자동 전환 설계 — 대표 후속 지시 2026-10-07

대표는 지금 사이트를 결제 연결 전 상태로 설계하고, 결제 시스템이 붙으면 안내가 함께 갱신되길 요청했다. 아래는 **후속 구현 명세**이며 이번 요금표 배포에 자동결제나 준비 상태 판정기가 구현됐다는 뜻이 아니다.

### 준비 상태의 단일 원본

정기결제 구현 시 서버 전용 `getCreatorSubscriptionAvailability()`를 만든다. 가격과 이용량은 플랜 설정, 가입 가능 여부는 아래 증거의 교집합에서 읽는다. 이메일 승인 문구나 UI 플래그 하나만으로 가입을 열지 않는다.

| 판정 조건 | 확인할 실제 증거 |
| --- | --- |
| 자동결제 계약 | 해당 사업자·빌링 MID의 심사/계약 완료 기록 |
| 운영 자격 | 서버의 라이브 빌링 키 존재·환경 일치, 공개 생성 게이트 개방 |
| 이용 권한 | 운영 DB 장부/주문/갱신 마이그레이션 버전, 사용자별 접근 제어 |
| 결제 절차 | 등록 → 승인 → 월 이용량 부여, 중복 승인·실패 복구 검증 결과 |
| 구독 종료 | 다음 갱신 중단·기간 종료·실패 안내·환불 흐름 검증 결과 |
| 문안과 원가 | 대표 확정 구독 약관 버전, 실제 PG 수수료·직접비로 전량 사용 시 목표 마진 재검증 |

공개 응답에는 `status: preparing | open | paused`, 플랜 표시값, 안내 문구 버전만 포함한다. MID·키·내부 오류와 계약 증거는 서버에만 둔다. 필수 증거가 없거나 읽기에 실패하면 `preparing`을 유지한다. 운영 장애 시 신규 신청은 `paused`로 바꾸되 기존 회원의 결제/이용 기록을 삭제하거나 임의로 초기화하지 않는다.

### 한 번에 바뀌는 사용자 화면

- 요금표·템플릿 상세·FAQ·메타 문구는 같은 준비 상태와 ko/en 사전을 읽는다. `preparing`에서는 지금의 출시 전 예시와 신청 불가 안내, `open`에서는 실제 제공 조건과 구독 신청 CTA를 보여준다. 소스별로 별도 boolean을 두지 않는다.
- 가입 버튼은 실제 빌링 등록 라우트가 있을 때만 나타난다. 서버 주문 생성에서도 같은 상태를 다시 확인한다. 화면의 상태나 이용량 계산만으로 영상 생성 권한을 부여하지 않는다.
- 가입 완료 이후 계정 화면의 갱신일·해지·사용 내역은 서버 구독 장부에서 읽는다. 공개 요금표 미리보기 수치를 계정 잔량으로 재사용하지 않는다.
- 공개 페이지가 1시간 캐시이므로 전환 시 기존 카탈로그/준비 상태 캐시 태그를 무효화하고 ko/en 요금표·FAQ·관련 템플릿 상세·SEO 안내를 함께 재검증한다. 버전이 다른 페이지가 남아 있으면 전환 완료로 기록하지 않는다.
- 다른 채팅의 템플릿 작업은 카탈로그를 통해 반영한다. 미확정 가격/엔진/길이/비율은 임의로 확정하지 않으며, 구독 대상 모델의 원가가 검증된 템플릿부터 포함한다.

### 답변 추적과 후속 반영

기존 매시간 회신 추적 작업은 새 토스 답변을 지정 Slack 채널에 알리고, 계약과 기능 구현의 진행 상태를 구분한다. 심사 승인만 온 경우 요구 자료·남은 구현 작업을 갱신한다. 실제 결제 통합이 완료되면 이 명세에 맞춰 공통 판정기와 연결 화면을 구현하고, 필수 검증 → PR/프리뷰 → Production → 실제 도메인 확인 순서로 반영한다. 현재 대표 지시는 이 조건을 충족한 사이트 안내 후속 반영을 승인한 것으로 기록한다. 계약 서명·가입비 결제·운영 비밀값 입력은 별도 운영 단계다.

중복 실행 방지는 `준비 상태 버전 + 플랜 버전 + 구현 커밋`으로 한다. 같은 버전은 새 PR/배포/Slack 메시지를 만들지 않는다. 원가 가정이 바뀌면 자동으로 가격이나 월 제공량을 바꾸지 않고 변경 근거를 대표에게 먼저 알린다. 새 회신이나 실행 가능한 상태 변화가 없으면 조용히 유지한다.
