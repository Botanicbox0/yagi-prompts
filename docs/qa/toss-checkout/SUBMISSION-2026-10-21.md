# 토스 심사 — 왜 막혔고, 무엇을 했고, 대표가 할 일 (2026-10-21)

## 1. 왜 승인이 안 났나

**코드 버그가 아니라 교착이었다.** 상점관리자의 신청 상태는 지금도 `심사중`(MID `twingssm8a`)이고,
반려 통지는 메일함에 없다. 다만 **현재 사이트 상태로는 심사를 통과할 수 없었다.**

토스 심사 체크리스트([notice/20057](https://www.tosspayments.com/notice/20057))가 홈페이지에 요구하는 것:

| # | 요건 | 10/21 작업 전 |
| --- | --- | --- |
| 1 | 하단에 상호·사업자등록번호·대표자명·주소·유선번호 | ✅ 충족 |
| 2 | **판매 가능한 상품 1개 이상** | ❌ 전부 "출시 준비 중" |
| 3 | **테스트 API 키로 신용카드 결제창 연동 완료** | ❌ 운영에서 결제 경로가 닫혀 있었음 |
| 4 | 상품 금액 = 결제 금액 | ✅ 서버 저장가 승인 |

2번과 3번이 막힌 원인은 `lib/flags.ts` 한 곳이었다. 운영에서는 Toss 키가 **둘 다 `live_`일 때만**
결제 경로가 열리도록 되어 있었는데, **라이브 키는 이 심사를 통과해야 발급된다.**
개발자센터 → API 키 → 라이브는 비어 있고, 결제위젯 키는 아직 문서 예제 키(`test_gck_docs_…`)이며
"내 키는 전자결제 신청하고 확인할 수 있어요"라고 표시된다.

승인을 받아야 키가 나오고, 키가 있어야 승인을 받는다. 그래서 심사자가 twings.app에 와도
상품을 살 수 없었고 결제창도 볼 수 없었다.

## 2. 무엇을 했나 — 운영 반영 완료

### 코드 (PR [#60](https://github.com/Botanicbox0/yagi-prompts/pull/60), [#61](https://github.com/Botanicbox0/yagi-prompts/pull/61), main 병합·배포 완료)

`RENDER_PIPELINE_PUBLIC`에 세 번째 상태 `review`를 만들었다.

| 값 | 상점 화면 | 결제·생성 | 운영 테스트 키 |
| --- | --- | --- | --- |
| `off` | 닫힘 | 관리자만 | — |
| **`review`** (현재) | **열림 — 가격 + 구매 CTA** | 관리자 + **심사 계정만** | **허용** |
| `on` | 열림 | 로그인한 모든 사람 | 금지(라이브 키 필수) |

- **공개 판매 개시가 아니다.** 일반 고객은 로그인해도 기존처럼 닫힌 스튜디오를 본다.
  공개 판매(`on`)와 그 시점은 그대로 대표 결정이다(AGENTS.md §6).
- 심사 계정 판별 근거는 Auth 서버의 `app_metadata.purpose = 'toss_review'` 하나뿐이다.
  등급도 관리자 권한도 주지 않는다. 운영 DB에서 `pg-review-20261014@twings.app`에 이 표시가
  정상으로 붙어 있고 `is_admin=false`, 프로필 존재, 계정 확인됨을 확인했다.
- 게이트를 `lib/auth/purchase-gate.ts` 한 곳으로 모아 렌더 큐·토스 주문/승인·동의 라우트·주문
  페이지가 같은 답을 읽는다.
- FAQ도 상점 상태를 따르게 했다. 그러지 않으면 구매 버튼 바로 아래에서 "결제는 준비 중"이라고
  답해 심사자가 한 화면에서 모순된 두 문장을 읽는다.
- JSON-LD `Offer`는 그대로 공개 판매만 따른다. 일반 고객이 실행할 수 없는 재고 상태를
  검색엔진에 알리지 않는다.
