# 토스 심사 계정

2026-10-14 대표가 심사용 계정 생성과 토스 신청서 제출을 요청했다. 운영 로그인은 Google/Kakao만 지원하므로 심사 계정의 실제 접속 경로가 필요하다.

## 범위

- `/auth/review?locale=ko` → 같은 origin의 `POST /auth/review/login`.
- `pg-review[-식별자]@twings.app`만 Supabase 비밀번호 인증에 전달한다. 일반 고객은 기존 Google/Kakao 로그인으로 안내한다.
- Auth 서버가 관리하는 `app_metadata.purpose=toss_review`와 일반 프로필(`is_admin=false`)을 함께 확인한 뒤에만 실제 Supabase 세션을 쿠키에 넣는다. 사용자 편집 가능 metadata는 권한 판정에 사용하지 않는다.
- staff 자동 관리자 부여 도메인(`@yagiworkshop.xyz`)은 사용하지 않는다. 관리자·유료 구독·다른 고객 데이터 접근을 부여하지 않는다.
- 기존 결제 공개 플래그, 빌링 준비 상태, 서버 금액 검사, 얼굴·제공사 검수는 변경하지 않는다. 계정 생성은 결제 개통이나 심사 승인이 아니다.
- 신규 비밀번호는 로컬의 Git 제외 `.env.local`에만 보관하고 토스 공식 신청서에만 전달한다. 로그·PR·화면 캡처에 비밀번호와 API 키를 넣지 않는다.
- **키 이름: `TOSS_REVIEW_ACCOUNT_PASSWORD`** (저장소 루트 `.env.local`). 10/14 최초 비밀번호는 어느 파일·세션 기록에도 남지 않아 2026-10-22 대표가 직접 재설정했다(무작위 20자, Supabase Admin API로 적용 → 비밀번호 로그인 확인 → `.env.local` 저장). 에이전트는 값을 보지 않았다. 토스 온보딩 "회원 전용 쇼핑몰 · 테스트 계정"과 카드사 심사 회신에는 이 값을 쓴다. 다시 바꾸면 두 곳 모두 고쳐야 한다.
- Supabase 자체 인증 제한에 더해 인스턴스별 1분 시도 예산(계정 5회·클라이언트 10회·전체 40회)을 둔다. 이 메모리 제한은 여러 인스턴스의 공용 장부가 아니며, Supabase의 인증 제한을 대체하지 않는다. 인증 후 프로필 검증이 실패하면 생성된 해당 세션을 폐기한다.

- **기준 사진(2026-10-22)**: 심사자가 셀카 없이 결제창까지 가도록 기준 사진을 미리 등록했다. 사진은 YAGI가 만든 **AI 생성 가상 인물**이다.
  "본인 얼굴만" 원칙(약관 §5.3, AGENTS.md §5)의 **심사 계정 한정 예외**로 대표가 2026-10-22 결정했다. DB 직접 삽입 없이 앱의
  정상 업로드 경로(`/identity/portrait`, 제공사 생성·검수)를 거쳤고, 시도 2건 성공·선택 1건이다. `/api/renders/access`는 이 계정에서
  `open:true`와 저장된 `portraitId`를 돌려준다. 실존 인물 사진으로 바꾸지 않는다. 심사 종료 후 계정과 함께 정리한다.

## 운영 확인

1. Auth 사용자를 정식 Supabase 사용자 생성 화면에서 만들고, 일반 프로필과 서버 전용 심사 목적 표시를 확인한다.
2. Supabase 비밀번호 인증과 일반 계정 여부를 검증한다.
3. 배포된 TWINGS 심사 로그인으로 실제 로그인, 계정 페이지와 로그아웃, 관리자 접근 거절을 확인한다. 실패한 비밀번호·일반 계정·cross-origin 요청이 세션을 만들지 않는지 확인한다.
4. 새 로그인 경로의 운영 배포가 검증된 뒤 토스 신청서에 입력한다. 가입비 납부·담보 수락·서명은 별도의 대표 단계다.
5. 심사 종료 후 운영자가 계정과 세션을 정리한다. 이 변경은 자동 만료나 계정 정리를 수행하지 않는다.
