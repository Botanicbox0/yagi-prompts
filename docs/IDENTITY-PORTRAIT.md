# 내 얼굴 기준 사진

2026-09-22 · 두 모델 비교 흐름으로 변경 · 운영 공개 전

## 확정 계약

- 대표의 최신 결정은 **최초 셀카 한 장 → Sunburst 1장 + Seedream 5.0 Pro 1장**이다. “어떤 사진이 더 나를 닮았나요?”에 사용자가 직접 고른다. “둘 다 닮지 않았어요”를 선택하면 **다른 원본 사진으로 Sunburst 1장**을 추가 무료 생성한다. 계정당 성공 결과 최대 3장, 월별 리셋·추가 판매 없음. 이전의 Sunburst 2회 규칙을 대체한다.
- 원본 셀피 한 장을 두 모델에 전달한다. Sunburst는 [기존 대표 프롬프트](product/prompts/identity-portrait-v1.md), Seedream은 [2026-09-22 대표 전용 프롬프트](product/prompts/identity-seedream-v1.md)를 원문 그대로 사용한다. 최신 지시가 기존 동일 프롬프트 규칙을 대체한다. 프롬프트 버전을 모델별로 기록하고 템플릿 프롬프트 치환을 통과시키지 않는다.
- Sunburst는 OpenAI Images edits, `gpt-image-2.5-sunburst`, `quality=max`, PNG, `moderation=auto`, **1344×2016**. Seedream은 ModelArk `dola-seedream-5-0-pro-260628`, 단일 PNG/base64 응답, 공식 2K·2:3 **1664×2496**. 두 결과는 같은 2:3 비율로 표시하며 얼굴을 변형하거나 강제로 리사이즈하지 않는다. 한 모델의 출력을 다른 모델의 입력으로 보내지 않는다.
- Seedream은 소유자 동의 후 정규화한 원본을 공식 `data:image/png;base64,...` 형식으로 전송한다. Seedance용 `asset://`, AK/SK, 자산 등록·라이브니스는 이 얼굴 사진 생성의 전제 조건이 아니다. Seedream 기본 제공사 검수는 그대로 적용하며 거절 시 `moderated`로 실패 처리한다. 검수 비활성화·모델 대체·자동 추가 생성은 없다. 기존 영상 생성의 자산 검수 경로는 변경하지 않는다.
- 사용자가 원본·결과를 비교하고 선택해야 활성 얼굴이 바뀐다. 얼굴 인증 성공이라고 표시하지 않는다. 화면에서는 모델 선호가 판단에 영향을 주지 않도록 “사진 1 / 사진 2”로 표시한다.
- 선택된 버전의 바이트를 결제 주문에 복사하고 원본→기준 사진→주문→렌더 계보 ID를 저장한다. 결제 후 얼굴 변경은 이미 시작한 작품에 영향을 주지 않는다.

## 실패와 저장

2026-09-22 API 연결 오류 수정: `sequential_image_generation`은 Pro 모델에서 `disabled`도 거절하며 `asset://`도 올바른 이미지 URL이 아니다. 두 HTTP 400은 요청 형식 오류이지 본인 셀카 이용 제한의 증거가 아니었다. [공식 이미지 API](https://docs.byteplus.com/en/docs/ModelArk/1541523)의 Base64 입력과 [Pro 출력 규격](https://docs.byteplus.com/en/docs/ModelArk/2582774)을 적용했다. 기존 1344×2016도 사용자 지정 범위에는 들어가므로 원래 오류의 원인은 비율이 아니었다.

계정 행 잠금과 DB 슬롯 고유 제약으로 최초 Sunburst(1), 최초 Seedream(2), 추가 Sunburst(3)를 각각 한 번 예약한다. 최초 두 모델은 병렬 처리하지만 같은 슬롯은 동시에 중복 제출할 수 없다. 요청 ID는 슬롯별로 멱등 처리한다. 추가 Sunburst는 첫 두 결과가 모두 성공하고 명시적으로 거절한 뒤, 최초 원본과 다른 정규화 이미지일 때만 예약한다. 실패한 슬롯은 저장된 같은 원본으로만 재시도하며 다른 모델의 성공 결과를 다시 만들지 않는다. 실패 복구는 추가 사진 변경 기회를 소비하지 않는다. 하루 생성 시도는 모델별 행 기준 6개로 제한한다.

OpenAI 동기 편집은 결과 재조회가 없으므로 네트워크 오류·시간초과·5xx는 `uncertain`이다. 자동 재호출하지 않는다. 저장은 성공했으나 DB 완료 기록이 실패한 경우, 다음 확인에서 저장 파일을 검증하고 완료 처리한다. 파일도 없는 불명확 요청은 운영자가 공급사 기록을 확인해 확정 실패로 처리해야 한다. 성공 결과를 실패로 바꿔 횟수를 복원해서는 안 된다.

원본은 방향을 보정하고 메타데이터를 제거해 비공개 renders 버킷에 보관한다. 결과는 정확한 해상도로 디코딩 검증 후 저장한다. 사진 읽기는 로그인한 소유자만 가능하며 응답은 `private, no-store`다. 브랜드나 공개 공유 경로에 노출하지 않는다. 기존 개인정보처리방침의 얼굴 사진·결과물 보관 및 계정 삭제 범위를 따르며 법무 본문은 수정하지 않는다. 계정 삭제 운영 시 해당 계정 시도의 input/result 객체도 함께 삭제해야 한다.

## 출시와 검증

`IDENTITY_PORTRAIT_ENABLED=true`가 필요하다. 기본은 닫힘이며, `RENDER_PIPELINE_PUBLIC=false`는 별도로 유지한다. 내 얼굴 준비를 열어도 유료 템플릿 생성은 열리지 않는다.

기존 `0028`/`0114`는 PR #8 배포 때 승인받아 적용했다. **새 클라우드 적용 필요:** `0029_core_portrait_comparison.sql`, `0115_glue_portrait_comparison.sql`. 이번 변경에서는 운영 DB·환경변수·공개 플래그를 변경하지 않는다. 코드 배포 전에 두 마이그레이션을 적용해야 한다. 기존 선택 ID와 결제·렌더 연결은 그대로 보존하며, 기존 두 번째 Sunburst는 추가 슬롯 3으로 이동해 무료 혜택을 리셋하지 않는다. 기존 계정의 누락된 Seedream은 저장된 최초 원본으로만 보완한다.

연결 검사: 개인정보 없는 단색 테스트 이미지로 실제 Sunburst edits 200, 1344×2016, 69초 확인. 이는 계정 접근·크기 검사이며 얼굴 보존 품질 검증이 아니다. 대표 결정에 따라 원본·결과를 나란히 보여주고 “내 얼굴처럼 나왔나요?”에 사용자가 직접 판단해 선택한다. 자동 얼굴 수·유사도 판별은 구현하지 않았으며 안내·본인 사진 동의·사용자 결과 선택과 기존 제공사 검수를 사용한다.

업로드 안내는 “얼굴이 많이 가려지지 않고, 되도록 정면을 바라보는 사진을 올려주세요.”다. 대표가 9월 22일 지정한 좋은 예시 2장, 머리카락 가림·얼굴 회전 예시 각 1장을 `public/images/portrait-guide/`에서 표시한다. 원본의 비율과 얼굴은 바꾸지 않고 작은 WebP로 변환해 메타데이터를 제거했다. 예시 사진은 생성 API 입력으로 보내지 않는다.

공식 근거: [Sunburst 모델](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), [Images API 가이드](https://developers.openai.com/api/docs/guides/image-generation).

최신 연결 검사: Seedream 전용 대표 프롬프트와 합성 도형 원본으로 실제 API HTTP 200, PNG 1664×2496, 69초 확인. 실제 셀카 얼굴 보존 품질은 미검증이다.

로컬 검증: `tsc --noEmit`, `vitest run` 120파일·1,377테스트, `build:local`, `start:local`, `sweep:anon` 606/606 통과. [UI 검증 기록](IDENTITY-PORTRAIT-QA.md).
