## 0. 한 장 요약

대표의 작업 루프 네 가지를 제품의 원칙으로 옮긴다.

| 대표의 방식 | 제품에서 |
| --- | --- |
| 레퍼런스마다 권한을 나눈다 (`@Image 1` 얼굴, `@Image 2` 의상 …) | **슬롯**: 주인공 얼굴 / 주인공 의상 / 함께 나오는 출연자 / 배경 / 움직임 / 소리 |
| 에셋을 먼저 확정하고, 480p 초안으로 검증한 뒤 올린다 | 슬롯마다 에셋을 만들고 **잠근다**. 영상은 **초안 → 완성본** 두 단계로 보인다 |
| 다시 만들지 않고 "고정 + 변경분"으로 v2, v3를 낸다 | **수정 지시서**: 유지 / 바꿀 것 / 빼야 할 것. 버전은 지시서와 슬롯의 변경분만 가진다 |
| 색·업스케일·싱크는 생성이 아니라 후처리로 한다 | 마감은 **편집 스튜디오**의 일이다. 생성으로 풀지 않는다 |

만드는 방법(지금 영상 고치기 / 움직임 그대로 대상 바꾸기 / 다시 찍기)은 고객이 고르지 않고 우리가 고른다(2026-11-17 대표 원칙).

## 1. 지금 상태 (코드 확인)

- **수정 패널**: 방식 카드 두 개(`edit` "이 영상에서 고치기" / `reshoot` "다시 촬영하기")와 실행 버튼("수정 영상 만들기"). 카드가 버튼처럼 보여 선택지가 셋으로 읽힌다. 방식 추천(`revise.plan`: 바꿀 것이 겉모습이면 고치기, 움직임·구도·길이면 다시 찍기)은 이미 있지만 화면은 고객에게 고르게 한다.
- **"1080p로 완성"**: 보이는 영상은 480p 초안이고, 이 버튼은 그 초안을 기준으로 1080p를 새로 만든다. 화면에 "초안"이라는 표시가 없다. 초안은 7일 뒤 완성본으로 올릴 수 없게 된다. 완성본은 업스케일이 아니라 새로 만든 영상이라 세부가 달라질 수 있다.
- **버전**: `params.revision`으로 v1 → v2가 이어진다. 고치기는 직전 영상을 참조 영상으로 보내고, 다시 찍기는 처음 실행의 참조와 설정을 이어받는다. 시드는 없다.
- **참조 역할**: `product / person / logo / style / place / other`. 주인공 얼굴과 의상, 함께 나오는 출연자를 나누는 역할은 없다.
- **참조 영상·오디오**: 업스트림 요청은 두 실행 경로 모두 참조 영상과 참조 오디오를 이미 받는다(`video_remix`). 다만 지금의 "영상 리버스"는 영상을 읽어 글로 옮길 뿐 영상 자체를 보내지 않는다.
- **움직임 가이드**: 클레이·노멀·포즈 같은 전처리 코드는 저장소에 없다.
- **로컬 GPU**: 스튜디오 작업을 가져가는 로컬 GPU 워커는 없다. 업스케일(SeedVR2)과 음악은 야기 프로덕션 서버로 작업을 보내고 결과를 받아 오는 다리(`YAGI_PRODUCTION_URL`)를 이미 쓴다. 워크스테이션에는 OpenJutsu 작업을 한 번에 하나씩 처리하는 프로덕션 워커가 서비스로 돌고 있다.
- **대표의 수동 작업과 워커의 차이**: 워커는 원본 오디오를 참조로 넣지 않고(끝에 덧입힌다), 인물만 클레이로 만들어 원본 배경을 남기며(대표는 화면 전체를 클레이로), 의상·캐릭터·배경 에셋을 만들지 않는다.

## 2. 공통 개념

### 2.1 슬롯

| 슬롯 | 무엇을 맡나 | 넣는 법 | 프롬프트의 자리 |
| --- | --- | --- | --- |
| 주인공 얼굴 | 얼굴 정체성만 | 사진 올리기(실제 사진, 머리 위와 어깨 여유, 과한 보정 없음) | `@Image 1` |
| 주인공 의상 | 옷만 | 올리기 / 사진에서 옷만 뽑기 | `@Image 2` |
| 함께 나오는 출연자 (선택) | 원본의 주변 인물을 대신할 캐릭터 | 올리기 / 캐릭터 시트 만들기 | `@Image 3` |
| 배경 | 공간 | 올리기 / 원본 구도에 맞춰 만들기·정리하기 | `@Image 4` |
| 움직임 | 카메라, 컷 리듬, 동작, 표정, 입 모양 | 원본 영상에서 자동으로 만든 가이드 | `@Video 1` |
| 소리 | 립싱크와 타이밍 | 원본 영상에서 자동으로 뽑음 | `@Audio 1` |

- 브랜드 영상에서는 **제품**, **로고** 슬롯이 더 붙는다(기존 `product`, `logo` 역할 그대로).
- 저장: 참조의 역할 값에 `outfit`, `cast`를 더한다(`person` = 주인공 얼굴, `place` = 배경). 슬롯 순서가 곧 `@Image n` 번호다. Seedance는 배열 순서로만 묶으므로 순서를 고정한다.
- 슬롯은 **잠글 수 있다**. 잠긴 슬롯은 다음 버전에 그대로 간다.

### 2.2 수정 지시서

```
유지      인물, 의상, 카메라 움직임, 컷 타이밍
바꿀 것    배경 → 흰 방 (슬롯 교체)
          5.9–7.8초, 9.0–10.0초: 얼굴에 정면 조명
빼야 할 것  역광으로 어두워진 얼굴 실루엣
```

- 세 칸은 버전을 거치며 **쌓인다**. v4의 지시서는 v1~v3의 "유지"와 "빼야 할 것"을 그대로 안고 있다.
- "바꿀 것"은 세 종류다: 슬롯 교체, 구간 지시(시작–끝 초), 전체 지시.
- 지시서가 프롬프트의 구획과 일대일로 맞는다: 유지·슬롯 → `Reference authority`, 구간 지시 → `Timeline`, 빼야 할 것 → `[Exclusions]`.

### 2.3 초안과 완성본

- 모든 생성은 **초안(480p)** 으로 시작한다. 버전 카드에 "초안" 표시와 남은 기간(7일)을 보인다.
- **완성본(1080p)** 은 마음에 든 버전에서 한 번 만든다. 초안을 기준으로 다시 만들기 때문에 세부가 조금 달라질 수 있다는 것을 그 자리에서 말한다.
- 길이가 바뀌면(10초 시험 구간 → 전체) 완성 전에 그 길이의 초안을 한 번 더 본다(대표의 순서 그대로).

## 3. 수정 대화 ("Edit this video")

### 3.1 흐름

1. 고객이 바꾸고 싶은 것을 말한다: 글, 영상 위 표시(위치 또는 **구간**), 참조(역할을 붙여서).
2. AI가 **이해한 내용을 지시서로 답한다**. 그 아래 한 줄로 방법과 크레딧을 말한다.
   - 예: "지금 영상에서 그 부분만 고칩니다. 구도와 길이는 그대로예요 · 96 크레딧"
   - 예: "움직임이 달라져야 해서 다시 찍습니다. 구도가 달라질 수 있어요 · 80 크레딧"
3. 고객은 "이대로 만들기"를 누르거나, 말로 고친다("캡은 그대로 두고 리본만 빼줘"). 고치면 지시서가 갱신된다.
4. 요청이 두 갈래로 읽힐 때만 AI가 한 번 묻는다(PR #243이 이 부분을 이미 만들었다).
5. 결과는 새 버전(초안)으로 쌓이고, 대화는 그 버전 아래에서 이어진다.

### 3.2 화면에서 바뀌는 것

- 방식 카드 두 개를 없앤다. 방법은 지시서 아래 한 줄로 알리고, 다른 방법을 원하면 작은 링크("다른 방법으로")로 바꾼다.
- 실행 버튼은 하나("이대로 만들기" + 크레딧).
- 패널은 위에서 아래로 대화가 쌓이는 모양이다: 고객의 말 → AI의 지시서 → 결과 버전 → 다음 말. 입력창은 맨 아래 고정.
- "1080p로 완성"은 타일이 아니라 대화의 마지막 단계다: 버전이 초안일 때만 "이 버전을 완성본으로" 버튼이 그 버전 카드에 붙는다.
- 참조를 붙일 때 역할을 고른다(슬롯 이름 그대로).
- "고칠 곳 표시"가 위치와 함께 구간도 받는다(재생 막대에서 끌어서).

### 3.3 서버에서 바뀌는 것

- `revise.plan`의 답을 넓힌다: 지금은 방식과 이유만 돌려준다. 여기에 `sheet {keep[], change[], exclude[]}`를 더한다. 같은 Gemini 호출에서 만든다(영상과 직전 지시서를 함께 읽는다).
- 지시서는 `params.revision.sheet`에 저장하고 다음 버전의 기본값이 된다.
- 표시(mark)에 `endTime`을 더한다.
- 방식은 서버가 정한 것을 기본으로 보내고, 고객이 바꾸면 그 값을 쓴다(기존 `mode` 그대로).
- 마이그레이션은 없다(모두 `params` 안이다). 역할 값 추가(§2.1)만 check 제약을 바꾼다.

## 4. 리믹스 영역

### 4.1 무엇인가

기존 영상의 **카메라·컷 리듬·동작·표정·입 모양**은 그대로 두고, **주인공·의상·함께 나오는 출연자·배경**을 바꾼 영상을 만든다.

핵심 원리(대표의 작업에서 확인된 것):

- 원본 영상을 생성 모델에 그대로 넣지 않는다. 원본 배우의 얼굴·피부색·세트 색이 새어 나온다.
- 깊이 지도도 쓰지 않는다. 눈·입의 작은 굴곡이 뭉개져 윙크와 립싱크가 죽는다.
- 원본에서 색·정체성·옷·배경을 지운 **회색 클레이 가이드**(DSINE 3D 노멀)를 만들어 움직임 참조로 넣고, **원본 오디오**를 함께 넣어 립싱크를 한 번 더 잠근다.

기존 "영상 리버스(설계도)"와의 관계: 리버스는 영상을 **읽어서 글로** 옮긴다(분위기·구성 참고). 리믹스는 움직임을 **가이드 영상으로** 직접 넘긴다(동작·립싱크까지 그대로). 입구는 하나("레퍼런스 영상으로 만들기")로 두고 첫 질문 하나로 가른다: "움직임까지 그대로 따라가기" / "구성만 참고하기". 사람이 나오고 동작이 뚜렷한 영상이면 앞쪽을 기본으로 둔다.

### 4.2 단계

```
① 원본 영상 올리기 ─ 시험 구간 고르기(기본 앞 10초, 최대 30초)
        │  자동: 구간 자르기 → 클레이 가이드 → 오디오 추출 (10초에 약 1분 30초)
② 슬롯 채우기 ─ 얼굴 · 의상 · 함께 나오는 출연자 · 배경 (각각 확인하고 잠금)
③ 10초 초안 (480p)
④ 보고 고치기 ─ 슬롯만 갈아 끼우기 / 구간 지시 / 빼야 할 것 → v2, v3 …
⑤ 전체 길이 초안 (480p) ─ 확정한 레시피 그대로
⑥ 완성본 (1080p)
```

- ②에서 슬롯 에셋을 **먼저 한 장씩 만들어 확인**한다. 영상부터 돌리지 않는다.
- ④는 §3의 수정 대화와 같은 화면이다. 리믹스에서 나온 영상은 슬롯과 가이드가 잠겨 있으므로 "배경만 바꿔줘"는 슬롯 교체가 되고, 방법은 "같은 가이드로 다시 만들기"다.
- 버전 카드에 무엇이 바뀌었는지 칩으로 보인다: "배경 바뀜", "구간 조명 추가".

### 4.3 슬롯 안에서 에셋 만들기

| 슬롯 | 동작 | 하는 일 | 쓰는 것 (우리가 고름) |
| --- | --- | --- | --- |
| 의상 | 사진에서 옷만 뽑기 | 모델·얼굴·가방·액세서리를 지우고 옷만 흰 바탕에 | Seedream 5.5 |
| 함께 나오는 출연자 | 캐릭터 시트 만들기 | 정면 + 3/4 두 장면, 흰 바탕 | 이미지 모델(작업별로 고정) |
| 배경 | 정리하기 / 만들기 | 사람·차·글자 지우기, 원본 첫 장면의 투시에 맞춰 다시 구성 | 이미지 모델(작업별로 고정) |
| 얼굴 | 올리기만 | 실제 사진을 권한다. 구도 안내만 한다 | — |

- 각 동작은 기존 이미지 작업으로 돈다(크레딧은 이미지 요금 그대로). 결과를 고르면 그 슬롯에 잠긴다.
- 의상 추출은 "사람이 한 명도 나오지 않는다"를 지킨다(대표 규칙).

### 4.4 전처리 (움직임 가이드)

- **어디서 도나**: 워크스테이션의 프로덕션 워커. 스튜디오 서버는 업스케일·음악과 같은 다리(`YAGI_PRODUCTION_URL`)로 작업을 보내고 상태를 받아 온다. 새 작업 종류 하나(움직임 가이드)를 더한다.
- **하는 일**: 구간 자르기(720p, 24fps) → 클레이 가이드(`openjutsu_mocap_pro.py`, `dsine_3d`, **화면 전체**를 클레이로, 자막 지우기 끔) → 오디오 추출(mp3). 스크립트가 자르기와 오디오 추출을 이미 지원한다.
- **결과**: 가이드 영상과 오디오를 스튜디오의 비공개 자산으로 저장한다. 같은 원본·같은 구간이면 다시 만들지 않는다.
- **기다림**: 워커는 한 번에 하나만 처리하고 GPU 우선순위는 ComfyUI가 먼저다. 화면은 "움직임 가이드를 만드는 중"과 대기 순서를 정직하게 보인다. 워커가 꺼져 있으면 리믹스를 시작할 수 없다고 말하고 "구성만 참고하기"를 권한다.
- **한도**: 업스트림은 참조 영상을 합쳐 30초까지 받는다. 스튜디오의 영상 길이 상한(지금 15초)을 리믹스에 한해 30초로 연다. 30초를 넘는 원본은 §5.3(구간 리믹스)로 간다.

### 4.5 프롬프트 조립

감독 컴파일러(`director/compiler`)에 리믹스 틀을 더한다. 대표의 프롬프트 구조 그대로다.

1. `Reference authority:` 슬롯마다 한 줄. "이 참조는 ○○만 준다. △△는 버린다." 가이드 줄에는 "회색 클레이 질감을 절대 그리지 않는다. 클레이 인물은 모두 대체한다"를 넣는다.
2. `Visual style:` 한 문단(렌즈, 빛, 색).
3. `Timeline:` 원본 영상의 컷 시각대로 구간을 나눈다(기존 영상 읽기 `film.analyze`의 결과를 쓴다). 구간 지시는 해당 구간 문장에 붙는다.
4. `[Exclusions]` 한 줄. 지시서의 "빼야 할 것"이 쌓인다.

제공사가 표현 때문에 거절하면(대표 작업의 "픽셀아트 / 아케이드" 사례) 기존 규칙대로 표현을 바꿔 한 번 다시 시도하고, 그래도 막히면 이유를 말하고 멈춘다. 크레딧은 돌려준다.

### 4.6 데이터

- 새 작업 종류를 만들지 않고 기존 `video_remix`에 방식 하나(`guide`)를 더한다. 가이드 준비는 그 작업의 준비 단계(`work`)가 아니라 **별도의 가이드 자산**으로 둔다. 여러 버전이 같은 가이드를 쓰기 때문이다.
- 레시피는 `params`에: `guide {assetId, sourceAssetId, start, length}`, `slots {face, outfit, cast, world, …}`(각각 자산 id와 잠금), `sheet`.
- 버전은 §3의 `params.revision` 그대로. 다음 버전은 레시피를 복사하고 바뀐 것만 다르다.
- 가이드 자산의 저장과 작업 종류 추가에 마이그레이션이 필요하다(자산 종류, 역할 값). 번호는 구현 시점의 main에서 정한다.

## 5. 비디오 스튜디오와 편집 스튜디오

### 5.1 역할

| | 비디오 스튜디오 | 편집 스튜디오 |
| --- | --- | --- |
| 다루는 것 | **컷 하나** | **컷들을 이은 한 편** |
| 하는 일 | 만들기, 리믹스, 수정 대화, 버전, 초안 → 완성본 | 순서, 길이, 전환, 음악, 자막, 컷 사이 색 맞추기, 소리 싱크, 내보내기 |
| 고치는 방식 | 생성(지시서) | 편집 명령과 후처리(다시 생성하지 않는다) |

### 5.2 잇는 곳

- **같은 컷, 같은 이력**: 타임라인의 컷은 스튜디오 결과물을 가리킨다(지금도 `outputId`와 테이크 목록이 있다). 컷을 누르면 그 컷의 버전과 지시서가 보인다.
- **타임라인에서 고치기**: "이 컷 고치기"는 §3의 수정 대화를 그 자리에서 연다. 새 버전은 그 컷의 테이크로 들어가고 길이가 같으면 타임라인이 흔들리지 않는다(편집 스튜디오 설계의 "생성으로 고치기"와 같은 것).
- **대화는 하나, 가는 길은 둘**: "병 색을 파랑으로"는 컷을 다시 만드는 일이고, "3번 컷을 줄여줘"나 "음악 드롭에 맞춰줘"는 편집 명령이다. AI가 가른다. 고객은 어느 스튜디오의 기능인지 알 필요가 없다.
- **마감은 편집에서**: 색 맞추기, 업스케일, 피부 디테일, 소리 싱크는 생성 재시도가 아니라 편집 스튜디오의 후처리다. 완성본(1080p)까지가 비디오 스튜디오, 그 뒤가 편집 스튜디오다.

### 5.3 긴 영상의 리믹스 (둘이 함께 하는 일)

30초를 넘는 원본(뮤직비디오 한 곡)은 한 번에 만들 수 없다.

1. 비디오 스튜디오가 원본을 컷 경계에 맞춰 30초 이하 구간으로 나눈다.
2. 같은 슬롯·같은 지시서로 구간마다 리믹스한다(구간마다 초안 → 확인).
3. 편집 스튜디오가 구간을 원본 순서대로 놓고 **원본 오디오 한 줄**을 깐다. 구간 사이 색은 편집에서 맞춘다.

이 흐름이 두 스튜디오가 이어져 있다는 것을 가장 분명하게 보여 준다. 1단계 범위는 아니다(§6의 R5).

- 모든 조각은 플래그 뒤에서 만들고, 조각마다 AGENTS.md §3 검증 루프와 실제 화면 확인을 거친다. R1·R2·R4는 유료 생성으로 확인해야 하므로 비용을 먼저 알리고 대표가 말할 때만 돌린다.

## 7. 대표 결정 필요

1. **권리 확인**: 리믹스는 남의 영상과 음원을 바탕으로 쓸 수 있다. "권리를 가진 영상만 올린다"는 확인을 어떻게 받을지(약관 문구는 대표 승인 경로). 주인공 얼굴 사진의 동의도 같은 자리다.
2. **로컬 워커 수정**: 프로덕션 워커에 작업 종류를 더하고 서비스를 다시 시작해야 한다. 수정과 재시작 승인.
3. **GPU 대기**: ComfyUI 작업 중에는 고객의 가이드 작업이 기다린다. 이 대기를 받아들일지, 워커가 꺼져 있을 때의 안내.
4. **이름과 문안**: 영역 이름("리믹스"?), 슬롯 이름, 초안·완성본 표기, 수정 대화의 문구.
5. **크레딧**: 가이드 만들기에 크레딧을 받을지(우리 GPU라 외부 원가는 없다). 초안과 완성본은 지금 요금식 그대로 갈지. 참고: 대표 작업에서 10초 480p 초안의 외부 원가는 124 크레딧(견적은 104)이었고, 10초 1080p 완성 견적은 575, 23초 1080p는 1,319였다.
6. **누구에게 여나**: 전체 조직 / 일부 조직. 모픽·샌드박스 조직은 닫힌 채로 둔다.

## 8. 확인하지 못한 것

- 1080p 완성(`draftFinalize`)은 대표의 작업에서도 아직 실행되지 않았다. 완성본의 품질과 초안과의 차이는 본 적이 없다.
- 클레이 가이드의 GPU 메모리 사용량과 긴 구간의 시간(22.5초에 3분 38초 한 번 측정).
- 프로덕션 워커가 "화면 전체 클레이 + 오디오 참조"를 받도록 바꾸는 데 드는 일의 크기(워커 코드는 저장소 밖에 있다).
- 초안 수정의 비대칭: 480p 초안을 고칠 때 한쪽 실행 경로는 초안으로, 다른 쪽은 초안이 아닌 것으로 보낸다(`scripts/brand-studio-lane-worker.mjs`). V1 전에 확인한다.
- 편집 스튜디오 설계 문서는 아직 커밋되지 않은 초안이다. §5는 그 초안의 "생성으로 고치기"와 맞춰 썼고, 두 문서의 경계는 구현 전에 한 번 더 맞춘다.
