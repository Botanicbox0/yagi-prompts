# AI 크리에이티브 허브 설계안 (프로필 · 블로그 · 입구)

작성 2026-11-28 · Claude · 상태: 대표 확인 전 설계안. 코드는 아직 바뀌지 않았다.

대표 요청: "개인이 maker가 되고 blog를 운영할 수 있는 느낌이 지금은 전혀 없다. SOTA급으로 설계해야 한다." 참고로 본 곳은 Higgsfield의 크리에이터 블로그(`higgsfield.ai/@…/blogs`)다.

## 1. 지금 왜 그 느낌이 없는가 (main 7165e399 기준 조사)

| 문제 | 실제 상태 |
| --- | --- |
| 들어가는 문이 없다 | 헤더, 계정 메뉴, 앱 하단 탭 어디에도 프로필·블로그 링크가 없다. 푸터와 계정 화면의 링크는 운영에서 꺼져 있다. |
| 있는 문은 블로그를 말하지 않는다 | 홈 아래쪽 섹션 하나와 `/direct`의 버튼 두 개뿐이고, 둘 다 "템플릿 올리고 수익"만 말한다. |
| 둘러볼 곳이 없다 | AI 크리에이티브 목록도, 전체 블로그 피드도 없다. 글은 그 사람 프로필이나 템플릿 페이지를 거쳐야만 보인다. |
| 프로필이 채널처럼 보이지 않는다 | 블로그 탭은 글이 1편 이상일 때만 나온다. 팔로우, 조회수, 대표 글이 없다. 템플릿 카드의 `by @핸들`은 링크가 아니다. |
| 글쓰기가 멀다 | 글쓰기는 긴 작업공간 화면 맨 아래에 있다. 사진·영상은 다른 패널에 먼저 올려야 하고 4MB까지만 된다. |
| 공개한 글이 안 보일 수 있다 | 공개 프로필이 꺼져 있으면 "공개"를 눌러도 아무에게도 안 보이는데 편집기가 알려 주지 않는다. |
| 반응이 없다 | 팔로우, 좋아요, 댓글, 조회수가 전부 없다. 쓰는 사람이 돌아올 이유가 없다. |

이미 있는 것: 블록형 글(제목·본문·목록·미디어·프롬프트·템플릿 카드·인스타그램), 글 SEO, 프롬프트는 회원에게만 공개, 관리자 숨김, MCP로 글 쓰기, 프로필(커버·소개·링크·작업물). 운영에서 블로그는 11-26부터 켜져 있다.

## 2. Higgsfield에서 본 것과 TWINGS가 다르게 할 것

가져올 것
- 프로필 왼쪽에 고정된 신원 영역: 아바타, 이름, 팔로워·조회수·좋아요, 팔로우 버튼.
- 항상 보이는 탭(전체 작업 / 게시물 / 블로그)과 16:9 표지 카드 3열.
- 글 화면: 큰 제목, 작성자 줄에 조회수·좋아요·댓글 수, 본문 속 영상, 실제 프롬프트 박스, 오른쪽 목차, 맨 아래 댓글.

다르게 할 것
- **글이 판매로 이어진다.** Higgsfield 글은 "이 모델로 만들어 보세요" 링크로 끝난다. TWINGS 글은 "이 장면, 내 얼굴로 만들기" 버튼으로 끝나고, 제작될 때마다 글쓴이에게 적립된다. 이것이 TWINGS만의 이유다.
- 프롬프트 전문은 회원에게만 보인다(지금 규칙 유지).
- 화이트 바탕의 TWINGS 아이덴티티를 그대로 쓴다. 핑크는 화면당 버튼 하나.
- 한 글에 한국어·영어를 함께 둔다(Higgsfield 크리에이터는 같은 글을 언어별로 따로 올린다).

## 3. 설계: 다섯 곳을 고친다

### 3-1. 입구 — 어디서든 한 번에 닿는다
- 헤더에 **"블로그"** 메뉴 하나를 더한다. 누르면 전체 블로그 피드(3-2)로 간다.
- 로그인한 사람의 계정 메뉴: AI 크리에이티브면 "내 프로필", "글 쓰기". 아니면 "AI 크리에이티브 시작하기"(→ `/direct`).
- 템플릿 카드의 `by @핸들`을 프로필 링크로 바꾼다(카드 모양은 그대로 조용하게).
- 내 영상이 완성된 화면에 한 줄: "이 영상으로 글 쓰기 · 템플릿으로 공개하기". 만들고 싶은 마음이 가장 큰 순간이다.
- 설치형 앱 하단 탭: AI 크리에이티브에게만 "스튜디오" 탭을 켠다(코드는 있는데 꺼져 있다).
- 푸터 링크는 항상 보이게 하고 `/direct`로 보낸다. 운영에서 404인 프로그램 안내 페이지는 `/direct` 하나로 합친다.

### 3-2. 둘러보기 — 전체 블로그 피드와 크리에이티브 목록
- `/{locale}/blog`: 맨 위에 대표 글 1편(큰 표지), 아래에 글 카드 3열. 카드에는 16:9 표지, 제목 2줄, 작성자 아바타와 @핸들, 읽는 시간, 좋아요·조회수.
- 주제 칩: 전체 / 만드는 법 / 프롬프트 공개 / 비하인드. 글에 주제 태그(최대 3개)를 새로 둔다.
- 오른쪽 또는 중간에 "AI 크리에이티브" 줄: 아바타, 템플릿 수, 팔로우 버튼.
- `/{locale}/makers`: AI 크리에이티브 목록(카드: 커버, 아바타, 한 줄 소개, 템플릿 수, 글 수).
- 둘 다 정적 페이지 + 캐시 태그로 만든다(지금 프로필과 같은 방식). 사이트맵과 구조화 데이터에 넣는다.

### 3-3. 프로필 — "내 채널"로 보이게
- 데스크톱: 왼쪽 고정 영역에 아바타, 이름, @핸들, 숫자 세 개(팔로워 · 템플릿 · 제작된 횟수), **팔로우** 버튼, 링크, "브랜드 제안 열림". 오른쪽에 탭과 내용.
- 탭은 글이 없어도 항상 보인다: 전체 · 템플릿 · 블로그 · 작업. 본인에게는 빈 탭에 "첫 글 쓰기" 버튼, 방문자에게는 "아직 글이 없습니다".
- 맨 위 고정: 대표 글 1편 + 대표 템플릿 3편(본인이 고른다).
- 휴대폰: 신원 영역이 위, 탭은 스크롤해도 위에 붙는다.
- 본인이 자기 프로필을 보면 "글 쓰기", "프로필 수정" 버튼이 보인다.

### 3-4. 글 화면 — 읽고, 반응하고, 만든다
- 제목 아래 작성자 줄: 아바타, @핸들, 팔로우 버튼, 조회수 · 좋아요 · 댓글 수, 공유.
- 본문 첫 영상 바로 아래와 글 끝에 **템플릿 버튼 카드**: 포스터, 제목, "이 장면, 내 얼굴로 만들기". 가격은 적지 않는다(가격은 템플릿 페이지와 요금표에서만 보인다는 기존 규칙).
- 프롬프트 박스: 회원에게 전문과 복사 버튼, 비회원에게는 제목과 "로그인하고 보기".
- 글 아래: 좋아요, 댓글(로그인 회원만 작성, 신고·숨김), 같은 사람의 다른 글, 같은 주제의 다른 사람 글.

### 3-5. 글쓰기 — 영상에서 바로 시작한다
- **"영상에서 글 시작하기"**: 내가 만든 영상이나 내 템플릿을 고르면 표지, 영상, 클립, 프롬프트가 채워진 초안이 열린다(지금 있는 "클립 가져오기"를 첫 화면으로 올린다).
- 본문에 사진·영상을 바로 끌어다 놓는다. "대표 작업" 패널을 거치지 않는다. 영상 한도는 4MB에서 올린다(3-7의 결정 7).
- 공개 전 점검표: 공개 프로필이 켜져 있는지, 핸들이 있는지, 표지가 있는지. 하나라도 빠지면 공개 버튼 옆에 이유와 바로가기를 보여 준다.
- 표지 만들기: 영상에서 한 장면을 고르고 제목을 얹는다(Higgsfield 인기 글의 표지가 전부 이 형태다).
- 작업공간 첫 화면을 세 칸으로 줄인다: 내 템플릿 · 내 글 · 적립. 지금의 긴 한 화면을 나눈다.

### 3-6. 반응과 알림
- 새 기록: 팔로우(사람), 좋아요(글), 조회(글, 하루 1회), 댓글(글).
- 알림(지금 있는 웹 푸시·이메일): 새 팔로워, 새 댓글, "내 글을 본 사람이 템플릿을 N번 만들었습니다".
- 작업공간 숫자: 글별 조회 → 템플릿 페이지 이동 → 제작 → 적립. 글이 수익으로 이어지는 것이 보여야 계속 쓴다.

## 4. 순서

| 단계 | 내용 | DB 변경 | 대표 결정 |
| --- | --- | --- | --- |
| 1 | 입구(3-1), 전체 피드와 목록(3-2, 태그 제외), 탭 항상 보이기와 빈 상태, 공개 전 점검표, 카드 링크, 작업공간 글쓰기 버튼 위로, 하드코딩 문구 정리 | 없음 | 1, 8 |
| 2 | 팔로우·좋아요·조회·댓글, 프로필 왼쪽 영역과 고정 글, 알림, 주제 태그 | 표 4개 + 열 추가(0208~) | 2, 3, 4, 5 |
| 3 | 영상에서 글 시작하기, 본문에 바로 올리기, 표지 만들기, 글→제작 숫자, 한·영 한 글 | 열 추가, 저장소 경로 | 7 |

1단계는 표를 새로 만들지 않고 지금 있는 것을 보이게만 한다. 그래서 가장 먼저, 가장 안전하게 나갈 수 있다. 2단계의 댓글은 신고·숨김·속도 제한을 함께 만들어야 열 수 있다. 권한과 상태가 걸린 2단계의 서버 쪽은 Gemini가 아니라 Claude Opus가 맡는 기존 원칙을 따른다.

## 5. 지켜야 할 것

- 고객 화면의 호칭은 "AI 크리에이티브"다. "메이커"는 코드와 DB 이름으로만 남긴다. 지금 화면 세 곳에 "메이커"가 그대로 적혀 있어 1단계에서 고친다.
- 모델·엔진 이름은 블로그 글 본문에서만 허용된다. 피드 카드, 프로필, 버튼에는 쓰지 않는다.
- 글은 올리는 즉시 공개되고 글쓴이가 고친다. 문제가 되면 관리자가 숨긴다(11-26 대표 결정 그대로).
- 실명·연락처 같은 개인정보는 공개 문안과 예시에 넣지 않는다.
- 색·서체·모서리·버튼은 `docs/design/IDENTITY.md`와 `TASTE.md`를 따른다.
