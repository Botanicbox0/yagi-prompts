# KAIPER 캠페인 결제·견적 수락 정책안

**2026-10-16 대표 승인 기록 · 소스 반영, 배포·개별 견적 확정은 별도.**

대표가 TWINGS 자체 서비스 대금만 수납, 견적별 총액·세금·범위·착수·환불 조건 확정, 전액 환불로 처리 가능한 계약 우선, 참여자 지급 분리를 승인했다. 아래 문구 중 이 승인 범위를 이용약관 제4조의2와 환불정책 제8항의 한국어·영어 원문에 반영하고 `LEGAL_EFFECTIVE`를 `2026-10-16`으로 변경했다. 협업·대리 초상·대화 분석 약관은 이번 승인 대상이 아니다. 실제 배포와 PG 계약 지원 확인은 완료로 간주하지 않는다.

**아래는 승인 전 검토안을 보존한 기록이다.** 작성 기준 소스 `8082a688854c2dfdb91558b6c7940c1733c8f55d`. 금액·세율·수수료·착수 시점·환불 사유를 이 문서가 대신 정하지 않는다. 대표가 아래 문구와 견적 필수 항목을 확정한 뒤, 약관·환불정책의 적용 범위와 시행일을 검토한다. 실제 PG 계약이 이 서비스 수납을 지원하는지는 별도 확인 사항이다.

## 현행 근거와 달라지는 범위

현행 약관 `LEGAL_EFFECTIVE=2026-10-14` 제4조는 「템플릿 한 편당 한 번 결제」와 결제 직후 생성 시작을 설명한다. 제8조 제5항은 브랜드 캠페인의 실제 진행 조건을 회사와 브랜드의 별도 합의로 정한다. 현행 환불정책은 맞춤 생성 결과물의 생성 개시·하자·생성 실패를 기준으로 한다. 이 문구만으로 새로운 브랜드 캠페인 운영 대금의 착수·취소·환불 조건까지 확정됐다고 보지 않는다.

신규 캠페인 결제는 별도 불변 견적을 수락하고 그 견적의 총액을 수납한다. 입금 기록은 캠페인 공개, 참여자 선정, 제작 개시 또는 참여자 지급을 자동 실행하지 않는다. 다음은 이 동작에 맞춰 추가할 **브랜드 계약 문구안**이며 소비자 템플릿 약관·환불정책 원문을 교체하지 않는다.

## 제안하는 브랜드 안내 문구

### 서비스와 견적

> TWINGS는 브랜드와 합의한 캠페인 운영 서비스를 제공합니다. 서비스명, 제공 범위, 최종 결제 총액, 세금 기준, 유효기간, 시작 조건과 환불 조건은 견적에 명시합니다. 브랜드 담당자는 이 내용을 확인하고 견적을 수락한 뒤 결제합니다.
>
> 결제 총액은 수락한 견적에 적힌 원화 금액입니다. 결제 화면에서 금액을 바꾸지 않습니다. 참여자 보상 제안과 TWINGS 서비스 견적은 별도 항목이며, 보상 제안을 보냈거나 스튜디오가 검토했다는 사실만으로 참여자 보상 조건이 확정되거나 지급되지 않습니다.

서비스명 후보는 **「TWINGS 브랜드 캠페인 운영 서비스」**다. 이 이름과 수납 대상은 대표 확정 사항이다. 본 초안은 TWINGS 자체 서비스 대금을 수납하는 안을 기준으로 한다. 참여자에게 전달할 자금을 함께 수납하거나 지급을 대행하는 범위를 포함하려면 그 구조·회계·PG 계약을 별도로 확인하고 문구를 다시 정한다.

### 수납과 착수

> 결제 완료는 입금 확인을 뜻합니다. 캠페인 공개, 참여자 선정, 제작 시작과 원고료 지급은 각각 별도의 절차입니다. 서비스는 견적에 적힌 시작 조건을 충족하고 회사와 브랜드가 확인한 뒤 진행합니다.
>
> 수락한 견적을 변경해야 하는 경우 변경 내용을 별도 견적으로 제시하고 다시 수락받습니다. 기존 지원자가 동의한 캠페인 참여 조건은 브랜드 견적이나 보상 제안만으로 바뀌지 않습니다.

현재 코드가 지원하는 재견적은 **만료된 수락 견적에 입금되거나 결과가 불명확한 주문이 없는 경우**의 관리자 무효 처리와 새 버전 발행이다. 입금 후 계약 변경, 부분 제공이나 추가 발주까지 이 경로로 처리할 수 있다고 안내하지 않는다.

### 취소·환불

> 환불의 대상과 금액은 해당 견적에 명시한 조건과 적용되는 법령에 따라 확인합니다. 환불이 확정되면 원래 결제 수단으로 처리합니다. 제공사 처리 결과가 확인되지 않은 경우 완료로 안내하지 않고 확인 중임을 알립니다.
>
> 이 안내는 이용자에게 법령상 보장된 청약철회·환불 권리를 제한하지 않습니다. 템플릿 결과물 결제에 적용되는 기존 환불정책과 브랜드 캠페인 서비스의 합의 조건은 적용 대상을 구분해 안내합니다.

이 문구는 「착수 전 전액 환불」, 「선정 이후 환불 불가」, 특정 비율 공제 또는 특정 처리 기한을 새로 정하지 않는다. 해당 기준이 필요한 견적은 대표가 실제 제공 내용과 진행 단계에 맞춰 구체적인 조건을 입력해야 한다. 현재 관리자 기능은 **전액 환불만** 지원한다. 부분 환불이나 공제 조건을 약속한 견적은 지원 절차가 준비되기 전 이 경로로 수납하지 않는 안을 제안한다.

### 동의 범위

> 견적 수락은 해당 견적에 표시된 서비스·총액·세금 기준·유효기간·시작 조건·환불 조건에 대한 브랜드의 동의입니다. 브랜드가 현재 지정한 소유자 계정으로 수락·결제하며, TWINGS 관리자는 구매자를 대신해 수락하거나 결제하지 않습니다.
>
> 브랜드의 견적 수락과 입금은 참여자의 사진·초상 사용 동의를 대신하지 않습니다. 참여자는 자신의 계정에서 캠페인 조건을 확인하고 참여합니다. 대리 등록·제작을 위한 별도 동의와 제공사 검토가 필요한 경우 그 절차를 따로 진행합니다.

대리 등록·제작 및 대화 분석 고지의 검토안은 [별도 초안](KAIPER-DELEGATED-LIKENESS-AND-MESSAGING.md)으로 유지한다. 본 초안 승인만으로 본인 확인·제공사 검수·인물 자산 소유권을 변경하지 않는다.

## 견적 발행 전 채워야 하는 내용

아래는 관리자가 현재 `termsSummary`, `termsRef`, `taxBasis`에 넣을 수 있는 **작성 양식**이다. 빈칸은 아직 합의되지 않았다는 뜻이며 빈 상태로 발행하거나 구매자의 추정에 맡기지 않는다.

| 항목 | 확정할 내용 |
| --- | --- |
| 서비스명 | 제공하는 TWINGS 서비스의 명칭 |
| 제공 범위 | 포맷 설계·운영·검수·리포트 등 실제 포함 항목과 납품 범위, 제외 항목 |
| 최종 총액 | 관리자가 승인한 원화 정수 금액. 실제 가격은 이 초안에서 정하지 않음 |
| 세금 기준 | 해당 견적 총액의 세금 포함 여부·처리 기준. 회계 확인 내용 그대로 입력 |
| 시작 조건 | 결제 이외에 확인할 조건, 충족 여부를 확인하는 담당자와 기록 방식 |
| 환불 조건 | 취소 시점·사유별 환불 대상/금액, 미제공·지연 시 처리. 현재 전액 환불 기능과 양립하는지 확인 |
| 유효기간 | 구매자가 수락·주문할 수 있는 기한. 한국 시각 날짜·시각으로 표시 |
| 문서 참조·버전 | 위 내용이 담긴 합의 문서와 버전 식별값 |
| 참여자 보상과의 관계 | 총액에 참여자 보상금이 포함되는지 여부와 지급 담당. 미확정인 범위는 수납 대상으로 넣지 않음 |

현재 견적은 자유 문안을 저장하며, 서버가 「시작 조건」「환불 조건」의 의미상 완전성을 자동 판정하지 않는다. 운영자는 위 항목을 체크한 뒤 발행해야 한다. 수락한 견적의 금액·문안·버전과 수락자·수락시각은 보존한다.

## 대표가 확정할 결정

1. 공급 서비스명을 「TWINGS 브랜드 캠페인 운영 서비스」로 하고 **TWINGS 자체 서비스 대금만 수납**하는 위 문구를 채택할지. 참여자 자금 수납·지급 대행을 포함하면 별도 범위 확인이 필요하다.
2. 서비스별 고정 가격을 새로 만들지 않고 **견적마다 총액·세금·제공 범위·시작 조건·환불 조건을 확정**하는 방식을 채택할지.
3. 현재 전액 환불 기능으로 처리할 수 있는 견적에 한해 우선 수납할지. 실제 착수·미제공·취소 사유별 환불 조건은 각 견적 발행 전에 별도 확정해야 한다.
4. 위 브랜드 안내 문구와 브랜드 소유자 수락 방식, 현행 소비자 정책과 적용 대상을 구분하는 방식, 개정 문서의 시행일·고지 절차를 승인할지.

위 결정으로 실제 개별 견적 금액이나 개별 환불 조건까지 정해진 것으로 처리하지 않는다. KAIPER의 실제 계약/견적 조건은 해당 문서로 확인한다.

## 기술 준비와 외부 확인은 분리

- 신규 수락·결제는 `CAMPAIGN_FUNDING_PUBLIC`과 `CAMPAIGN_FUNDING_POLICY_READY`가 모두 켜져야 한다. 운영은 live 게이트웨이, 비운영은 test/fake 게이트웨이로 제한한다. 플래그를 켰다는 사실은 정책·PG 계약 승인의 증거가 아니다.
- 같은 상점의 client/secret 키 한 세트를 사용해야 한다. 공식 [Toss API 키 안내](https://docs.tosspayments.com/reference/using-api/api-keys)는 테스트 승인이 가상이며 결제수단에서 금액을 차감하지 않는다고 설명한다. 키의 존재·접두사 일치는 실제 승인·취소 검증이나 가맹 계약 범위를 증명하지 않는다.
- 기존 템플릿 상품의 PG 심사·테스트 기록을 브랜드 캠페인 서비스 판매 승인으로 간주하지 않는다. 해당 상품·업종·거래 구조·결제수단이 현재 MID 계약 범위에 드는지 제공사에 확인해야 한다.
- 세금계산서·현금영수증·카드전표 처리, 원고료 세무 및 지급대행을 포함할 경우 그 계약은 별도 확인한다. 이 초안은 세율이나 세무 처리를 정하지 않는다.
- 실검증은 격리된 test 환경에서 실제 소유자 로그인 → 견적 확인/수락 → [결제 위젯](https://docs.tosspayments.com/guides/v2/payment-widget/integration) 인증 → 명시적 서버 확인 → 제공사 조회 일치 → 관리자 전액 취소 → 제공사 `CANCELED`·잔액 0 대사를 확인해야 한다. API·상태의 기준은 [Toss 코어 API](https://docs.tosspayments.com/reference)다.
- 실제 검증에도 캠페인 공개, 제작, 참여자 지급이 자동 발생하지 않는지 별도로 확인한다. 환불·미확정 결과는 [복구 절차](../../qa/campaign-funding-recovery.md)를 따른다.
