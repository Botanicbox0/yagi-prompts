### 실제로 노출하는 결제수단 (2026-10-21 대표 결정)

계약에는 계좌이체가 들어 있지만 **결제창에는 신용·체크카드 · 토스페이 · 페이코 · 카카오페이만 노출한다**
(카카오페이는 같은 날 대표 요청으로 추가). 토스 결제 어드민
→ 결제 UI 설정 → 기본 UI(`variantKey` `DEFAULT`) → 기능 → 결제수단 목록에서 라이브·테스트 둘 다 바꿨다
(코드가 아니라 어드민 설정이다. 결제위젯 v2는 SDK로 결제수단을 뺄 수 없다).

- **퀵계좌이체 제외**: 매번 은행 인증을 거치는 번거로운 경험이고, 최소 수수료 220원 때문에 저가 상품(특히
  이미지)에서 손해가 난다. 이전에는 목록 맨 위에 "30% 소득공제" 배지와 함께 강조돼 오히려 계좌이체로 유도되고 있었다.
- **가상계좌 제외**: 우리 승인 로직(`lib/billing/toss-service.ts`)은 상태가 `DONE`이고 잔액이 주문 금액과 같을 때만
  결제를 받는다. 가상계좌는 승인 직후 `WAITING_FOR_DEPOSIT`이라 주문이 "확인 중"에 머물다 30분 만료 때 실패로 끝나고,
  취소 요청에 환불 계좌를 싣지 않아 입금 뒤 환불도 막힌다. **어드민에서 가상계좌를 다시 켜면 안 된다.** 켜려면
  입금 대기 주문의 수명과 환불 계좌 입력부터 구현해야 한다.
- **카카오페이 켬**(2026-10-21, 대표 요청). 수수료 3.74%로 카드와 같다.
- **네이버페이는 아직 못 켰다.** 계약 조건표에는 네이버페이(3.85%)가 있지만 결제 UI 설정의 결제수단 목록에
  나타나지 않는다. "+ 추가하기"의 네이버페이는 **간편결제 직연동(Pro)** — 네이버와 따로 계약하고 우리 코드에서
  네이버페이를 직접 연동하는 경로라 쓰지 않는다. 토스에 상점 MID의 네이버페이 활성화를 요청해야 하고, 활성화되면
  목록에 체크박스로 나타난다(라이브·테스트 둘 다 켤 것). 수수료가 카드보다 0.11%p 높다.
- 삼성페이·애플페이·SSG페이·엘페이는 꺼져 있다(처음부터 그 상태). 삼성페이는 4.07%로 가장 비싸다.

자동결제(빌링)는 이 화면에 없다. 월 구독을 열려면 별도 신청·계약이 필요한지 확인해야 한다
(체크리스트상 정기 추심 구조는 계좌이체 결제수단을 쓸 수 없다).

### 2. 계좌이체 최소 수수료 220원과 저가 상품

계좌이체는 결제금액 1만원 미만이면 2.2%가 아니라 220원이 붙는다. 영상(3,900원 이상)은 마진 4.8% 이상으로
버티지만, **이미지 하한가에서는 계좌이체 한 건마다 손해**다.

| 이미지 엔진 | 5% 하한가 | 카드 결제 시 이익 | 계좌이체 결제 시 이익 |
| --- | --- | --- | --- |
| Seedream 5.0 Lite | 200원 (최소가) | +126원 | −67원 |
| Seedream 5.0 Pro | 200원 | +49원 | −144원 |
| GPT Image 2 | 500원 | +102원 | −81원 |
| GPT Image 2.5 Flare | 700원 | +81원 | −96원 |
| GPT Image 2.5 Sunburst | 1,100원 | +81원 | −82원 |

2026-10-21 이미지 최소가를 200원으로 정했고, 같은 날 결제 UI에서 계좌이체를 아예 뺐다(위 "실제로 노출하는
결제수단"). 그래서 이 표의 계좌이체 열은 지금은 발생하지 않는 경우다. 어드민에서 계좌이체를 다시 켜면 되살아난다. 지금 결제위젯은 상점 기본 설정의 결제수단을 그대로 보여준다.

### 3. 정산과 한도

- 정산은 거래일+4영업일, 수수료는 정산금에서 먼저 뺀다(선취).
- 월 정산한도 1천만원은 보증보험 담보 1천만원에 묶여 있다. 월 결제가 1천만원에 가까워지면 한도 증액(담보 증액)을
  먼저 협의해야 정산이 막히지 않는다.

### 4. 환불

카드 365일, 계좌이체 180일 안에 취소할 수 있다. 우리 자동 환불(생성 최종 실패 시 전액 취소)과
환불정책(`lib/legal/documents.ts`) 기간은 이 안에 들어간다.

## 라이브 전환 체크리스트 (2026-11-11 정리)

**운영은 이미 라이브 키로 열려 있다.** 2026-11-11 확인한 근거(값은 읽지 않았다):

- Vercel Production의 `TOSS_SECRET_KEY`(2026-11-05 15:00 UTC), `RENDER_PIPELINE_PUBLIC`(15:08), `TOSS_CLIENT_KEY`(15:09)가 그날 다시 입력됐다.
- 같은 날 15:04~15:56 UTC 운영 로그에 `render_pipeline_closed` `{"setting":"review","required":"test","keys":"live"}`가 5번 찍혔다.
  라이브 키가 들어갔는데 값이 `review`라 닫혀 있던 구간이다. 그 뒤 배포부터는 이 로그가 없다.
- 지금 `https://twings.app/api/renders/access`는 `open: true`다. 운영에서 라이브 키로 `open`이 되는 값은 `on`뿐이다.

그러니 **2026-11-06 01시(KST) 무렵부터 일반 계정도 실제 결제가 된다.** 2026-11-11까지 라이브 주문은 0건이다(운영 DB의
`billing_payments`는 테스트 주문 3건, 전부 `failed`). 아래 토스 쪽 항목과 실결제 1건 확인은 아직 기록이 없으므로 먼저 끝낸다.
값이 정말 `on`인지는 대표가 Vercel 화면에서 본다.

### 토스 쪽 (대표, 상점관리자·개발자센터)

2026-11-05 확인 때 아래 세 가지가 남아 있었다. 끝냈는지는 어드민에서 다시 본다.

1. **결제 UI의 MID 연결**: 결제위젯 → 결제 UI 설정 → 기본 UI(`variantKey` `DEFAULT`)의 국내 일반결제 MID가 계약하지 않은
   옛 MID(`pitchv1br8`)였다. `twinkodj7p`로 바꾼다. 안 바꾸면 라이브 키로 결제창이 열려도 승인이 나지 않거나 다른 MID로 잡힌다.
   바꾼 뒤 결제수단 목록이 위 "실제로 노출하는 결제수단"과 같은지(카드·토스페이·페이코·카카오페이, 가상계좌·퀵계좌이체 꺼짐)
   라이브 탭에서 다시 확인한다.
2. **라이브 웹훅 등록**: 개발자센터 → 웹훅 → 라이브 탭에 `https://twings.app/api/billing/toss/webhook`,
   이벤트 `PAYMENT_STATUS_CHANGED`. 가상계좌를 쓰지 않으므로 `DEPOSIT_CALLBACK`은 필요 없다. 우리 웹훅은 본문을 믿지 않고
   토스에서 결제를 다시 읽기 때문에 **웹훅 시크릿 환경변수가 없다**(`TOSS_WEBHOOK_SECRET` 같은 값은 넣지 않는다).
3. **안심정산플랜** 연이용권 결제(정산 수령 조건).
4. 상점관리자의 사업자 정보를 새 사업자등록증(영등포구)으로 바꾼다.

### Vercel 쪽

- `TOSS_CLIENT_KEY`·`TOSS_SECRET_KEY`는 `twinkodj7p`의 **결제위젯 연동 키** 쌍(`live_gck_…`/`live_gsk_…`)이어야 한다.
  API 개별 연동 키(`live_ck_`/`live_sk_`)를 넣으면 열리지 않는다. 지금 들어 있는 키가 `twinkodj7p` 것인지, 옛 MID 것인지는
  개발자센터의 키 목록과 대조해 대표가 확인한다.
- 닫아야 하면 `RENDER_PIPELINE_PUBLIC`을 지우고 Redeploy 한다. 이미 결제된 주문의 생성·환불은 계속 처리된다.
- 값은 빌드 시점에 읽는다. 바꾼 뒤에는 반드시 재배포한다.

코드가 지키는 규칙(`lib/flags.ts`, `lib/auth/purchase-gate.ts`):

- 운영에서 `on`은 라이브 위젯 키 쌍일 때만, `review`는 테스트 위젯 키 쌍일 때만 열린다. 어긋나면 닫힌 채
  `render_pipeline_closed` 오류 로그를 남긴다. 그래서 **라이브 키 + `review`는 판매가 닫히고**, 심사 계정에 실제 청구가
  나가는 일은 없다. 이 문서의 이전 판은 반대로 적혀 있었다.
- **관리자 계정은 어떤 값에서도 결제할 수 있다.** 라이브 키가 들어간 뒤 관리자 결제는 실제 청구다. 판매를 닫아 둔 채
  실결제를 확인해야 할 때 이 경로를 쓴다.
- 주문은 만들어질 때의 키 종류(`environment` `test`/`live`)에 묶인다. 키를 바꾸면 테스트 키로 만든 미종결 주문은 다시
  처리되지 않는다. 2026-11-11 운영 DB에는 테스트 주문 3건이 전부 `failed`로 끝나 있어 남는 것이 없다.
- 일반 결제(`billing_payments`)에는 관리자 환불 오퍼레이션이 없다. 수동 환불은 **토스 상점관리자에서 취소**하고, 라이브
  웹훅이 그 취소를 우리 DB에 반영한다. 웹훅을 등록하기 전에 수동 취소를 하면 DB는 계속 `paid`로 센다.

### 개시 직후 확인 (Director + 대표)

`docs/PLATFORM-2.0.md` §2.3: 실결제 1건과 취소 반영, 일반 계정으로 CTA·결제창 확인, 심사 계정 정리, 정산 조건 확인.
로그에 `toss_docs_key`·`render_pipeline_closed`가 더 찍히지 않는지, 웹훅이 200으로 들어오는지 본다.
관리자 "결제 확인 필요" 목록은 `environment`로 거르지 않아 옛 테스트 주문이 걸려 있으면 계속 보인다.

### 계약에 없는 것

- **자동결제(빌링)**: 월 구독을 웹에서 카드로 받으려면 별도 계약이 필요하다. 지금 계약은 단건 일반결제뿐이다.
- **네이버페이**: 정식 MID에 활성화를 요청해야 결제 UI 목록에 나타난다.
- **해외 카드**: 국내 일반결제 계약이다. 영어 페이지의 달러 구독가(`lib/twings/template-price.ts`)을 웹에서 받으려면 해외결제 계약 또는 앱 스토어 결제가 필요하다.
