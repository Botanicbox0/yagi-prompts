# 브랜드와 크리에이터의 공개 진입 분리

2026-10-07. 조사 근거: [공식 서비스 비교와 관찰 기록](research/audience-conversion-research-2026-10-07.md). 문의 운영: [Slack 발송과 복구](BRAND-INQUIRY-DELIVERY.md). 판매 상태: [크리에이터 구독 설계](CREATOR-SUBSCRIPTION.md).

## 바꾼 이유

기존 `/campaigns`는 브랜드 영업 설명·쇼릴·문의와 크리에이터 모집을 한 화면에 담았다. 새 브랜드의 우선 버튼은 로그인 공간으로 향했고, 실제 상담 폼은 접힌 영역 안에 있었다. 크리에이터 홈과 footer에도 제작사 영업 CTA가 반복됐다. 서로 다른 첫 행동을 요구하는 두 이용자를 명확한 URL과 문맥으로 나눈다.

Brandazine의 실제 공개 화면에서 브랜드 문의는 로그인 전에, 크리에이터 지원은 캠페인 상세 이후에 배치돼 있었다. 이 원칙을 TWINGS의 기존 도메인·권한 구조에 적용한다. 전환율이나 비용 절감 수치를 경쟁사 관찰만으로 주장하지 않는다.

## 최종 정보구조

| 목적 | 공개 경로 | 첫 행동 | 이후 경로 |
| --- | --- | --- | --- |
| 크리에이터 탐색 | `/ko`, `/en`, `/[locale]/video`, `/[locale]/image` | 예시를 보고 템플릿 선택 | 선택한 템플릿으로 로그인 복귀 → 기존 얼굴 검수/생성 게이트 → `/renders` |
| 캠페인 참여 | `/[locale]/campaigns` | 브리프·조건·일정 확인 | 상세 → 로그인 → 지원 → `/campaigns/mine` |
| 브랜드 의뢰 | `/[locale]/brands` | 포맷·활용 유형·실적·과정 확인 → 상담 | 계정 없는 문의 접수 → 운영자 검토 → 기존 브랜드 공간 |
| 진행 중인 브랜드 | `brand.twings.app` | 브랜드 로그인 | 기존 프로젝트·승인·리포트 권한 유지 |
| 개별 영상/필터 | 브랜드 페이지의 YAGI 보조 영역 | 제작 문의 | 같은 언어의 폼, 또는 한국어임을 명시한 별도 예상견적 사이트 |

헤더의 브랜드/크리에이터 링크는 목적지 이동이다. 쿠키에 역할을 저장하거나 권한을 바꾸지 않는다. DNS·인증 제공자·세션 경계를 변경하지 않는다. 기존 `/campaigns#brands`는 새 브랜드 안내 링크로 연결한다. `brandEnquiryHref`를 쓰는 기존 광고·footer도 새 문의 폼으로 이동한다.

## 브랜드 페이지

순서는 참여하고 싶은 포맷을 설명하는 hero → 실제 제작 예시 4편 → 크리에이터의 참여 동기 → 활용 유형 5개 → 승인된 익명 사례 → 진행 과정 → 열린 문의 폼 → YAGI 보조 제작 → 브랜드 FAQ다. Header와 footer의 가장 큰 행동은 상담으로 통일한다. 진행 중인 고객 로그인은 별도 링크다.

차별점은 크리에이터가 자신의 채널에 게시하고 싶은 포맷이다. 참여 동기를 고려해 모집과 운영을 설계한다는 정성적 설명을 사용한다. 성과·단가 절감을 보장하지 않는다. 일정 일수, 패키지 금액, 신규 사례 인용문을 만들지 않는다.

사례 매니페스트 `lib/campaigns/case-studies.ts`에는 승인된 익명 글로벌 AI 플랫폼과 영상 9편·200만 뷰+·파생 오가닉 300건+만 기록한다. 기존 쇼릴은 제작 예시로 표시하며 이 캠페인의 결과 영상이라고 연결하지 않는다. Pitch 소개서의 개별 미디어와 사례를 잇는 근거는 확보하지 못해 새 영상 매핑을 추가하지 않았다.

`pricing.yagiworkshop.xyz`는 실제 공개 화면과 `lang=ko`, 내비게이션을 확인했으며 영어 선택을 찾지 못했다. 영문 페이지는 영어 제작 문의를 먼저 제공하고, 계산기는 `Production estimate · Korean`으로 표시한다. 별도 저장소의 코드에는 손대지 않는다.

## 웹 제품과 모바일 앱 확장

공개 템플릿 탐색과 캠페인 상세를 로그인 전에 유지한다. 로그인 링크는 선택한 템플릿을 `next`로 보존한다. 공개 생성 준비 중인 상태와 월 구독 미출시 안내는 계속 노출한다. 앱 설치 요구로 웹 기능을 막지 않는다.

로그인 이후 공통 헤더는 모바일에도 템플릿·캠페인·내 작품·계정 네 경로를 제공한다. 화면 하단 고정 UI를 추가하지 않아 기존 결제·생성 버튼을 가리지 않는다. 미래 앱에서도 같은 작업 식별자와 복귀 URL을 재사용할 수 있다. 네이티브 앱이나 푸시를 현재 기능으로 설명하지 않는다.

모바일 메뉴에는 현재 목적, 로그인, 기본 CTA, 언어 전환을 둔다. Escape·Tab 순환·메뉴 버튼으로 초점 복귀를 제공한다. 쇼릴은 화면의 절반 이상 보일 때만 자동재생하고, 수동 정지·탭 비활성·동작 줄이기 설정을 존중한다. 재생/소리 버튼은 44px다. 320px에서는 토끼 마크를 숨기고 TWINGS 워드마크를 유지해 두 모드와 메뉴가 겹치지 않게 한다.

## 구현 경계와 정리

- 공개 페이지는 사전 기반 서버 렌더, 1시간 TTL, 카탈로그 캐시를 유지한다. Service JSON-LD는 브랜드 페이지로, 캠페인 목록은 참여 안내로 이동한다. 두 언어 sitemap·FAQ·llms 안내도 일치시킨다.
- 새 외부 라이브러리를 추가하지 않았다. 기존 Next/React/Tailwind와 재생 컴포넌트를 사용한다.
- 기존 `brand-landing.tsx`, `brand-section.tsx`는 모든 TS/TSX 참조를 검색해 소비자가 없음을 확인하고 제거했다. 이들이 가졌던 로그인 우선·접힌 폼 구조를 새 페이지가 대체한다. 승인 영상, render/identity 안전장치, 다른 작업공간의 YAGI 랜딩은 보존한다.
- 얼굴·결제·약관 코드는 변경하지 않는다. 구독 신청/정기결제/월 장부/해지는 이 범위에서 구현하거나 개방하지 않는다.
- 문의 선택 필드와 UUID를 기존 API에 추가했다. 개인정보는 기존 문의 테이블에서 관리자 인증 후 조회한다. Slack은 UUID·고정 문의 종류·관리자 링크만 받는다. 접수 실패와 Slack 실패를 분리하며 불명 발송은 자동 재시도하지 않는다.

## 검증 기록

2026-10-07 로컬 필수 순서 검증:

| 검사 | 결과 |
| --- | --- |
| `npx tsc --noEmit` | 종료 코드 0 |
| `npx vitest run` | 189개 파일 / 2,033개 테스트 통과, 586.99초 |
| `npm run build:local` | 성공. 브랜드·크리에이터 목록 양 언어 SSG, TTL 1시간 |
| `npm run start:local` | 3000 포트 local/PGlite/storage 모드 Ready |
| `npm run sweep:anon` | `SWEEP PASSED — 711/711 checks passed` |

첫 스윕은 삭제된 홈 광고 마커를 기대하던 검사 1건이 실패했다. 새 구조의 브랜드 진입부와 `/en/brands` 연결을 검사하도록 갱신한 뒤 전체 스윕을 통과했다. 첫 Vitest 실행 중 no-JS 보완과 사전 키가 동시에 변경돼 신규 결과화면 테스트 3건이 실패했으므로, 최종 소스를 고정한 뒤 전체를 다시 실행한 결과가 위 수치다. 로그는 작업공간의 `audience-typecheck.log`, `audience-vitest.log`, `audience-build.log`, `audience-sweep.log`에 보관한다(커밋 제외).

로컬 IAB 320×760에서 한국어 브랜드 화면을 실제 캡처했다. 수동 재생 정지 후 스크롤 이탈·복귀에도 정지 유지, 실행 중 reduced-motion 변경 시 4편 정지를 확인했다. 영문 폼은 `type=production`을 하이드레이션 후 올바르게 선택하고 한국어 계산기를 명시한다. 앱·모바일 실기기 로그인/실결제/영상 생성은 수행하지 않았다.

로컬 fixture 영상은 운영 콘텐츠 품질 증거가 아니다. 프리뷰에서 실제 공개 카탈로그/미디어를 재확인해야 한다. 최종 PC·모바일 브라우저 캡처와 Slack 실제 수신은 PR/운영 담당의 후속 확인 단계다. Slack secret과 cron secret 저장, RLS SQL 적용은 root의 운영 작업이며 실제 사이트 수신 확인과 구분한다.

JavaScript가 꺼진 폼도 `/api/brands/inquiries/result`의 서버 HTML에서 접수 결과를 확인한다. 결과에는 실제 DB의 접수 UUID와 메일 발송 여부만 사용하고 PII는 읽지 않는다. 결과 HTML은 private/no-store·noindex·CSP를 적용한다. Slack의 live runtime은 `VERCEL_ENV=production`일 때만 활성화 설정을 읽으므로 운영 변수를 복사한 프리뷰/로컬에서도 발송하지 않는다.
