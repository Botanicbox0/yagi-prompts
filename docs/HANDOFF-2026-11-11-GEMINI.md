2. **모픽 샌드박스 유지.** 조직 `d425c3b1-4066-4970-8a3b-93c52b3eef70`, `deb648e9-c2df-43d4-b2a7-7f9eff8180d9` 및 이름에 Morphic/모픽이 들어간 조직에는 스튜디오, 브랜드 키트, 전용 템플릿 의뢰, 쇼케이스 배너, **프로젝트 룸**이 보이지 않는다(대표 2026-11-11: "모픽 조직에는 아직 열지 말아야 함"). `lib/brands/features.ts`의 `SANDBOXED_CLIENT_ORG_IDS`, `DEFAULT_SANDBOX_DENIED`, `isSandboxedClientOrganization`과 `lib/brand-studio/visibility.ts`, `lib/brand-rooms/access.ts`의 가드를 지우거나 약하게 만들지 않는다. 새 화면·API를 만들면 가드를 먼저 넣고 404로 닫는다. 로그인한 워크스페이스 예시 에셋에 모픽 캠페인 영상이나 "글로벌 AI 플랫폼 · 영상 9편 · 200만 뷰+" 문구를 쓰지 않는다.

## 3. 대표에게 요청하는 규칙

- **자원이 필요하면 요청한다.** 클라우드 계정·버킷·API 키·유료 플랜·도메인처럼 직접 만들 수 없거나 돈이 드는 것은 "무엇이, 왜, 대략 얼마, 없으면 어떻게 되는지"를 한 번에 적어 요청하고, 기다리는 동안 다른 묶음을 진행한다.
- **로그인이 필요하면 멈춘다.** frame.io, storyboarder.ai, Morphic 에디터, admin.twings.app처럼 로그인해야 보이는 곳은 해당 창을 띄워 놓고 대표에게 로그인을 요청한다. 직접 계정을 만들거나 비밀번호를 넣지 않는다.
- **대표가 정할 것은 정하지 않는다.** 가격·플랜 구성, 약관 문구, 공개 사례의 브랜드명·숫자, 외부 발송 문안. 제안값과 근거를 적어 질문으로 남긴다.

## 4. 작업 묶음

권장 순서: **A → B → I(점검만) → E → C → F → D → G·H**.
G(워딩)와 H(디자인)는 화면이 바뀌는 묶음이 끝난 뒤에 적용한다. 다만 조사(목록·채점·감사 보고서)는 처음에 같이 해 둔다.

### A. 부분 수정이 어긋나는 문제 (버그, 최우선)

**증상.** 향수 병 사진에서 병 위에 로고를 넣는 부분 수정을 했더니, 고른 상자 안쪽의 병이 바깥쪽보다 크게 다시 그려져 상자 아래 변에서 병 윤곽이 계단처럼 끊겼다. 대표가 같은 방식(잘라서 고치고 다시 붙이기)을 oplux에서 손으로 했을 때와 Americano 얼굴 교체 때는 잘 됐다.

```text
C:\Users\User\Pictures\Screenshots\스크린샷 2026-11-11 151645.png
```

**원인(코드로 확인).** `lib/brand-studio/region-edit/composite.ts`가 손 작업 방식에서 정렬 단계를 뺀 채로 만들어졌다. 파일 머리말에 "Not done here: sub-pixel alignment of a shifted edit (ECC)"라고 적혀 있다.

1. 편집 모델은 돌려주는 그림의 위치와 크기를 원본과 픽셀 단위로 맞춰 주지 않는다. 지금은 돌아온 그림을 잘라 낸 영역 크기로 그대로 늘려(`fit: 'fill'`) 붙인다. 모델이 병을 몇 % 크게 그리면 그대로 어긋난다. 돌아온 그림의 비율이 요청과 다르면 찌그러지기까지 한다.
2. 붙이는 마스크가 고객이 그린 **사각형 전체**이고 가장자리 번짐이 짧은 변의 3%뿐이다. 사각형 변이 병 윤곽 같은 구조선을 가로지르면 이음매가 그대로 보인다. 손 작업 규칙은 "구조선 위에서는 가장자리를 부드럽게 지운다"였다(`docs/design/IDENTITY.md` §6-4-3).
3. 붙이기 전에 "제대로 맞았는지" 확인하는 단계가 없다. 어긋난 결과도 그대로 완성본이 된다.

어느 쪽 비중이 큰지는 운영 작업 기록의 원본 조각과 돌아온 그림 크기를 비교해 재 봐야 한다(미측정).

**목표: oplux의 편집 방식을 그대로 가져온다 (대표 지시 2026-11-11).** 대표가 잘 된다고 한 방식은 "자동으로 붙이기"가 아니라 "결과를 레이어로 받아 가장자리를 지우개로 지우고 합치기"다. 녹화 두 개를 먼저 본다(Figma 안의 oplux 플러그인, 모델은 GPT Image Editing):

```text
C:\Users\User\Videos\화면 녹화\화면 녹화 중 2026-11-11 161219.mp4
C:\Users\User\Videos\화면 녹화\화면 녹화 중 2026-11-11 161645.mp4
```

녹화에서 확인한 흐름(Claude가 프레임으로 확인):

1. 그림을 편집기에 연다. 도구는 이동, 사각 선택, 지우개, 자르기 넷. 오른쪽에 모델·프롬프트·레이어 목록.
2. 고칠 곳을 확대해서 **작게** 사각 선택한다(폴로 셔츠 가슴의 로고만, 또는 머리와 어깨만). 선택한 조각이 "입력 미리 보기"로 뜨고, 이 조각이 **1번 이미지**가 된다("The editor input image is used as the first prompt image").
3. 필요하면 참조 이미지를 추가한다(2번 이미지부터). 얼굴 교체에서는 바꿀 인물 사진을 2번으로 넣었다.
4. 문장은 번호로 지시한다. 로고 지우기: "이미지의 모든 배경과 옷 질감을 유지한 채, 로고만 자연스럽게 제거해줘." 인물 바꾸기: "1번 이미지에서 모든 배경과 얼굴 각도와 표정과 나머지 모든 요소를 유지한 채 1번 이미지의 인물을 2번 이미지의 인물로 변경해줘." 설정은 2K, 품질 중간.
5. 결과는 원본을 덮어쓰지 않고 **선택한 자리에 놓인 새 레이어**로 들어온다.
6. 아래 레이어를 숨겨 조각만 보면서 **지우개(크기, 경도 약 30%)로 조각의 가장자리를 지운다.** 로고 조각은 가운데만, 얼굴 조각은 얼굴과 머리카락만 남긴다. 조각 가장자리의 어긋난 배경·옷 주름이 이때 사라진다.
7. 레이어를 다시 켜서 이음매를 확인하고, 레이어를 합쳐 저장한다.

지금 우리 부분 수정과 다른 점: (가) 결과가 레이어로 남지 않고 자동으로 합쳐진다, (나) 사람이 가장자리를 고를 수 없다, (다) 참조 이미지와 조각에 번호를 매겨 지시하는 방식이 드러나 있지 않다. 향수 병 결과가 깨진 것은 상자가 병 윤곽을 가로질렀는데 지울 방법이 없었기 때문이다.

**만들 것.**
- 부분 수정을 "꾸미기"(레이어 편집기, `components/brand-studio/layers/*`)와 한 화면으로 합친다. 사각 선택 → 참조 추가(번호가 붙은 정사각 썸네일, 조각이 1번) → 지시 → 결과가 선택 자리의 레이어로 들어온다. 생성하는 동안 화면을 막지 않는다.
- 레이어 도구: 지우개(크기·경도), 되살리기 붓(지운 곳 복구), 레이어 보이기/숨기기, 불투명도, 아래로 합치기, 전체 합쳐 새 에셋으로 저장. 지우개는 픽셀을 버리지 않고 레이어 마스크를 고치는 방식으로 만든다(되돌리기 가능).
- **올린 이미지에서도** 같은 흐름이 돌아야 한다(스튜디오에서 만든 그림만이 아니라).
- 대상 사례 세 가지를 처음부터 넣고 각각 실제로 돌려 본다: (1) 아주 작은 부위 — 로고 넣기·지우기, 글자 고치기, (2) 얼굴 조각을 참조 인물로 바꾸기, (3) 멀리 찍힌 작은 얼굴을 조각으로 잘라 디테일을 보강한 뒤 되붙이기. 작은 조각은 2K로 키워 보내고 원래 크기로 줄여 놓는다(지금 `plan.ts`의 `WORK_TARGET_LONG`이 이 역할).
- 자동 보조는 기본값으로만 둔다: 레이어가 들어올 때 가장자리를 미리 부드럽게 지운 마스크를 걸어 주고(아래 "정렬"과 "마스크"), 사람이 지우개로 마무리한다. "자동으로 바로 합치기"는 선택 사항으로 남긴다.
- **지시 도우미 엔진.** oplux에는 어떻게 지시하면 되는지 알려 주는 것이 없다. 우리는 넣는다: 선택한 조각과 참조를 읽어 하려는 일을 고르게 하고(로고 지우기 / 로고·글자 넣기 / 인물 바꾸기 / 디테일 보강 / 직접 쓰기), 고르면 검증된 문장 틀("1번 이미지에서 …을 유지한 채 …만 …")을 번호와 함께 채워 준다. 참조가 필요한 일인데 없으면 먼저 알려 준다. 상자가 너무 크거나 구조선을 가로지르면 "더 작게 고르면 정확해져요" 같은 안내를 한다. 기존 보정기(`lib/brand-studio/enhancer/`, `profiles/tasks.ts`)에 얹고, 화면 안내는 "!" 설명 방식(`components/brand-studio/explainer.tsx`)을 따른다. 보정된 문장은 조각의 구도·크기·위치를 그대로 두라고 말해야 한다(지금 문장은 대상을 다시 그리게 유도한다).
- oplux를 직접 써 봐야 하면 Figma에서 플러그인을 열어 본다(로그인·크레딧이 필요하면 대표에게 요청).

**자동 보조의 세부(기본 마스크와 검사).**
- 정렬: 상자 바깥 띠(모델이 바꾸면 안 되는 부분)를 기준으로 돌아온 그림의 이동·배율(가능하면 affine)을 추정해 맞춘 뒤 놓는다. 서버에는 OpenCV가 없으니 (a) 축소한 흑백 그림에서 배율·이동을 탐색하는 순수 JS 구현, (b) `opencv-wasm` 계열, (c) 로컬 작업기(예약 작업 `TWINGS-Studio-Lane`, Python + OpenCV 가능)에 붙이기를 맡기는 방법을 비교해 고른다. 손 작업 원본은 `D:\dev\Video-Creator`의 local-fix 스크립트다.
- 마스크: 정렬한 뒤 원본과 실제로 달라진 픽셀만 고르고(차이 마스크 → 넓히기 → 번짐), 상자 변이 구조선과 만나는 곳은 번짐을 넓힌다. 차이 마스크를 못 만들면 지금 방식으로 내려간다.
- 검사: 정렬 뒤 바깥 띠의 잔차가 크면 한 번 다시 시도하고, 그래도 크면 붙이지 않고 "이 부분은 정확히 맞추지 못했어요"라고 알린다. 크레딧 처리 규칙도 같이 정한다(대표 질문).
- 모델: 마스크를 직접 받는 편집 모델이 Sunra에 있으면 그 경로(전체 그림 + 마스크)를 조각 방식과 비교한다.
- 문장: 보정된 프롬프트에 "이 그림은 큰 사진의 일부이며 구도·크기·위치를 그대로 둔다"를 넣는다. 지금 문장은 병을 다시 그리게 유도한다("curving naturally to match the cylindrical curvature").
- 불변 조건은 유지한다: 상자 밖 픽셀은 0개 바뀐다(`tests/brand-studio`의 원시 버퍼 테스트).

**완료 기준.** (1) 녹화의 두 흐름(로고 지우기, 참조 인물로 얼굴 바꾸기)을 우리 화면에서 처음부터 끝까지 따라 할 수 있다: 선택 → 참조 → 지시 → 레이어 → 지우개 → 합치기. (2) 같은 향수 병 사진에 로고 넣기, 작은 얼굴 디테일 보강을 실제로 돌린 전·후 그림을 대표에게 보여 준다(Sunra 비용을 먼저 말한다). (3) 일부러 3~8% 크게, 몇 픽셀 밀린 편집본을 넣는 자동 보조 테스트가 통과한다. (4) 지시 도우미가 다섯 가지 일에 대해 문장을 채워 주고, 참조가 빠졌을 때 알려 준다.

### D. 영상 합치기 (간단한 편집기)

- 목표: 만든 영상 여러 개를 순서대로 놓고, 자르고, 글자와 음악을 얹어 한 편으로 내보낸다. **간단하게.** 참고: Morphic 에디터의 compose 화면(로그인 필요 → 대표에게 요청), OpenCut `https://github.com/opencut-app/opencut`.
- OpenCut에서 가져올 것(타임라인 모델, 렌더 방식)을 고르기 전에 **라이선스와 의존성**을 확인해 설계 문서에 적는다. 코드를 통째로 넣지 말고 우리 화면 규칙으로 다시 짠다.
- 내보내기를 어디서 할지 비교한다: 브라우저(WebCodecs 등) / 서버 함수(시간·메모리 한도) / 로컬 GPU 작업기. 30초·1080p 기준으로 실제 걸리는 시간을 잰다.
- **채팅으로 편집**(참고 `https://github.com/0xsline/OpenChatCut`): 대표는 사용자가 자기 ChatGPT·Claude 구독을 연결하는 방식을 원한다. 구현 전에 (1) OpenChatCut이 실제로 무엇을 연결하는지(구독 로그인인지 API 키인지 로컬 CLI인지), (2) OpenAI·Anthropic 약관이 제3자 웹 서비스에서 소비자 구독 로그인을 쓰는 것을 허용하는지 확인해 보고한다. Claude 쪽 인계 메모: 소비자 구독 토큰을 제3자 서비스에서 쓰는 것은 제한되는 것으로 알고 있다(확인 필요). 막혀 있으면 대안은 사용자 API 키 입력 또는 우리 크레딧으로 돌리는 채팅 편집이다. 대표에게 선택지로 묻는다.

### E. "야기 팀과" 다시 짜기 — 의뢰, 소통, 작업물 리뷰

대표 지적: 의뢰·메시지·리뷰 탭의 체계가 안 잡혀 있다. 메시지에서 작업물을 놓고 의견을 나누거나 공유하기가 불편하다. frame.io 수준이 아니다.

**Claude의 권고안**(더 좋은 구조가 있으면 바꿔도 된다):

1. 레일의 "야기 팀과" 묶음을 **"프로젝트" 하나**로 줄인다(크리에이터는 캠페인 쪽으로). 들어가면 스튜디오와 다른 공간처럼 보이게 한다(다른 머리말, 프로젝트 목록이 첫 화면). 주소를 따로 두는 것도 된다.
2. 프로젝트 안은 **작업물 중심**이다. 탭: 개요 / 파일(기획서, 스토리보드, 시안, 최종본) / 대화. 의견은 대화방이 아니라 **작업물 위에** 단다: 영상은 시간·구간과 화면 위 표시, 그림과 PDF는 위치 핀. 대화 탭에는 그 의견이 카드로 흘러 들어오고, 누르면 해당 작업물의 그 지점이 열린다.
3. "메시지"와 "리뷰" 메뉴는 없애고, 모든 프로젝트의 새 의견·승인 요청·새 버전을 모은 **알림함** 하나로 대신한다.
4. 시안 화면이 frame.io에 못 미치는 부분을 직접 써 보고 채운다(대표가 Chrome에 frame.io를 띄워 놓았다. 로그인이 필요하면 요청한다): 버전 스택과 비교, 프레임 단위 이동, 의견 필터와 완료 처리, 승인 상태, 의견 내보내기, 공유 링크의 권한·만료·암호·내려받기.
5. 참고로 실제 사용 흐름을 본다: frame.io, Slack(스레드·멘션), `https://app.storyboarder.ai`(스토리보드), 비슷한 영역의 상위 서비스 2~3개. 무엇을 가져오고 무엇을 버렸는지 설계 문서에 적는다.

**의뢰 접수 폼.** 고객은 보통 기획서를 PDF·PPT로 넘기거나 글로 전달한다. 권고 구성(3단계, 임시 저장 가능):

1. 무엇을 맡기나: 유형(전용 템플릿 / 영상 캠페인 / 영상 제작 / 기타), 프로젝트 이름, 한 줄 목표.
2. 자료: 기획서 파일(PDF, PPT, 문서, 이미지), 또는 글로 붙여 넣기, 참고 영상 링크, 제품·브랜드 에셋(에셋에서 고르기).
3. 조건: 원하는 결과물(종류, 길이, 비율, 수량, 올릴 채널), 희망 일정(시작, 납품), **대략적인 예산(구간 선택 + "아직 모름")**, 담당자와 연락 방법, 승인하는 사람.

올라온 기획서를 읽어 2·3단계 칸을 미리 채워 주는 기능을 검토한다(고객이 확인하고 고친다). 지금 폼과 필드는 `lib/brands/workspace/commission-tracks.ts`와 `docs/CAMPAIGNS.md` §11을 본다. 관리자 문의함에 새 필드가 보여야 한다.

**구독하지 않는 외주 고객.** 구독 없이 프로젝트만 맡기는 고객사가 있다. 이 조직은 "프로젝트" 공간만 쓰고 스튜디오(직접 만들기)는 닫히거나 체험 수준이어야 한다. 조직 상태를 어떻게 나눌지(예: 구독 / 프로젝트 전용), 초대·권한·저장 한도·프로젝트 종료 뒤 보관 기간을 설계한다. 기능 개방은 `lib/brands/features.ts`의 "기본 개방 + 조직별 차단 목록" 구조를 따른다. 가격·계약 조건은 대표 결정이다.

이미 있는 것: 룸(대화·스토리보드·시안·공유 링크), 관리자 화면 `/admin/brand-rooms`, CLI `scripts/twings-room.mjs`(`docs/BRAND-ROOMS-CLI.md`). 테이블은 살리고 화면 구조를 바꾼다.

### F. 조직별 저장 한도

### I. 설계 검증과 규모가 커졌을 때의 문제 (점검 보고서 먼저)

각 묶음은 **짧은 설계 문서 → 작은 PR → 실제 화면 확인** 순서로 한다. 설계 문서에는 목표와 하지 않을 것, 검토한 대안과 버린 이유, 데이터 모델, 실패했을 때의 동작, 측정할 숫자, 되돌리는 방법을 적는다.

코드를 고치기 전에 아래를 읽고 **위험 목록**(`docs/SCALE-RISKS-2026-11.md`: 항목 / 근거 파일 / 어느 규모에서 터지는지 / 심각도 / 대책 / 비용)을 만든다. Claude가 알고 있는 후보:

- 룸 메시지가 폴링(4초·20초)이다. 동시 사용자 수 × 함수 호출 수.
- 시안 올리기는 서버가 파일을 통째로 읽어 옮긴다(그래서 200MB 한도). 브라우저에서 저장소로 직접 올리는 구조가 필요하다.
- 스튜디오 그림이 같은 출처 게이트웨이(`app/api/brand-studio/media/[...key]`)를 거친다. 함수 시간과 전송량.
- 갤러리·보관함·대화 목록의 페이지 나누기, 긴 목록 그리기, 새 테이블의 인덱스.
- 생성 작업 줄: 계정 경로 작업기가 이 PC 한 대의 예약 작업이다(단일 장애점). 제공사 동시 실행 한도(20).
- 크레딧 차감의 동시성, 조직·사용자별 속도 제한, 비용 폭주 방지.
- 공개 공유 링크 `/s/[token]`의 속도 제한과 추측 방어.
- Vercel Hobby 플랜의 한도와 약관(상업 서비스에 맞는지 확인), Supabase 전송량(11-02에 한도로 인증까지 막힌 적이 있다), DB 연결 수.
- 오류 추적·알림이 있는지, 백업과 복구 연습.
- GitHub Actions가 결제 문제로 돌지 않아 CI가 없다. 로컬 루프가 유일한 검증이다.

## 5. 검증과 보고

`AGENTS.md` §3의 루프를 전부 통과해야 끝난 것이다. 이 PC에서 알아 둘 것:

```bash
npx tsc --noEmit
```

```bash
npx vitest run --maxWorkers=6
```

```bash
rm -rf .next && MSYS_NO_PATHCONV=1 NEXT_PUBLIC_APP_URL=http://localhost:3330 npm run build:local
```

```bash
MSYS_NO_PATHCONV=1 SWEEP_BASE_URL=http://localhost:3330 NEXT_PUBLIC_APP_URL=http://localhost:3330 npm run sweep:anon
```

- vitest는 기본 병렬 수에서 메모리 부족으로 작업자가 죽는다. `--maxWorkers=6`을 쓴다.
- 3000이 아닌 포트에서 스윕하려면 빌드와 실행 모두 `NEXT_PUBLIC_APP_URL`을 그 주소로 준다. Git Bash는 `/`로 시작하는 환경변수 값을 경로로 바꾸므로 `MSYS_NO_PATHCONV=1`을 붙인다.
- 로컬 서버 설정은 `D:\dev\twings\.claude\launch.json`의 `brand-studio-v2-fake`(3320, 개발용·가짜 제공사)와 `brand-studio-v2-start`(3330, 빌드 실행)에 있다. 서버를 멈춘 뒤 포트가 남으면 포트 소유 프로세스를 끝낸다.
- `db:local`을 다시 돌리면 빌드를 다시 해야 스윕이 맞는다. 로컬 모드의 쓰기는 서버를 다시 켜면 초기화된다.
- Vercel 환경변수는 Git Bash에서 `printf 'value' | vercel env add NAME production`으로 넣는다(PowerShell로 넣으면 줄바꿈이 붙어 플래그가 꺼진 것으로 읽힌다). 넣은 뒤 재배포.
- 화면은 실제 브라우저로 확인하고 캡처를 남긴다. 캡처에 운영 고객 정보가 들어가지 않게 한다.
- 보고: `git rev-parse HEAD`, `git diff --stat`, 실행한 명령과 결과, 건너뛴 검사, 남은 위험, 다음 행동, 프리뷰 URL. 묶음 하나가 끝나면 ICM `context-twings`에 상태를 저장한다.
- 형식 검증(`AGENTS.md` §11)은 크레딧 차감·저장 한도 집계처럼 돈과 한도가 걸린 상태 전이에만 검토한다. 도구가 없으면 "미실행"으로 보고한다.
