## 2. 대표 결정을 기다리는 것 (임의로 정하지 않는다)

- **영상 스튜디오 모드·확인 카드 켜기**: 카드의 "바꿀 것"이 실제 영상에 반영되는지는 유료 초안으로만 확인된다. 견적(Re-Architect 15초 480p 초안 약 241크레딧, 18초 참고 영상의 Motion Transfer 약 318크레딧)을 드렸고 "진행"을 기다린다. 그 전에는 `BRAND_STUDIO_VIDEO_MODES`를 켜지 않는다. 스위치가 꺼져 있는 동안 참고 영상을 붙이면 대표가 지적한 펼쳐지는 패널이 그대로 나온다.
- 캠페인 운영(`BRAND_CAMPAIGN_OPS`)과 이미지 수정 결과를 벽에 올리기(`BRAND_STUDIO_EDIT_TO_WALL`)를 테스트 조직 밖으로 넓힐지.
- 오버레이 트랙 최대 3개(참고한 편집기는 12개 이상 허용).
- 다른 사람의 영상·음원을 참고로 올릴 때의 약관 문구.
- "AI 미디어 후보정에 특화된 편집 스튜디오"가 편집기에서 구체적으로 무엇인지(1단계 뒤에 묻기로 함).

## 3. 오버레이 트랙: 한 것과 남은 것

한 것(1단계, 이 PR): 컷을 위로 끌어 오버레이로, 겹친 자리는 새 트랙(최대 3), 아래로 끌어 메인에 삽입, 연동(기본 켜짐·오버레이 종류는 기본 꺼짐), 자동 스냅(2px 붙고 6px 풀림), 겹쳐 보는 미리보기, 꼬리 구간 재생, 단축키, 말로 편집 카드의 안내 줄, 내보내기 차단(새 편집 스튜디오와 예전 편집기 모두).

남은 것(순서대로):
1. **T2 오버레이까지 내보내기**. 지금은 오버레이가 있는 영상의 내보내기를 막아 둔다. 내보내기가 되기 전에는 이 스위치를 테스트 조직 밖으로 넓히지 않는다.
2. T3 미리보기에서 오버레이 크기·위치 조절, 트랙 수 늘리기.
3. T4 오디오 분리, T5 트랙 머리(잠금·숨김·음소거).
4. 만들지 않은 것: 자석 끄기, 그룹, 잠금/숨김/음소거.

동작 규칙의 근거(직접 실험한 기록)와 설계는 Claude의 작업 노트에 있다(저장소 밖). 핵심 규칙: 연동은 클립의 **시작점** 아래 메인 컷에 묶인다; 묶인 컷을 지우면 클립도 통째로 지워진다; 메인 컷 순서 바꾸기는 이웃 컷의 (닫힌 뒤) 중간 지점에서 바뀐다; 스냅은 0초에도 붙는다.

코드 위치: `components/brand-studio/editor-v2/`(timeline.tsx, preview.tsx, play-forward.ts, panels.tsx, export-sheet.tsx), `lib/brand-studio/editor-v2/tracks.ts`(규칙), `stored.ts`(저장 형식: 기존 `overlays`에 프레임 블록을 더함), 문구 `messages/studio-editor-tracks.ts`, 테스트 `tests/brand-studio/editor-v2/tracks-*.test.ts(x)`.

## 4. 검증 방법 (완료라고 하기 전에)

1. `AGENTS.md` §3 루프 전부: `npx tsc --noEmit` → `npx vitest run` → `npm run build:local` → `npm run start:local` → `npm run sweep:anon`. 새 마이그레이션이 들어왔으면 `npm run db:local`을 먼저 다시 돌린다. vitest 전체 출력은 파일로 받는다.
2. 화면이 바뀌는 변경은 브라우저에서 실제로 끌고 누른다(1440×900). **내보내기는 정식 Chromium(`channel=chromium`)으로** 확인한다. 가벼운 헤드리스 셸은 스위치와 무관하게 내보내기 중 죽는다(이번에 원인 찾느라 두 번 돌았다).
3. 재생 타이밍은 화면 갱신이 초당 55회 이상일 때만 판단한다(가려진 창은 초당 1회로 떨어진다).
4. 병합 뒤 배포가 READY가 되면 운영 테스트 조직에서 한 번 눌러 본다. 유료 생성(만들기)은 누르지 않는다.

## 5. 이번에 배운 주의점

- **원인 설명을 검증한다.** 내보내기 탭이 죽는 문제에 대해 "빈 배열을 매번 새로 만들어서"라는 설명이 나왔지만 틀렸다(양쪽이 같은 코드, 나노초 단위). 켠 쪽과 끈 쪽을 같은 조건(새 프로필, 번갈아)에서 재서 환경 문제로 가렸다.
- **"main과 같다"는 테스트는 main의 실제 결과에 묶는다.** 자기 코드로 기대값을 만들면 아무것도 증명하지 않는다. 닫힌 화면은 sha256과 길이로 고정해 둔다.
- **기존 테스트 기대값을 느슨하게 바꾸지 않는다.** 바꿨다면 PR 본문에 무엇을 왜 바꿨는지 적는다.
- **스쿼시는 main을 합친 직후, behind 0에서만.** `reset --soft origin/main` 전에 `git fetch` 후 뒤처진 커밋이 0인지 보고, 스쿼시 뒤 `git diff --name-only origin/main..HEAD`에 남의 파일이 없는지 본다.
- `play-forward.ts`는 운영 재생 수정(#427)이 들어 있다: 컷 끝/`video.ended` 판정이 `play()`보다 먼저다. 순서를 바꾸면 원본 끝까지 쓰는 컷에서 다시 멈춘다(`tests/brand-studio/editor-v2/playback-end.test.tsx`).
- 저장소는 공개다. 커밋·PR 본문에 고객사 이름, 개인정보, 조직 id를 쓰지 않는다. 참고한 편집기의 제품 이름도 코드·주석·테스트·문구에 쓰지 않는다.
- 결제, 크레딧, 렌더 작업 상태, 마이그레이션을 건드리는 변경은 PR만 열고 병합은 월요일 검수 뒤로 미룬다(대표에게 권한 내용).
