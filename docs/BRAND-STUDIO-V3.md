# 브랜드 스튜디오 개편 (v3) — 2026-11-11

> v2(`docs/BRAND-STUDIO-V2.md`)의 서버(계약·모델·두 경로·허용량·검수 재시도)는 그대로 쓴다. 이 문서는 대표의
> 2026-11-11 피드백으로 **화면과 흐름**을 다시 짠 것이다. v2 문서와 다르면 화면·내비게이션은 이 문서가 맞다.
> 플래그는 그대로 `BRAND_STUDIO_V2`. 꺼져 있으면 운영 화면은 달라지지 않는다.

## 1. 대표가 말한 것 (원문 요지)

1. B2B 스튜디오에는 본인 얼굴 확인이 없다. 브랜드는 AI 페르소나나 다른 인물을 쓴다. "내 사진이 준비됐어요",
   템플릿별 본인 확인 체크를 스튜디오에 두지 않는다.
2. "브랜드 전용 포맷 / 인하우스 패키지"는 제품을 정확히 말하지 않는다. 회사 소개서 기준으로 다시 쓴다.
   구조는 **이미지 만들기**와 **영상 만들기**(캠페인 제작, 스케일 제작, 단일 영상 의뢰, 그리고 야기 팀과 피드백을
   주고받는 리뷰 공간).
3. 이미지 탭은 갤러리 벽 + 떠 있는 프롬프트 바. 차별점은 오른쪽 탭: **폴더 / 좋아요 / 내 업로드**에서 끌어다 쓰기.
4. 부분 수정은 참조 이미지(로고·제품·얼굴)를 받아야 하고, 수정 중에도 다른 탭·다른 생성이 막히면 안 된다.
5. 완성 뒤 편집: Canva류 레이어 편집을 어떻게 녹일지.
6. 참조는 작은 정사각 썸네일 + 아래 번호. "이미지 1" 둥근 칩이 아니다.
7. GPT Image 2.6 Flare / Sunburst 선택 가능. 프롬프트 개선 옆 "!"에 hover하면
   "각 이미지 모델에 최적화 된 프롬프트가 생성됩니다." 모델마다 무엇에 강한지 표시. 버튼을 누르면 입력창이 빛나며
   개선된 프롬프트를 보여 준다(Gemini 3.8 Flash, 고객 무료).
8. 원이 아니라 **크레딧**으로 보여 준다.
9. 왼쪽 사이드바. 탭 순서 변경, 이름 숨기기(접기).
10. 팀 화면에 멤버별 월 크레딧 사용량.
11. 영상: 참고 영상을 넣고 → 리버스 → 참고 영상 없이도 거의 같게 재현. 그리고 이 영상이 캠페인이 되어
    twings.app의 인플루언서·일반 유저에게 노출된다는 것이 보여야 한다.
12. 처음 쓰는 사람을 위한 설명(히어로 + 단계 카드).

  `studioV2`(서버가 넘긴 `brandStudioV2Open()`)가 켜져 있으면 `rail`, 아니면 지금처럼 `topbar`.
  **`sidebar` 분기의 마크업과 CSS는 한 글자도 바꾸지 않는다**(하드라인).
- 레일: 접힘 72px(아이콘 + hover 툴팁) ↔ 펼침 232px(아이콘 + 이름). 맨 아래 토글. 상태는

  편집 스튜디오(`/brand/studio/editor`, `/brand/studio/compose`)는 저장값과 상관없이 접힌 채 열리고, 거기서의
  토글은 그 방문에만 해당해 쿠키·localStorage에 쓰지 않는다(대표 요청 2026-11-25, `rail-model.ts` `railEditorRoute`).
- 항목(기본 순서): 이미지 `/brand/studio` · 영상 `/brand/studio/video` · 리뷰 `/brand/studio/review` ·
  캠페인 `/brand` · 크리에이터 `/brand/creators`(열려 있을 때) · 에셋 `/brand/library` · 브랜드 키트 `/brand/identity`.
  아래쪽: 팀 `/brand/members` · 설정 `/brand/settings` · 언어 · 로그아웃.
  스튜디오 세 항목은 `visible.studio`일 때만.
- 가운데 채운 **"+" 만들기** 버튼: 메뉴(이미지 만들기 / 영상 만들기 / 참고 영상으로 만들기 / 캠페인 의뢰).

- 크레딧 계기: 레일 아래. 펼침 "크레딧 12,340 / 30,000" + 막대 + 채워지는 날, 접힘은 고리 아이콘 + 툴팁.

### 3.1 레일 정리 (2026-11-25)

대표의 말: "레일도 정리해줘". 홈을 정리한 뒤(§12) 펼친 레일이 화면에서 가장 무거웠다: 누를 수 있는 것이 21개,
흰색으로 꽉 찬 "홈" 알약과 흰 원 "+ 만들기"가 화면의 주 버튼과 겨뤘다. 위 목록에서 아래 항목은 이 절이 대신한다.

- **세 묶음.** 위: 로고 + 브랜드 블록. 가운데: 모드 전환 → 홈과 주 메뉴 → "+ 만들기". 아래: 크레딧 한 줄 →
  POWERED BY와 접기 버튼. 그 밖의 줄은 없다.
- **워크스페이스 메뉴**(`components/brand-workspace/rail-workspace-menu.tsx`): 브랜드 블록을 누르면 열린다.
  첫 묶음이 팀 · 플랜 및 청구 · 설정(이 역할이 열 수 있는 것만), 그 아래 브랜드 바꾸기(브랜드가 둘 이상일 때),
  언어(한국어 | English), 순서 편집, 로그아웃. 레일 아래에 흩어져 있던 일곱 줄이 이 메뉴 하나다. 문구는 전부
  레일과 워크스페이스에 있던 문자열이다. 키보드: 블록에서 Enter·Space·↓로 열고(↑는 마지막 항목), ↑↓는 돌고,
  Home·End, Esc는 닫고 블록으로 돌아가며, Tab은 닫고 넘어간다. `role="menu"`, 이름은 브랜드 블록.
- 넓은 화면에서 레이아웃의 브랜드 블록·언어·로그아웃 줄은 숨기고(`rail.css`) 레일의 블록이 대신한다. 폰의 상단 바는
  세 가지를 그대로 둔다. 스크립트가 꺼진 브라우저에서는 예전 세 줄이 다시 나오고,
  팀 · 플랜 및 청구 · 설정은 레일 아래의 일반 링크로 나온다(`noscript`).
- **줄**: 높이 36px, 간격 2px. 지금 있는 쪽은 옅은 잉크 칠(11%) + 잉크 글자다. 흰색으로 채운 알약과 포인트 색 채움은
  레일에 쓰지 않는다. 개수 배지만 잉크로 채운다.
- **"+ 만들기"**(야기 팀과에서는 "새 프로젝트 의뢰"): 줄과 같은 높이의 외곽선 줄. 메뉴와 가는 곳은 그대로다.
- **순서 편집**: 메뉴에서 시작한다(접힌 레일이면 먼저 펼친다). 켜져 있는 동안만 목록 아래에 "완료"·"처음 순서로"가
  나온다. 끌어서 바꾸기와 저장 위치는 그대로다.
- **크레딧**: 상자 없이 한 줄 + 2px 막대 + 채워지는 날. 플랜 및 청구를 열 수 있는 역할에게는 그 화면으로 가는 링크다.
- **접힌 레일**: 같은 구조다. 브랜드 아바타가 같은 메뉴를 옆으로 열고, 아이콘 줄, 외곽선 "+", 크레딧 고리, 펼치기.
- 바꾸지 않은 것: 항목과 권한, 모드와 펼침 쿠키, 알림 배지, 640px 이하의 탭 바와 더보기 시트, 조직이 없는 계정과
  비로그인 화면, `sidebar`·`topbar` 분기.

## 4. 이미지 화면 (슬라이스 B1 + B2)

```
┌ 레일 ┬──────────────── 갤러리 벽 ────────────────┬ 보관함 레일 ┐
│      │  [결과 카드들: 줄 맞춘 타일, 여백 4px]      │ 폴더│좋아요│업로드 │
│      │                                            │  썸네일 그리드  │
│      │        ┌─ 떠 있는 프롬프트 바 ─┐            │  (끌어다 놓기)  │
└──────┴────────┴───────────────────────┴───────────┴────────────────┘
```

**갤러리 벽(B1)**
- 화면 끝까지 채우는 줄 맞춤 타일(높이 고정, 비율대로 폭). 날짜 구분선은 얇게.
- 카드 hover: 좋아요 하트, 폴더에 담기, 참조로 쓰기, 더보기 메뉴(열기 · 다시 만들기 · 설정 다시 쓰기 · 부분 수정 ·
  디테일 편집 · 영상으로 만들기 · 폴더에 담기 · 캠페인으로 보내기 · 저장 · 삭제).
- 진행 중 카드는 벽 안에서 자리 잡고 단계(대기 · 만드는 중 · 마무리)를 보여 준다. 실패 카드는 이유 한 줄 + 다시.
- 카드는 끌 수 있다(`REF_DRAG_TYPE`): 프롬프트 바, 부분 수정 참조, 레이어 편집기, 폴더로.
- 빈 상태: 설명 히어로 + 예시 문장.

**프롬프트 바(B1)**
- 아래 가운데 떠 있는 반투명 패널. 위: 참조 줄(**정사각 썸네일 44px + 아래 번호 1, 2, 3 …**, hover 시 ✕, 끌어서 순서 변경,
  누르면 쓰임/피할 것 메모). 가운데: 입력창. 아래: 모델 칩 · 비율 · 해상도 · 장수 · ✨개선 · [만들기 **N 크레딧**].
- 모델 칩을 누르면 목록: 이름 + **무엇에 맞는지 한 줄** + 장당 크레딧. 한 줄은 `brandStudio.models`에 있고, 확인한 사실과
  크레딧·해상도·참고 이미지 수만 쓴다(최상급, 확인하지 않은 비교 금지; `tests/brand-studio/ui/model-hints.test.ts`).
  부분 수정은 Seedream 5.5 하나로만 돌아서(2026-11-17) 어느 모델의 한 줄에도 "수정"을 쓰지 않는다. 인물은 GPT Image로도
  만든다(2026-11-19). 2026-11-20 문구: Seedream 5.5 "제품·인물 사진", GPT Image 2.6 Flare "속도가 빠르고 참고 이미지를
  16장까지 쓸 수 있어요", Sunburst "Flare보다 느리지만 세밀한 묘사에 집중해요", Nano Banana Pro "글자와 로고를 정확하게
  표현해요", Nano Banana 2.1 "참고 이미지로 일관성 있게 만들어요".
- **프롬프트 개선**: 토글(자동 개선, 기본 켬) + 옆 "!" — hover/포커스 툴팁
  "각 이미지 모델에 최적화 된 프롬프트가 생성됩니다." ✨ 버튼을 누르면 `prompt.enhance` 호출 → 입력창 테두리가
  빛나며 흐르고, 끝나면 개선된 문장으로 바뀐다("원래 문장으로" 되돌리기 제공). 이렇게 미리 개선한 문장은
  `enhance: false`로 보낸다. 무료라는 점을 툴팁 둘째 줄에 적는다.
- 금액 표시는 전부 크레딧. 허용량 줄은 "남은 크레딧 N".
- `StudioApp`에 `mode: 'image' | 'video'` — 화면이 매체를 고정한다(영상 화면이 `mode="video"`로 쓴다).
- 창 이벤트 `STUDIO_JOB_STARTED`를 들으면 보드를 다시 읽는다(다른 화면이 작업을 시작했을 때).

**새 모델(B1)**
- `gpt-image-2.6-flare`, `gpt-image-2.6-sunburst`: `npm run studio:catalog`로 Sunra 카탈로그에서 별칭·엔드포인트·
  인자 이름·가격을 **읽어서** 등록한다. 추측으로 넣지 않는다. 카탈로그에 없으면 `awaiting_provider`.
- 프롬프트 프로필 `gpt-image` 추가(`enhancer/profiles/gpt-image.ts`).
- 부분 수정에 쓸 수 있으면 `regionEdit: true`.
- 2026-11-11 확인: API 가격표는 사후 정산(요청당 $4 보류)이라 장당 가격이 없다. 계정 경로의 무료 견적은 두 모델이 같고
  low 3/6/9 · medium 5/9/15 · high 6/11/18(1K/2K/4K, 계정 크레딧 = 센트). 이 표로 두 경로 모두 예상 사용량을 잡고 `live`로 켰다.

### 4.1 업로드 사진의 역할 자동 인식 (2026-11-19)

업로드의 역할(제품·인물·로고·스타일·장소·기타)은 Prompt Architect의 참조 지시를 정한다(`enhancer/lines.ts`: 제품은 라벨·비율·색 유지,
인물은 얼굴·머리·체형만, 로고는 표식 그대로, 스타일은 빛·색·질감만, 장소는 배경만)와 피부 규칙(`profiles/skin.ts`, 인물이면 켜짐).
지금까지 아무도 정하지 않아(운영 업로드 17건 중 0건) 업로드 탭의 역할 칩이 비고, 작성기는 매번 사진을 보고 추측했다.

- **무엇을**: 사진을 올리면 한 번, 서버가 512 px WebP 썸네일을 Gemini(`gemini-4-hydrogen`, thinking LOW, `studioGeminiConfig`)에
  보내 사실만 받는다: 가장 맞는 역할, 다음으로 그럴듯한 역할(없으면 none), 사진 종류(사진·렌더·평면 그래픽·스크린샷·문서·콜라주),
  사람(없음·손이나 몸 일부·얼굴 보이는 한 명·얼굴 안 보이는 한 명·여럿), 인물 프레이밍, 빛(고름·자연광·극적·색광이나 효과),
  글자 양, 한 면이 화면을 채우는지. 저장 여부는 서버의 `roleFromFacts`(`lib/brand-studio/asset-role.ts`) 하나가 정한다.
  투명 썸네일은 회색 위에 얹어 보낸다(검은 로고가 투명 배경에서 안 보이던 문제, 실측).
- **언제**: 이미지 업로드가 끝난 뒤(`completeStudioAsset`), 응답을 보낸 다음 Next `after()`로(`StudioDeps.later`). 업로드를
  늦추거나 막거나 실패시키지 않는다. 올린 사람이 역할을 정했으면 묻지 않는다. 영상·오디오·생성 결과·팀 납품·업스케일 결과는 읽지 않는다.
  "빈 곳 채우기"가 올리는 캔버스 전체 그림(보관함에서 숨기고 실행이 끝나면 지우는 것)은 완료 요청에 `transient: true`를 실어 읽지 않는다.
  완료 응답의 `roleCheck: true`를 받은 화면은 약 4·8·14·24초 뒤 보관함을 다시 읽고, 답(`roleSource`)이 오면 멈춘다.
- **확실할 때만 저장**: 틀린 역할은 빈 역할보다 나쁘다(스타일 사진이 `product`로 저장되면 "라벨 유지"를 쓴다). 그래서
  ① `other`는 저장하지 않는다. ② 두 번째 읽기가 있으면 비운다. 단 실측상 모델은 거의 모든 사진에 `style`을 두 번째로 붙이므로,
  제품·인물은 빛이 평범할 때(고름·자연광)만 `style`을 무시하고, 장소는 `style`, 스타일은 `place`를 무시한다. 사람이 제품을 든
  사진(`person`/`product`), 정물인지 룩인지 애매한 사진(`style`/`product`), 장면 속 제품(`product`/`place`), 두 번째 읽기가 있는
  로고는 비운다. ③ 사실이 역할과 맞아야 한다: 제품은 사람 없음 또는 손만, 인물은 얼굴 보이는 한 명 + 클로즈업~상반신,
  로고는 평면 그래픽이나 렌더 + 글자는 표식뿐, 장소는 사람 없음 + 한 면이 화면을 채우지 않음, 스크린샷·문서·콜라주와 글자 많은 사진은 비움.
  첫 읽기가 답을 못 주면(15초 시간 초과, HTTP 오류, 잘못된 JSON) 같은 작업 안에서 한 번 더 묻는다(업로드당 호출 최대 2번).
  차단(`gemini_blocked`, 안전 사유 중단)은 다시 묻지 않는다. 두 번 다 실패하거나 차단되면 아무것도 쓰지 않고(역할은 비고 지금처럼
  작성기가 추측) `asset_role_failed {reason, tries}` 한 줄을 남긴다. 작업은 응답 뒤에 돌고 `POST /api/brand-studio`의
  `maxDuration = 300`초 안에 있다(15초 × 2 + 썸네일 읽기, 프로젝트 기본값 없음).
- **데이터**: `brand_studio_assets.role_source`(0098/0171) — `auto`: 확인을 마침(역할이 있으면 자동 인식, 없으면 애매해서 비움, 다시 묻지 않음),
  `user`: 고객이 정하거나 지움(업로드 때, 정보 고치기, 결과 저장 때). 자동 쓰기는 `role`과 `role_source`가 둘 다 비어 있을 때만 들어간다.
  이름만 고치면 역할을 보내지 않아 `auto`가 남는다. 자동 역할을 바꾸면 서버 로그 `asset_role_corrected {from, to}` 한 줄(행은 `user`가 된다).
- **화면**: 업로드 타일은 hover·포커스 때 오른쪽 아래에 역할 칩 하나(재생시간 칩과 같은 어두운 유리). 정보 고치기 창은 화면 가운데
  모달(배경 어둡게, Esc·배경 누르기로 닫힘, 닫으면 그 타일로 포커스가 돌아감)이고, 역할은 업로드 탭 필터와 같은 칩 한 줄
  (정하지 않음 + 여섯 역할, 라디오 그룹: Tab 한 번, 화살표로 이동·선택)로 고른다. 보이는 역할이 자동 인식 그대로일 때 칩 바로 아래
  한 줄 `uploads.roleAuto`. 트레이에 먼저 붙인 사진은 역할이 도착하면 채워진다(트레이에서
  고른 역할은 그대로). 서버는 트레이에 역할이 없을 때 저장된 역할을 쓴다(`plan.ts`).
- **끄기**: `BRAND_STUDIO_ASSET_AUTO_ROLE=off`. Gemini 키가 없으면 늘 꺼져 있다. 샌드박스 조직은 스튜디오 API가 404라 업로드 자체가 없다.
- **비용**: 이미지 업로드 1건당 호출 1번, 첫 읽기가 답을 못 줄 때만 2번("빈 곳 채우기" 임시 그림은 0번). 실측 평균 입력 약 2,300 · 출력 약 75 · 생각 약 290 토큰,
  중앙값 약 4.3초.
- **평가**: `npx tsx scripts/asset-role-eval.ts <env-file> --set <폴더> --labels <labels.json> --out <answers.json>`(규칙만 바꿨으면
  `--facts <answers.json> --labels <labels.json>`로 호출 없이 다시 채점). 사진과 라벨은 저장소 밖에 둔다. 2026-11-19, 직접 라벨한 63장
  (제품 14 · 인물 8 · 로고 8 · 스타일 12 · 장소 8 · 기타 6 · 애매 7, 그중 분명한 것 35): 같은 코드 두 번 실행에서 **틀린 저장 0건 / 0건**,
  분명한 사진의 역할 저장 31/35(88.6 %) · 29/35(82.9 %, 이 회차는 4건이 15초 시간 초과 — 답한 31건 중 29건). 놓친 것: 극적인 빛의
  얼굴 클로즈업, 픽셀 버튼 모양 로고, 색광의 3D 엠블럼, 문에 걸린 가방(`product`/`place`).

## 7. 리뷰 공간 (슬라이스 D)

- `/brand/studio/review`: 왼쪽 목록(리뷰 항목: 제목·상태·댓글 수), 오른쪽 플레이어 + 타임라인 핀 + 댓글.
- 항목 만들기: 스튜디오 결과·에셋의 더보기 "리뷰에 올리기"(D가 내보낸 함수를 B1이 메뉴에 연결) 또는 리뷰 화면에서 고르기.
  야기 팀이 납품 시안을 올리는 것도 같은 표(관리자 화면).
- 댓글: 본문 + 시각(ms, 없으면 전체 댓글) + 화면 위치(x, y 0..1, 선택) + 답글 + 해결 표시.
  작성자 역할 `brand` | `studio`. 영상은 핀을 누르면 그 시각으로 이동, 이미지도 위치 핀.
- 상태: `open` → `changes_requested` | `approved`.
- 표: `brand_studio_reviews`, `brand_studio_review_comments`
  (`0080_core_brand_studio_review.sql` + `0155_glue_brand_studio_review.sql`).

  보인다. 휴대폰(640px 이하)은 위쪽 막대의 44px 지구본, 메뉴는 버튼 아래로 연다. 레일이 아닌 모드(샌드박스 조직의
  사이드바, 상단 막대 모드)와 관리자 화면의 언어 전환은 바꾸지 않았다.

## 13. 여러 모델로 한 번에 (2026-11-19)

대표 원문: "이미지 모델을 2개 이상을 동시 선택해서 만드는 것도 가능하게 되었으면 좋겠어. 동일한 레퍼런스들 넣었을때 > 그럼 각
프롬프트별 로직이 따로 들어가서 이미지가 2장이 나오게 되는거지."

같은 문장·참조·설정을 이미지 모델 2~3개에 동시에 보내고, 모델마다 자기 Prompt Architect 프로필로 설계된 결과가 따로 나온다.
부분 수정(Seedream 5.5 고정)과 영상 화면은 그대로다. 순수 규칙은 `components/brand-studio/group-model.ts` 한 파일에 있다.

- **모델 목록**(`gallery/model-menu.tsx`): 이미지 화면에서만 줄마다 체크가 붙는다. 줄을 누르면 예전과 똑같이 그 모델 하나를 고르고
  닫힌다. 왼쪽 체크(키보드는 스페이스)는 함께 고를 모델을 더하거나 빼고, 목록은 열린 채다. 셋을 고르면 나머지 체크는 닫히고 목록
  아래 "최대 3개까지 고를 수 있어요." 한 줄. 마지막 하나는 뺄 수 없다. 참조가 그 모델이 받는 수보다 많으면 그 줄 체크가 닫히고
  힌트 자리에 이유가 나온다(참조를 몰래 빼지 않는다; 지금 목록의 모델은 모두 10개 이상을 받아 실제로는 걸리지 않는다). 모델별
  인물·사물 장수(Nano Banana 프로필 문서)는 단일 실행처럼 프롬프트 안내로만 쓰고 막지 않는다.
- **칩**: 하나면 이름 그대로, 여럿이면 첫 모델 이름 + 조용한 "+N". 접근성 이름은 고른 모델을 모두 읽는다.
- **공통 설정**: 비율·해상도는 고른 모델이 모두 가진 값만 보인다. 모델을 더해 지금 값이 빠지면 가장 가까운 값(비율은 모양,
  해상도는 크기)으로 옮기고 입력창 아래 한 줄: "고른 모델이 모두 지원하도록 바꿨어요. 비율 4:5 → 3:4, 해상도 4K → 2K".
  품질은 GPT Image에만 있으므로 칩은 "GPT · 품질 보통", 목록 위에 "이 설정은 GPT Image 2.6 Flare에만 적용돼요.". 장수는 모델당이다
  ("모델당 N장").
- **크레딧**: 모델마다 단일 실행과 같은 계산(`usage-rate.ts` `imageRunKrw`)으로 견적하고, 버튼은 합계, 버튼 아래 한 줄에 모델별
  크레딧. 서버는 모델별 작업에 같은 값을 예약하고 허용량은 합계로 미리 본다(보인 값 = 예약 = 차감, PR #255 규칙 그대로).
- **Prompt Architect**: 스위치를 켠 채 바로 만들면 서버가 작업마다 자기 모델의 프로필로 설계한다(`work.enhancer.profile`,
  `profileVersion`이 모델별로 남는다). "지금 설계하기"를 누르면 모델마다 병렬로 한 번씩 설계하고(60초가 넘으면 그 탭은 실패로),
  입력창 위에 모델 이름 탭이 생긴다(밑줄 하나; 설계 중·설계 전·실패는 작은 점). 탭마다 고칠 수 있고 참조 표시는 #266의 같은
  글자 층(`PromptHighlight`)이 그린다. 실패한 탭은 단일 흐름과 같은 문장 + "다시 설계하기". 설계 뒤 모델을 더하면 그 탭은
  "아직 설계 전이에요." + "이 모델만 설계하기", 뺀 모델의 탭은 사라진다. "원래 문장으로"는 탭을 모두 거둔다. 보낼 때 탭 문장이
  입력한 문장과 다르면 그 모델만 `reviewedPrompt` + `enhance: false`, 나머지는 스위치를 따른다. 스위치를 끄면 모든 모델에 입력한
  문장 그대로. 하나만 남기면 그 탭이 입력창이 되고 "원래 문장으로"가 남는다.
- **서버 `job.create_group`**(`lib/brand-studio/job-group.ts`, 계약 `ImageJobGroupSchema`): 한 트랜잭션에서 자리 → 조직 잠금 →
  멱등(작업마다 키 `{그룹 키}-{모델}`; 같은 요청은 같은 N개를 돌려준다) → 모델이 아직 제공되는지(아니면 `model_unavailable`,
  409) → 작업마다 단일 실행과 같은 `planJob` → 진행 중 6개 한도에 N개가 다 들어가는지(`too_many_running`) → 합계 허용량 → N개
  삽입. 하나라도 걸리면 아무것도 생기지 않는다. 묶음은 `params.group = { id, models }`(jsonb, 마이그레이션 없음)이고 화면은
  `StudioJobView.group`으로 받는다. 이후 실행·정산·실패·환불은 작업마다 따로다(한 모델 실패가 다른 모델에 닿지 않는다).
  샌드박스 조직은 다른 작업과 같은 문에서 404, 열람자는 `forbidden`.
- **갤러리·뷰어**: 같은 요청의 결과는 고른 순서대로 붙어 있고(`orderGroups`), 칸마다 작은 모델 이름(올리면 기존 정보 알약이
  대신한다; 실패 칸은 이름이 사유 위에). 그 묶음의 칸 하나에 마우스나 펜을 올리거나 키보드 초점이 가면 묶음의 모든 칸에 같은 조용한
  잉크 테두리가 생긴다(포인트 색 아님, 줄이 바뀌어도 묶음이 읽히게; 레이아웃 변화 없음, 혼자 만든 칸에는 없음, 터치는 초점이 주는 것만).
  뷰어 오른쪽 맨 위 "같이 만든 결과" 알약 줄: 지금 결과는 채워지고, ←/→로 옮기며, 실패한 모델도 이유 한 줄과 함께 남는다.
- **모델 비교**(`gallery/model-compare.tsx`): 무대에 그 요청의 모든 모델 그림(2~3장)을 같은 높이로 나란히 놓는다. 그림마다 자기 비율
  그대로(파일이 열리면 실제 비율로) 폭을 받고, 아래에 모델 이름과 그 그림의 크레딧. 실패한 모델은 자리를 지키는 조용한 칸(이유 한 줄,
  이름은 아래). 그림을 누르면 비교를 끝내고 그 결과 하나를 연다. ←/→는 그대로, Esc는 비교를 먼저 끝낸다. 휴대폰은 화면 폭에 한 장씩
  옆으로 넘기고(scroll-snap) 이름과 "1 / 3"이 그림 밑에 붙어 함께 움직인다. 같은 요청이라도 모델마다 구도가 달라서(얼굴·손·병의
  자리), 선으로 반씩 가르는 전/후 슬라이더는 쓰지 않는다. 그 슬라이더는 같은 그림의 부분 수정에만 남는다.
  비교하는 동안 그림이 뷰어 본문 전체를 쓴다: 오른쪽(휴대폰은 아래) 동작 칸은 숨고(마운트는 유지), 모델 알약과 "모델 비교" 토글이
  그림 위 한 줄로 올라간다(휴대폰은 알약이 옆으로 흐르며 끝이 흐려지고, 토글은 아이콘만·이름은 접근성 이름·44px). 그림 크기는 무대 상자를
  재서 정한다(`compareSizes`): 나란히는 한 높이로 폭과 높이가 허락하는 만큼, 휴대폰은 한 장이 폭과 (이름·위치 줄을 뺀) 높이가 허락하는
  만큼. 1440×900에서 3:4 셋 532px, 1:1 셋 399px, 16:9 둘 341px(셋 다 폭이 한계). 비교를 끝내면 동작 칸이 그대로 돌아온다(열어 둔
  "보낸 문장", 스크롤 위치, 토글 초점).
- **칸 아래 줄**(`.bs-tile-foot`, 칸 자기 폭의 container query — 칸 자체에 두면 칸의 고정 위치 메뉴가 갇혀서 따로 둔 0높이 상자):

  터치 44px), 180px 미만이면 크레딧만, 140px 미만이면 정보 알약을 감춘다.
