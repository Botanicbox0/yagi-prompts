# TWINGS 문구 진단 — 2026-09-19

이번 PR은 **문구 목록·진단·수정 후보**를 만드는 선행 작업이다. 화면 사전, 서비스 동작, 가격, 약관, 메일 발송 설정은 변경하지 않는다. 기준 소스는 `41d69c9`이며, 사전의 정확한 SHA-256은 [summary.json](summary.json)에 기록한다.

브랜드 공간의 방향은 **스튜디오가 운영하고 브랜드가 진행 상황과 콘텐츠를 확인·승인하는 구조**로 정했다. 이 방향은 이후 설계의 기준이다. 아직 없는 브랜드 승인 화면이나 자동 리포트를 현재 기능처럼 광고하지 않는다.

전체 문구가 수집됐다는 말은 전체 문장의 품질 검토가 끝났다는 뜻이 아니다. `review_basis`를 기준으로 구분한다.

직접 검토는 Codex가 원문과 코드 문맥을 대조한 AI 편집 검토를 뜻한다. `context-reviewed-candidate`는 사람의 검수나 대표의 최종 승인을 의미하지 않는다.

## 재생성과 검증

```powershell
npx tsx scripts/dump-wording.ts
npx tsx scripts/dump-wording.ts --check
npx vitest run tests/i18n/wording-audit.test.ts
```

`reviews.json`이 수동 검토의 원본이다. `source_ko`·`source_en`은 검토 당시 원문이다. 현재 사전과 달라지면 생성이 실패한다. 바뀐 문장을 다시 검토한 뒤 원문 스냅샷과 점수·후보·근거를 함께 갱신한다. `{days}` 같은 치환값을 없애거나 바꿔도 실패한다.

생성 결과는 결정적이다. `--check`는 아래 생성 파일이 현재 입력과 정확히 같은지 확인하며 파일을 쓰지 않는다. 서비스 모듈을 실행하거나 환경변수 파일·DB·네트워크를 읽지 않는다.

| 파일 | 용도 |
|---|---|
| `inventory.csv` | 현재 KO/EN, 사전 키, 소스 위치, 후보 경로, 점수, 수정안, 근거 |
| `routes.csv` | 페이지·API 진입점 63개의 보수적인 후보 키 목록 |
| `hardcoded-candidates.csv` | 사전 밖 JSX·한글 리터럴 후보 49건. 내부 오류·메일 등이 섞이므로 일괄 치환 금지 |
| `proposals.md` | 현재와 달라지는 수정 후보의 읽기용 비교표 |
| `summary.json` | 입력 해시, 개수, 분석 한계 |

CSV는 UTF-8 BOM과 인용부호를 사용하며 쉼표·줄바꿈을 보존한다. 스프레드시트 수식으로 해석될 수 있는 셀에는 작은따옴표를 앞에 붙인다. 원문을 정확히 재사용할 때는 사전 또는 `reviews.json`을 사용한다.

## 점수 읽는 법

각 언어의 **현재 문장**을 명확성·구체성·자연스러움 3축, 1~5점으로 평가한다. 수정 후보의 완성도 점수가 아니다. 라벨은 짧고 해당 대상을 정확히 가리키면 충분하다. 숫자가 없다는 이유로 낮게 평가하지 않는다.

| 점수 | 직접 검토한 문구에서의 의미 |
|---|---|
| 1 | 뜻·행동을 잘못 이해하거나 실제 상태와 충돌할 가능성이 큼 |
| 2 | 문맥 보충 또는 재작성이 필요함 |
| 3 | 뜻은 전달되지만 더 명확하거나 자연스럽게 다듬을 수 있음 |
| 4 | 현재 문맥에 적합한 유지 후보 |
| 5 | 해당 문맥에서 뚜렷하고 간결하며 조건도 충분함 |

직접 검토 전에는 **3점을 ‘미평가’ 중립값**으로 쓴다. 규칙이 긴 문장, 내부 용어, 지급 시점 약속 등을 찾으면 관련 축을 2점으로 낮춰 검토 대상을 표시한다. 규칙에는 오탐이 있다. `review-priority` 202건은 품질 결함이 확정된 202건이 아니다. `no-low-score`도 승인 의미가 아니다.

| decision | 처리 |
|---|---|
| `candidate` | 코드 문맥을 확인한 적용 후보. 이번 PR에서는 미적용 |
| `owner-decision` | 운영 조건·권리·사례·발송 문안 등 대표 결정이 필요한 후보 |
| `keep` | 현 문장 유지 후보. 법률·정책 승인이나 실제 노출 확인을 뜻하지 않음 |
| `retire-if-unused` | 런타임·검색·메일·리다이렉트까지 확인한 뒤에만 삭제 판단 |
| `review-pending` | 직접 검토 전 |

메일·SNS 문구는 모든 decision 값과 관계없이 AGENTS.md §5의 발송 문안 승인 대상이다.

## 노출 위치의 정확도와 한계

TypeScript 심볼로 `Dictionary`의 별칭·props·상태별 접근을 따라간다. `static`은 직접 참조, `dynamic-set`은 동적 선택 집합, `object-transfer`는 사전 일부를 다른 타입의 컴포넌트에 전달한 지점이다. 마지막 두 종류는 모든 하위 문장이 실제 보인다는 증거가 아니다.

`candidate_routes`는 import와 상위 layout/error/loading/not-found의 연결이다. 공용 서비스와 메일 모듈 때문에 경로가 넓게 잡힐 수 있다. 로그인, 플래그, 상태 분기, 리다이렉트, 실제 호출 여부는 실행하지 않는다. 동적 import, 타입 정보가 사라지는 전달, 런타임 키 생성은 누락될 수 있다. **정적 참조가 없는 221개 키를 미사용으로 단정하거나 삭제하지 않는다.**

법률 본문, DB의 템플릿·캠페인 제목, 외부 결제 위젯, `public`의 HTML, 일부 메타데이터와 영어 코드 문자열은 이 사전 진단의 전체 수집 대상이 아니다. 사전 밖 후보 목록도 화면 문자열의 완전한 목록은 아니다. 후속 적용 작업에서는 해당 화면의 실제 상태와 함께 확인한다.

## 다음 적용 순서

1. 캠페인 랜딩·의뢰·참여 동선에서 일반 문체 후보를 선택하고 사전에 반영한다. 세 줄 히어로는 한 묶음으로 적용한다.
2. 정산 기준·권리·사례·응답 기한은 [결정 목록](FINDINGS.md#대표-결정-후-진행할-항목)을 먼저 확정한다. 코드 변경이 필요한 건은 별도 작업으로 다룬다.
3. 템플릿 → 결제 → 생성 → 결과 → 계정 순서로 남은 문구를 직접 검토한다. 기존 결제 안내와 법률 본문의 일치를 유지한다.
4. 이후 브랜드 확인·승인 공간과 크리에이터 모바일 동선에 같은 용어·상태명을 적용한다.

각 적용 작업은 별도 범위와 완료 기준으로 진행한다. 이번 진단만으로 브랜드 공간·앱 전환·약관 변경을 승인한 것으로 보지 않는다.
