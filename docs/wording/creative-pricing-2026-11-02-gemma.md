# 크리에이티브 가격·수익 문구 — 로컬 Gemma 추천 (2026-11-02)

대표 지시(2026-11-02): "크레딧을 올리면 사용자 소모가 늘고, 한 번 만들 때 내 몫은 이만큼"은 너무 구리다. 새로 만드는 화면 문구는 로컬 Gemma에 전체 맥락을 주고 추천받아 설계한다.

- 모델: `yagi-crm-gemma4:31b-q8_0`, `http://127.0.0.1:11434`(gpu-arbiter 경유), temperature 0.5~0.6, JSON 출력.
- 프롬프트: 서비스 정의, 가격·정산 사실(80%, 7일, 기본값 아래 불가, 회사 계정), 호칭("AI 크리에이티브", 일반 사용자 호칭 없음), 금지 패턴(소모·내 몫·배분·귀속, 기계적 병렬, 명령+약속, 대조 공식)을 모두 넣었다.
- 받은 뒤 사실과 어긋난 추천은 이유를 적어 다시 물었다(2차). 3차는 스튜디오 보조 문구와 관리자 문구다.

## 채택한 문구 (`messages/ko.ts` `makerRecipe`)

| 키 | 문구 | 출처 |
| --- | --- | --- |
| `priceLabel` | 판매 가격 | 1차 A11-A1 대안 (best "사용자 결제 금액"은 "사용자" 호칭이라 대안을 씀) |
| `priceBaseHint` | 모델과 분량에 맞춰 기본값이 설정됐어요. | 1차 A2 |
| `priceTooLow` | {amount}보다 낮게 설정할 수 없어요. | 1차 A11-A3 |
| `earningOne` | 한 번 만들 때 {amount} 예상 | 1차 A4 |
| `earningMany` | {n}명이 만들면 {amount}이에요. | 1차 A5 |
| `earningRaise` | 가격을 높이면 만드는 분이 내는 금액도 늘고, 수익도 함께 올라가요. | 2차 R1을 원화로 (1차 A6·A11-A6은 만드는 분 쪽 사실이 빠져 다시 물음) |
| `earningRule` | 세금, 수수료, 제작 원가를 뺀 이익의 80%를 드려요. | 1차 A7 |
| `earningEstimate` | 원가와 환율에 따라 실제 정산액은 조금 달라질 수 있어요. | 1차 A8 |
| `earningSettle` | 결과물 전달 후 7일이 지난 건부터 정산 대상이에요. 환불된 건은 제외돼요. | 2차 R4 (1차 "7일 후 정산돼요"는 입금 약속처럼 읽혀 다시 물음) |
| `earningCompany` | 회사 계정의 수익은 정산 대상이 아니에요. | 1차 A10 |

플랜 카드와 템플릿 오류 점검 문구(1차 B·C, 2차 R2·R3)는 그 화면을 만들 때 쓴다. 2차에서 고친 것: 49,000원 소개 "제한 없이 마음껏 창작하고 싶을 때"(월 한도가 있어 거짓) → "가장 많은 크레딧으로 넉넉하게 만들고 싶을 때", 브랜드·유명인 경고 "검수에서 반려"(스튜디오 검수는 없음) → "AI 정책에 따라 결과가 나오지 않을 수 있어요".
