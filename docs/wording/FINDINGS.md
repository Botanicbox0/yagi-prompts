# 핵심 진단과 문장 기준

좋은 문구의 기준은 ‘유니콘처럼 보이는 문장’이 아니라 **누가 무엇을 할 수 있고, 다음에 어떤 상태가 되는지 한 번에 이해하는 것**이다. 한국어와 영어의 의미·조건은 맞추되 어순은 각각 자연스럽게 쓴다.

## 먼저 해결할 불일치

| 우선순위 | 발견 | 제안 및 근거 |
|---|---|---|
| 높음 | ‘게시 후 7일’과 실제 정산 대기 시작점이 다름 | `lib/admin/campaign-operations.ts`의 verify는 `verifiedAt`을 기준으로 `holdUntil`을 계산한다. `campaigns.payoutHold`는 ‘검수 완료 후 {days}일이 지나면 정산 대상’ 후보. 지급 완료와 구분한다. |
| 높음 | 조회수 측정 기준이 문서·화면·입력 허용 상태에서 다르게 읽힘 | `docs/CAMPAIGNS.md` §4의 `metrics_at`은 `verified+hold`. `lib/campaigns/service.ts`의 조회수 보고는 posted/verified 상태에서 허용되며 측정 시점을 별도 고정하지 않는다. 문구만 고쳐 완료 처리하지 않는다. |
| 높음 | ‘접수 성공’에서 확인 메일 발송을 이미 완료한 것처럼 말함 | 브랜드 문의는 먼저 저장하고 `app/api/brands/inquiries/route.ts`의 `after()`에서 메일을 보낸다. 접수 완료만 확정해 안내하고, 1영업일 응답 약속은 운영 확인 대상으로 둔다. |
| 중간 | ‘내일 다시’가 요청 제한 해제 시점을 잘못 암시 | 브랜드 문의·캠페인 지원 제한은 최근 시간 구간을 센다. 자정 초기화가 아니다. ‘시간을 두고 다시 시도’로 변경 후보. |
| 중간 | ‘만들기’ 버튼이 캠페인 전용 생성으로 보임 | 현재 상세의 `makeItCta` 링크는 `/[locale]/studio`, 이후 템플릿 목록으로 이동한다. 현재 동작에는 ‘템플릿 살펴보기’가 맞는다. 전용 생성 연결은 별도 기능이다. |
| 중간 | ‘선정 인원’과 ‘지원 가능 횟수’가 섞일 수 있음 | `slotsLabel`은 남은 선정 가능 인원으로 설명한다. 남은 지원서 개수로 표현하지 않는다. |
| 중간 | 등록·검수·본인 확인을 모두 ‘인증’으로 표현하기 쉬움 | 콘텐츠 검수, 제공사 사진 검수, 카메라 본인 확인을 분리한다. `verified`는 콘텐츠 검수 완료다. |
| 중간 | 영상 전용 단어가 이미지 결과에도 쓰임 | 공통 결과 영역은 ‘결과물 / Result’, 영상 전용 영역은 ‘영상 / Video’를 사용한다. |

소스의 정확한 현재 위치는 [inventory.csv](inventory.csv)의 `source_locations`에서 키별로 확인한다. 경로 연결은 실행 노출 증명이 아니다.

## 상태와 용어

| 내부 상태·개념 | 사용자에게 전달할 의미 | 피할 오해 |
|---|---|---|
| applied | 지원 완료 / Application submitted | 선정이 끝났다는 뜻이 아님 |
| selected | 선정됨 / Selected | 콘텐츠 검수가 끝난 상태가 아님 |
| posted | 게시물 제출 / Post submitted | 제출만으로 정산 대상 확정이 아님 |
| rejected | 수정 요청 / Changes requested | 자동으로 캠페인 탈락 또는 재게시 요구가 아님 |
| verified | 검수 완료 · 정산 대기 / Approved · awaiting payment | 얼굴 인증이나 입금 완료가 아님 |
| holdUntil 경과 | 정산 대상 / Eligible for payment | 이 시각에 자동 입금한다는 약속이 아님 |
| paid | 지급 완료 / Paid | 관리자 지급 처리 근거와 일치해야 함 |
| brand | 브랜드 / Brand | 캠페인 전체를 직접 운영하는 계정이라는 뜻은 아님 |
| studio | TWINGS 스튜디오 / TWINGS studio | 사용자가 이해할 운영 주체. 기술 운영 문맥 외 ‘관리자’ 남발 방지 |
| format / template | 브랜드 제안은 영상 포맷, 사용자가 선택·생성하는 항목은 템플릿 | 데이터·권한 모델은 용어 변경으로 바꾸지 않음 |
| creator fee | 원고료 | 매출·수익·입금액을 같은 의미로 사용하지 않음 |

짧은 버튼은 ‘캠페인 의뢰하기 / Enquire about a campaign’, ‘참여할 캠페인 보기 / Explore campaigns’처럼 실제 도착점에 맞춘다. ‘바로’, ‘자동’, ‘보장’은 동작과 조건을 확인한 경우에만 쓴다. 빈 상태에는 현재 상황과 가능한 다음 행동을 함께 둔다.

## 대표 결정 후 진행할 항목

| 결정 | 후보 | 이유·후속 범위 |
|---|---|---|
| 정산 대기 기준과 실제 지급 일정 | 검수 완료 + 캠페인별 대기기간을 정산 대상 기준으로 명시. 실제 입금 기한은 별도 명시 | 현재 `payoutReleasable` 조건과 일치. 입금 기한은 코드만으로 확정할 수 없음 |
| 조회수 스냅샷 시점 | 검수 완료 + 대기기간 종료 시점 | 기존 도메인 문서와 정합. 시점 저장·입력 제한·증빙 UI는 별도 기능 검토 필요 |
| 문의 응답 기한 | 1영업일을 유지할지, 기한 약속을 뺄지 | 사람의 응답 SLA이며 메일 API 성공과 다른 문제 |
| 브랜드의 콘텐츠 재사용 권리 | 캠페인 계약에서 별도 합의 | 얼굴 등록 동의와 브랜드의 광고·2차 활용 동의를 하나로 취급하면 안 됨. 법률 본문 변경 없음 |
| 고객 사례의 300건 의미 | ‘같은 포맷으로 이어진 콘텐츠’ 후보 | 기존 승인 수치 9편·200만+·300건+ 유지. 새 표제가 기존 집계 범위를 정확히 뜻하는지 확인 |
| 메일 제목·본문 | 비교표의 발송 문구 후보 | AGENTS.md §5에 따라 발송 문안은 대표 확정 필요. 이번 작업에서는 발송하지 않음 |

구독·가격·결제수단·라이브 키·공개 플래그는 이번 결정 대상에 추가하지 않는다. 기존 보류 상태를 유지한다. 약관·환불·개인정보 본문은 이 문서의 문체 기준으로 자동 수정하지 않는다.

## 참고 제품에서 가져온 기준

확인일: 2026-09-19. 아래는 문장을 복제하기 위한 자료가 아니라 진단 기준의 출처다.

- [토스 UX 라이팅 원칙](https://toss.tech/article/21022): 사용자가 다음 행동을 이해하도록 쓰고 불필요한 표현을 줄인다. TWINGS에서는 접수·선정·검수·지급 상태를 정확히 말하는 데 적용했다.
- [Stripe 결제 상태 문서](https://docs.stripe.com/payments/payment-intents/verifying-status): 처리 중과 성공 상태를 구분한다. TWINGS에서도 접수와 메일 전송, 검수와 지급을 같은 완료 문장으로 묶지 않는다.
- [Sume](https://www.sume.com/): 무엇을 입력하고 무엇을 얻는지 짧게 제시하는 방식을 참고했다. 경쟁사의 제작 속도·자동화·모델 범위 약속을 TWINGS에 가져오지 않았다.
- [Linear 문서](https://linear.app/docs): 작업과 기능 이름을 기준으로 탐색시키는 구조를 참고했다. 구체적인 기능이 없는 추상적인 제품 구호를 메뉴 이름으로 쓰지 않는다.
- [Brandazine 브랜드 공간](https://workspace.brandazine.com), [크리에이터 앱 공개 소개](https://play.google.com/store/apps/details?id=kr.brandazine.app.cordova): 브랜드와 크리에이터의 역할을 분리하는 참고 자료. 브랜드 공간은 로그인한 웹 화면, 크리에이터 측은 스토어 소개·스크린샷을 확인했다. 설치 앱의 전체 흐름을 검증한 것은 아니다. 타 서비스의 비공개 계정·캠페인 데이터는 예시나 공개 문안에 사용하지 않는다.

## 후속 제품 설계의 경계

브랜드 공간의 첫 단계는 진행 단계·확인 요청·콘텐츠 승인/수정 요청·확정 리포트다. 스튜디오가 모집·선정·검수·정산을 운영한다는 책임 구조를 먼저 유지한다. 크리에이터 모바일 경험은 ‘지금 할 일’과 제출·수정·정산 상태를 우선한다. PWA나 네이티브 앱, 알림 채널, 승인 권한·이력 설계는 이후 별도 작업에서 확정한다. 여기의 화면 목록은 구현 완료 또는 범위 승인 주장이 아니다.
