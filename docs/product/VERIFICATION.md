## 시안 브라우저 검사

Chrome에서 `admin-prototype.html`을 로컬 HTTP로 열어 확인했다. 네이티브 앱이나 실기기 검사가 아니다.

확인한 흐름:

- 오늘 할 일 검색, 검색 결과 없음, 검색 조건 초기화, 상세 창 열기.
- 브랜드 수정 요청의 빈 사유 오류, 특정 버전 승인, 다음 버전에서 승인 초기화.
- 정산 대상·대기 중·지급 완료 탭, 정산 근거 상세. 실제 송금이나 지급 상태 변경 없음.
- 빈 상태·불러오는 중·오류·권한 없음과 기본 상태 전환. 서버 권한·네트워크 장애의 실제 재현이 아니라 표시 시연이다.
- SNS 조사 후 추가한 조건 편집기: 팔로워 범위 안/밖/자료 없음의 세 상태, 최소=최대 경계 포함, 잘못된 범위·음수·빈 목표·목표 0 거절, 플랫폼/목표별 수집 한계 안내, 시연 저장·재열기·Escape 복귀를 확인했다. 실제 API 판정이 아니다.

최종 재검증: 1440px 데스크톱과 390px 모바일에서 문서 가로 넘침이 없었다. 모바일 정산의 지급 상태·근거 보기 버튼을 가로 스크롤 없이 확인했다. 업무 상세를 Escape로 닫으면 원래 행으로 초점이 돌아왔다. v3 승인 뒤 v4를 추가하면 v4는 검토 대기로 바뀌고 v3 승인은 이전 이력에 남았다. 데스크톱에서는 모바일 전체 메뉴 버튼이 숨겨진다. 시각 자료는 PR 본문에 첨부한다.

SNS 조건 편집기 추가 후에도 같은 두 크기에서 화면을 확인했다. 390px에서 모달의 내용 너비와 표시 너비가 같아 가로 넘침이 없었고, 판정 버튼에서 세 결과로 초점·스크롤이 이동했다. 이번 변경 후 tsc→vitest(103/1,220)→build:local→start:local→sweep(484/484) 루프도 다시 통과했다.

공식 Instagram·TikTok·X 문서와 Featuring 페이지를 대조했고, 사용자 지정 Brandazine 필터 화면을 읽기 전용으로 살폈다. 실제 개인 행이나 수치를 시안에 복제하지 않았다. Meta API 사실·출처 검토는 별도 읽기 전용 검토에서도 필수 수정 사항이 없었다. API 토큰 발급이나 실계정 데이터 수집은 수행하지 않았다.

## 출시 판정의 한계

**설계 검토용. 운영 배포와 앱 출시에는 아직 준비되지 않았다.**

- 앱 범위 D01은 2026-09-20 답변으로 일반 사용자 생성 우선으로 확정했다. 생성 비용·브랜드 승인 의무·지급 정책 등 다른 미결정 항목은 설계 문서 §2에 남아 있다.
- 조직 격리·실제 버전 승인·영속 감사 이력·동시 선정·앱 API는 미구현이며, 이 PR에서 통과했다고 주장하지 않는다.
- Apple/Google 계정·서명·앱 프로젝트·설치 바이너리·실기기·TestFlight/Play 테스트 배포·스토어 심사를 수행하지 않았다.
- 시안은 가상 데이터만 사용한다. 실제 사용자·얼굴·브랜드 비공개 데이터·정산 금액·계좌·시크릿은 포함하지 않는다.
- 스크린리더 실사용, 전체 WCAG 감사, 성능·부하·침투 테스트는 하지 않았다.
- 시안에 없는 메뉴는 안내만 제공한다. 실제 브랜딩·미디어·모든 화면을 구현한 제품으로 취급하지 않는다.

다음 작업은 일반 사용자 생성 우선 답변에 맞춘 설계 문서 §10의 생성·계정 기반 개선이다. 캠페인 운영 신뢰성·SNS 연결은 별도 단계로 남긴다. 권한·상태·금액 경계를 보존하는 구현과 회귀 테스트를 각각의 PR로 진행한다.

## 셀피·브랜드 운영 후속 설계 검증 — 2026-09-20

기준 `d245b83` 위에서 공통 용어와 출시 설계를 갱신하고, `IDENTITY-AND-BRAND-WORKSPACE.md`, 원문 프롬프트 v1, `brand-workspace-prototype.html`을 추가했다. 무료 총횟수·정확한 2K 규격은 질문/설계 후보로 남겼다. 얼굴 생성 기능·조직 권한·SNS 수집·채팅 서비스 구현을 완료한 것이 아니다.

이번 변경에서 다시 실행한 순서: **tsc PASS → vitest 103파일/1,220테스트 PASS → build:local PASS → start:local Ready → sweep:anon SWEEP PASSED 484/484**. 런타임 회귀 검사이며 새 설계 기능의 구현 증거가 아니다. HTML JavaScript 구문과 `git diff --check`도 확인했다.

브랜드 시안은 Chrome에서 다음을 확인했다.

공식 OpenAI 문서와 기존 이미지 엔진을 대조해 Sunburst 모델 ID를 확인했다. 현재 계정의 API 권한·해상도 실응답·얼굴 동일성·비용은 미검증이며 유료 생성 호출을 하지 않았다. 원문 프롬프트는 보존했고 생성 결과를 검수 우회나 인증 증거로 취급하지 않는 경계를 기록했다.

## 글꼴·주소 운영 검증 — 2026-09-20

두 시안에 공통 CSS와 저장소의 Pretendard Variable subset을 연결했다. 영문·숫자는 로컬 Helvetica Neue를 우선한다. 현재 브라우저는 해당 로컬 글꼴을 사용할 수 없어 Arial로 대체되며, Helvetica Neue를 실제 사용했다고 주장하지 않는다. 유료 글꼴 파일을 복사하거나 배포하지 않았다.

추가한 `scripts/preview-product-design.mjs`로 HTML·CSS·폰트를 제공하고 CSS와 WOFF2의 HTTP 200 및 `font/woff2` 응답을 확인했다. 브라우저에서 Pretendard 로드와 공통 font-family를 확인했다. Chrome의 1440×1000·390×844에서 어드민/브랜드 시안을 직접 확인했으며 두 시안 모두 문서 가로 넘침이 없었다. 실제 휴대폰 검사는 아니다.

이번 변경 후 **tsc PASS → vitest 103파일/1,220테스트 PASS → build:local PASS → start:local Ready → sweep:anon SWEEP PASSED 484/484** 순서로 다시 확인했다. 기존 런타임 회귀 검사이며 시안의 서버 기능을 검증한 것은 아니다.

대표가 `twings.app`·`brands.twings.app`·`admin.twings.app`의 역할 분리를 승인했다. 현재 코드와 Vercel/Supabase 공식 문서를 대조한 결과, 하나의 저장소·Next 앱·Vercel 프로젝트·Supabase를 유지하는 구성이 현재 운영에 적합하다. 호스트 라우팅과 인증 복귀 경계는 별도 기능 PR에서 먼저 구현한다.

로그인된 Cloudflare DNS 화면에서 twings.app의 Full DNS 구성과 apex/www CNAME 두 개를 확인했다. 두 레코드는 DNS only이며 동일 Vercel 대상으로 연결된다. brands/admin 레코드는 없었다. DNS·Vercel·Supabase 설정을 변경하지 않았으며, 운영 도메인 연결은 라우팅 배포와 인증 검증 후 진행한다.
