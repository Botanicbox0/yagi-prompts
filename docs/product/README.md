# TWINGS 제품·어드민·앱 설계

이 폴더는 **설계 후보**다. 현재 서비스를 완성하거나 스토어에 앱을 출시했다는 보고가 아니다.

- [제품 완성과 앱 출시 설계안](RELEASE-DESIGN.md): 역할별 흐름, 어드민 정보 구조, 권한·버전 계약, 출시 게이트, 미결정 사항, 한 작업씩 실행할 순서.
- [클릭 가능한 어드민 시안](admin-prototype.html): 파일을 브라우저로 열어 오늘 할 일·캠페인·정산을 확인한다. 모든 데이터와 처리는 예시이며 새로고침하면 초기화된다. 백엔드·결제·메일 연결 없음.
- [공통 용어](../../CONTEXT.md): 브랜드 승인, 게시물 검수, 정산 대상, 지급 완료의 구분.
- [검증 기록](VERIFICATION.md): 실제 수행한 검사와 미검증 항목.
- [SNS 연결과 캠페인 지표](SOCIAL-CONNECTIONS.md): Instagram·TikTok·X의 공식 API 가능 범위, 지원 조건과 성과 목표 설계.
- [내 얼굴과 브랜드 캠페인 운영](IDENTITY-AND-BRAND-WORKSPACE.md): 셀피·무료 얼굴 생성, 브랜드 총예산과 지급 정보 분리, 두 제작 방식, 레퍼런스·대화·리포트·도메인·Slack 설계.
- [브랜드 공간 시안](brand-workspace-prototype.html): 의뢰·콘텐츠 승인·대화·리포트의 독립 HTML. 예시 데이터만 사용하며 실제 접수·발송·업로드가 없다.
- [기준 얼굴 프롬프트 v1](prompts/identity-portrait-v1.md): 대표가 제공한 영문 원문 보존.

확정 방향은 **일반 사용자 생성 앱부터 출시**, 이후 같은 사용자가 조건을 충족하면 캠페인에 참여하는 구조다. 캠페인은 **스튜디오 운영 + 브랜드 확인·승인**을 유지한다. 구독·라이브 결제·공개 플래그·가격·법무 문구 등 보류된 결정은 그대로 유지한다.

시안의 한글 문구와 예시 화면은 제품 사전에 반영되지 않는다. 실제 기능 PR에서는 KO/EN 사전, 서버 권한, 영속 상태, 동시성·실패 테스트와 함께 구현한다.
