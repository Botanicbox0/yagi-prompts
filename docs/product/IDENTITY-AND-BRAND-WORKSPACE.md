# 내 얼굴과 브랜드 캠페인 운영 설계

2026-09-20 · **설계안 / 실제 생성·브랜드 서비스·DNS·Slack 미연결**

일반 사용자는 자신의 얼굴로 영상을 만들고, 캠페인에 참여할 때 SNS를 연결한다. 브랜드는 총예산으로 캠페인을 의뢰하고 결과를 확인한다. 스튜디오는 제작·크리에이터 모집·지급·성과 수집을 책임진다. [출시 설계](RELEASE-DESIGN.md), [공식 SNS API 조사](SOCIAL-CONNECTIONS.md)를 구체화한다.

## 1. 확정 방향과 선택이 필요한 부분

대표가 요청한 방향은 셀피 기반 기준 얼굴, 가입 시 무료 변경 기회, 브랜드 총예산 의뢰, 개별 크리에이터 지급액 비공개, 두 가지 제작 방식, 게시물 링크 제출과 종료 리포트다. 스튜디오 운영 + 브랜드 확인·승인과 일반 사용자 생성 우선은 유지한다.

| 구분 | 설계안 | 상태 |
|---|---|---|
| 무료 얼굴 생성 | 첫 생성 포함 총 3회, 기술적 실패는 미차감 | 총 3회인지 첫 생성+교체 3회인지 대표 답변 대기 |
| 얼굴 모델 | `gpt-image-2.5-sunburst`; 버전 고정 후보 `gpt-image-2.5-sunburst-2026-09-08` | 공식 모델·저장소 등록 확인, 현재 계정 접근·실생성 미검증 |
| 출력 크기 | 2:3, 1344×2016 후보: 긴 변 약 2K | ‘2K’ 기준 합의 필요. 타 서비스의 2K 프리셋과 동일하다고 주장하지 않음 |
| 브랜드 주소 | `brands.twings.app` | 권장 후보. `admin.twings.app`은 스튜디오 내부용 권장 |
| 대화 | 캠페인별 브랜드–스튜디오 대화 + 별도 내부 메모 | 제안. 결재·승인은 구조화된 별도 동작 |
| Slack | 내부 비공개 `twings-campaigns` 채널에 접수·지연 알림 | 제안. 워크스페이스·채널·앱 권한·최종 발송 문구 미확정 |

이번 PR은 운영 코드·SQL·환경변수·법무 본문을 바꾸지 않는다. 새로운 가입 혜택의 제공 조건·보관 정책·캠페인 권리 범위는 구현 PR 전에 확정한다. 소비자 구독은 계속 보류한다.

## 2. 내 얼굴 만들기

### 사용자 흐름

회원가입 직후 선택 안내를 제공하고, 템플릿 첫 생성 시 아직 기준 얼굴이 없으면 이어서 만든다. 가입 자체를 얼굴 업로드로 막지 않는다. 일반 생성에는 SNS 연결을 요구하지 않는다.

1. **정면 사진 올리기**: 눈높이, 얼굴 한 명, 머리 전체와 양쪽 어깨, 밝고 균일한 빛, 필터·과도한 보정 없는 본인 사진을 안내한다. 원본을 과도하게 잘라 얼굴 비율을 바꾸지 않는다. 파일·디코딩·얼굴 수·심한 가림 등 입력 검사는 생성 요청 전에 수행한다.
2. **기준 사진 만들기**: 제공된 [프롬프트 v1](prompts/identity-portrait-v1.md)과 원본 사진 한 장만 사용한다. 진행 중에는 현재 얼굴을 유지하며 화면을 떠나도 작업이 이어진다.
3. **원본과 결과 확인**: 두 사진을 함께 보여주고 ‘눈·코·입과 얼굴형이 나와 같은지 확인해 주세요’라고 안내한다. `이 얼굴로 사용할게요` / `다른 사진으로 다시 만들기`를 제공한다. 생성 결과를 인증 성공처럼 표시하지 않는다.
4. **선택한 얼굴로 생성**: 계정에 활성 기준 사진 한 장을 지정한다. 다음 영상부터 재사용하고 템플릿 화면에서 작게 확인·변경할 수 있다. 진행 중 작업은 시작할 때의 얼굴 버전을 유지한다.

성공 결과가 마음에 들지 않으면 새 사진을 권한다. 무조건 더 좋은 결과나 얼굴 일치율을 보장하지 않는다. 얼굴 교체는 **같은 사람의 기준 사진 교체**다. 다른 사람을 계정에 추가하는 기능이 아니다.

### 무료 횟수 계약 후보

총횟수 답변 전에는 고객에게 ‘3회’ 또는 ‘4회’를 확정 공지하지 않는다. 아래 N은 결정할 총횟수다.

- 가입 혜택 N회는 계정 생애 기준이며 월별로 복원하지 않는다. 내부 카운터는 결제 재화나 소비자 영상 결제와 연결하지 않는다.
- 서버가 요청 ID별 1회를 원자적으로 예약한다. 같은 요청 재전송·동시 탭으로 추가 차감·N회 초과 생성이 생기지 않아야 한다.
- 사용자에게 확인 가능한 정상 후보가 영속 저장된 뒤 1회 사용 처리한다. ‘마음에 들지 않음’으로 재생성하면 새 1회다. 시스템 오류·빈 결과·손상 파일·입출력 검수 실패는 사용 처리하지 않고 예약을 한 번만 해제한다.
- 타임아웃처럼 결과가 불명확하면 즉시 새 요청을 보내지 않는다. 해당 시도를 확인 중으로 유지하고 정합성을 복구한다. 제공사가 조회를 지원하지 않으면 운영 검토·명시적 복구 정책으로 처리한다.
- 횟수가 끝나도 선택한 얼굴은 계속 사용한다. 추가 유료 교체·새 계정 가입 유도·무제한 재생성은 넣지 않는다. 잘못 생성된 결과는 기존 문의·실패 검토 정책과 연결할 후보이며 자동 추가 제공을 약속하지 않는다.
- 실패 미차감이 무제한 외부 비용을 만들지 않도록 계정별 동시 작업 1개, 속도 제한, 외부 오류 차단·지출 경보를 둔다. 정확한 운영 한도는 실제 비용 측정 후 정한다.

### 상태·저장 경계

`요청 → 횟수 예약 → 생성 → 결과 검사 → 후보 저장 → 사용 확정 → 사용자 선택`을 별도로 기록한다. 활성 얼굴 변경은 본인·현재 버전을 검사한 원자적 교체다. 실패·취소·늦은 완료가 기존 얼굴을 자동 덮어쓰지 않는다. 결과 저장 후 차감 전 장애, 차감 후 응답 전 장애도 재시도로 한 번만 완료한다.

테이블 후보는 `identity_portrait_attempts`(상태·요청 ID·원본 참조·프롬프트/모델/출력 규격·사용량·예약/확정), `identity_portraits`(불변 버전·검수 상태·파일 참조), 계정의 활성 버전과 생애 사용 수다. SQL 번호는 예약하지 않는다. 사진 바이트·얼굴 특징·토큰은 로그나 감사 이벤트에 복사하지 않는다. 원본·후보·선택 사진의 보관·삭제 기간은 새 장기 보관 목적에 맞춰 별도로 결정한다.

**기존 본인 얼굴·제공사 검수 경로를 유지한다.** `lib/identity/service.ts`의 가상 자산 그룹/라이브니스 흐름, `lib/renders/service.ts`의 자산 등록·대조는 그대로 필요하다. 생성한 초상화를 인증 증거로 사용하거나 제공사의 실인물 제약을 피하는 방법으로 설명하지 않는다. 사진 교체로 사람별 그룹 제한이나 검수 보류를 초기화하지 않는다. 원본→기준 사진→실제 사용 자산의 소유자·계보를 기록하며 공급사가 허용하지 않으면 실패를 표시하고 멈춘다.

### 모델과 품질 검증

현재 `lib/images/engines.ts`에는 Sunburst가 있지만 이미지 비율에 2:3이 없고 `lib/images/openai.ts` 출력도 기존 크기 매핑이다. 새 초상화 요청 규격이 필요하다. 기존 템플릿 전체 모델·출력 크기를 바꾸지 않는다.

무료 얼굴 생성은 가입 혜택을 검사하는 별도 서버 진입을 둔다. 기존 유료 `createRenderJob`의 결제 증명을 가짜로 만들거나 사용자에게 관리자 권한을 부여하지 않는다. `lib/renders/prompt.ts`의 일반 템플릿 문장 치환·추가를 통과시키지 않는 전용 프롬프트 경로로 원문을 전달한다. 재시도 때에도 사용자가 올린 원본을 참조하고 생성 사진을 다시 참조해 얼굴이 누적 변형되지 않게 한다. 제공사 자산 슬롯 회수와 별개로 선택된 기준 사진을 보존하고, 실행 중 참조와 재등록 경로를 보호한다.

공식 모델과 스냅샷은 확인했다. OpenAI는 사용자 지정 크기의 양쪽 변이 16의 배수여야 한다고 안내한다. 제안한 1344×2016은 정확한 2:3이고 2,709,504픽셀이다. 짧은 변 2048 기준은 2048×3072로 달라지므로 ‘2K’ 문자열만 API에 넘기지 않는다. [공식 모델](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), [출력 크기·품질](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options)

지금 계정의 모델 사용 권한과 해당 크기의 실제 응답은 아직 확인하지 않았다. 과거 조직 인증 실패 기록을 현재 장애라고 단정하지 않는다. 권한이 막혀도 다른 모델이나 비공식 브라우저 자동화로 대체하지 않는다. 공식 API 사용량 기반으로 가입자당 평균·상위 비용과 재시도 비용을 측정한다. 과거 저장소의 이미지 1장 추정 단가를 이 해상도의 확정 원가로 재사용하지 않는다.

대표가 제공한 프롬프트는 설계 요구이지 품질 보증이 아니다. 동의받은 다양한 원본의 결과에서 본인 식별성, 눈꺼풀·비대칭·피부색 보존, 머리 잘림, 배경, 옷, 가려진 부분의 과도한 생성 여부를 직접 확인한다. 규격 검사와 사용자 선택만으로 얼굴 동일성을 기술적으로 입증했다고 주장하지 않는다.

## 3. 브랜드 계약과 내부 비용 분리

TWINGS는 캠페인 제작·운영·배포 서비스를 **합의한 총 계약금액**에 제공하는 모델을 권한다. 브랜드에 전달할 것은 예산, 범위, 일정, 결과물, 사용권, 성과 측정 기준이다. 내부 크리에이터 지급액·제작비·원가는 별도 장부다. 실제 비용을 실비 정산하는 계약처럼 표현하면서 차액을 숨기는 설계는 하지 않는다. 금액·세금·예치·결제 일정·잔액 처리·변경 비용은 계약에서 확정한다.

| 데이터 | 브랜드 | 크리에이터 | 스튜디오 |
|---|---|---|---|
| 의뢰 예산·총 계약금액·계약 범위 | 자기 조직 | 기본 비공개 | 허용 역할 |
| 크리에이터 제안·약정·지급액 | 제공하지 않음 | 본인의 조건만 | 운영/재무 권한 |
| 내부 제작비·예상/실현 마진 | 제공하지 않음 | 제공하지 않음 | 재무 등 지정 역할 |
| 콘텐츠·버전·승인·게시 링크 | 계약 범위 | 자신의 참여 건 | 담당 범위 |
| 기준 얼굴·원본 사진 | 제공하지 않음 | 본인만 | 허용 목적·권한만 |
| 브랜드–스튜디오 대화 | 자기 캠페인 | 제공하지 않음 | 담당자 |
| 내부 메모·협상·지급 근거 | 제공하지 않음 | 별도 본인 약정 제외 비공개 | 허용 역할 |

브랜드 전용 응답은 허용 필드를 새로 구성한다. 내부 객체를 통째로 보낸 뒤 화면에서 숨기지 않는다. HTML/RSC/JSON, 서버 액션 오류, 검색·CSV/PDF, 공유 링크, 알림, 활동 이력, 미디어 파일명·첨부의 내용까지 동일하게 제한한다. 첨부파일 자체에 원가가 적혀 있으면 자동 필드 필터로 보호할 수 없으므로 외부 공유용 버전을 별도로 확정한다.

**현재 공개 경로도 수정 대상이다.** `lib/campaigns/catalog.ts`에 지급 규칙이 있고 `components/campaigns/card.tsx`, 캠페인 상세, `lib/campaigns/notify.ts` 모집 메일에서 금액을 표시한다. 새 설계는 공개 모집에서 업무·자격·기한만 안내하고, 검증된 크리에이터에게 본인이 수락할 구체적인 조건을 별도 제안한다. 브랜드 계정에 creator 역할을 추가하는 것만으로 전체 조건을 열람할 수 없게 참여 건 권한을 검사한다. 이전 메일·외부 캡처·크리에이터의 자발적 공유까지 회수하거나 비밀을 절대 보장할 수는 없다.

`docs/CAMPAIGNS.md`의 기존 브랜드 리포트 ‘총 정산’ 후보는 최신 요구로 대체한다. 전체 크리에이터 지급액 합계도 브랜드에 제공하지 않는다. `loadMyCampaigns`가 내부 예산을 포함한 전체 행을 반환하는 현재 서비스는 앱 응답으로 그대로 재사용하지 않는다. 공개·브랜드·본인 참여·스튜디오별 허용 필드를 분리하고 서비스 롤 조회마다 조직/참여 건 범위를 확인한다.

## 4. 의뢰 → 모집 → 제작 → 게시

브랜드 가입은 조직 생성과 첫 의뢰까지 허용하고, 스튜디오가 범위·실행 가능성을 검토한 뒤 견적·일정을 제안한다. 가입만으로 다른 조직이나 실제 캠페인을 볼 수 없다. 팀 합류는 검증된 초대를 사용하며 이메일 도메인이 같다는 이유만으로 합류시키지 않는다.

의뢰 폼은 **무엇을 알릴까요 / 누구에게 닿고 싶나요 / 예산 / 일정 / 참고 자료 / 제작 방식** 순으로 짧게 시작한다. 고급 입력에 플랫폼, 목표, 금지 표현·필수 표기, 콘텐츠 사용 범위, 원본 파일 제공 여부를 둔다. 예산 입력이 결제나 계약 수락은 아니다. 세전/세금 포함 기준과 미정 처리도 필드로 확정해야 한다.

참고 자료는 동영상·이미지·PDF·URL과 ‘이 자료에서 참고할 점’을 함께 받는다. 브리프 버전마다 첨부를 고정한다. 파일은 비공개 업로드·형식/크기 검사·진행/취소/재시도·권한 있는 미리보기를 제공한다. URL은 HTTP(S)로 제한하고 외부 링크임을 표시한다. 자동 미리보기는 별도 서버 검사(내부 IP·리다이렉트 차단 등) 후 허용된 출처만 처리한다. 참고 링크를 임의 다운로드하거나 그 콘텐츠의 재사용 권리까지 얻었다고 가정하지 않는다.

| 단계 | 크리에이터 제작 | 스튜디오 제작 |
|---|---|---|
| 선정·조건 수락 | 본인의 제작·게시 범위와 대가를 확인 | 본인의 얼굴 사용·게시 범위와 대가를 확인 |
| 제작 | 캠페인 전용 허용 횟수/포맷으로 제작·버전 제출 | 스튜디오가 캠페인과 인물의 명시된 권한 범위에서 제작 |
| 검토 | 스튜디오 검토 → 필요 시 브랜드의 해당 버전 승인 | 스튜디오 검토 → 크리에이터 본인 표현 확인 → 필요 시 브랜드 승인 |
| 전달·게시 | 승인된 버전을 자신의 SNS에 게시 | 승인 파일·권장 캡션·필수 표기를 받아 자신의 SNS에 게시 |
| 증빙 | 게시 링크 제출 → 소유 계정·게시 ID·조건 확인 | 동일 |

제작 방식은 캠페인 기본값과 참여 건별 명시적 예외로 저장한다. 운영 중 변경하면 새 약정·수락이 필요하다. 일반 사용자의 무료 얼굴 만들기 횟수와 캠페인의 영상 제작 비용/수정 횟수는 다른 계약이다. 이 비용 정책은 아직 미정이다.

버전 승인 전 게시, 잘못된 계정 링크, 비공개·삭제 게시물, 기한 연장, 수정 요구, 연결 해제, 제작 담당 변경을 명시적 예외로 처리한다. 광고/협찬 및 플랫폼이 요구하는 콘텐츠 표기는 게시 점검에서 다루며, 기존 TWINGS 화면 배지 결정과 혼합하지 않는다. 자동 SNS 게시 기능은 이 흐름의 필수 조건이 아니다.

## 5. 게시물 트래킹과 종료 리포트

크리에이터는 연결된 계정을 선택하고 게시 URL을 제출한다. 서버가 플랫폼·게시 ID를 정규화하고 중복을 막는다. 공식 API로 작성자·게시 시각·미디어를 검증할 수 있으면 수행하고, 불가능하면 **확인 필요**로 남겨 증빙과 수동 검수를 받는다. 호스트가 instagram.com이라는 사실만으로 본인 게시물이라고 인정하지 않는다.

플랫폼별 공식 API 범위·권한은 [SNS 설계](SOCIAL-CONNECTIONS.md)를 따른다. 토큰 철회·만료·요금 한도·비공개 전환·조회 지연 시 마지막 성공 시각과 현재 상태를 보여준다. 연결된 공식 API가 없는데 ‘실시간’이라고 표시하지 않는다. D+1/3/7/14/30 수집은 후보이며 계약의 측정 기간과 비용 예산으로 확정한다.

브랜드 첫 화면은 **진행 단계 / 확인할 콘텐츠 / 게시 완료 / 조회수 / 최근 업데이트** 중심으로 구성한다. 목표는 실적과 구분한다. 종료 리포트는 다음을 한 번에 전달한다.

- 납품·게시 완료 수와 약정 대비 이행, 콘텐츠별 링크·게시/승인 버전·재사용 가능 범위.
- 플랫폼별 조회수와 정의. 서로 다른 플랫폼의 재생을 합산하면 **조회수 합계**이지 ‘순 도달 인원’이 아니다. 조회수 스냅샷을 날짜별로 더하지 않는다.
- 좋아요·댓글·공유·저장 등 각 API가 제공하는 반응. 반응률은 분모(조회·도달·팔로워 중 무엇인지), 기간, 포함 항목을 표시한다. 서로 다른 정의를 무조건 평균내지 않는다.
- 수집된 게시물/전체 게시물, 출처(API·제출 증빙·운영 확인), 수집 시각, 미집계 사유. 미집계는 0이 아니다.
- 반응 내용 요약은 권한 범위에서 얻은 실제 댓글만 사용한다. 표본 수·언어·기간을 함께 보여주고 인용·요약 검토를 거친다. 댓글 접근이 없으면 ‘댓글 내용 분석 미제공’. 감성 추정은 관측 사실과 구분하며 사생활·민감 특성을 추론하지 않는다.
- 다음 캠페인 제안은 관측 근거와 가설을 구분한다. 목표 미달·삭제 게시물도 누락시키지 않는다.

발행 리포트는 버전과 기준 시점을 고정한다. 나중의 데이터 수정은 정정본으로 남기며 정산 완료·브랜드 확인과 독립 상태다. 총 계약금액 기반의 ‘캠페인 비용/조회수’는 정의를 붙인 별도 지표이며 내부 크리에이터 지급액을 사용하지 않는다.

## 6. 캠페인 대화와 Slack

브랜드와 스튜디오 간 **캠페인별 대화**를 우선 권한다. 메신저 전체를 만드는 대신 브리프·파일·콘텐츠 버전에 연결된 질문, 답변, 첨부, 미읽음, 담당자, 알림을 제공한다. 예상 답변 시간을 운영 약속 없이 임의로 쓰지 않는다. 전송 중/실패/다시 보내기에서 입력을 보존하고 클라이언트 요청 ID로 중복을 막는다.

브랜드 대화와 내부 메모는 별도 저장·조회 권한을 가진다. 작성 중 토글 하나로 내부 메모가 외부로 전환되는 UI는 피한다. 예산 변경·버전 승인·게시 허용은 대화에서 ‘좋아요’라고 썼다는 이유로 실행되지 않는다. 별도 버튼에서 대상·버전·변경 내용을 확인하고 기록한다. 회원 탈퇴·조직 제거 후에는 새 메시지·첨부 접근을 차단한다.

Slack은 대화의 원본이 아니라 운영 알림 창구다. 후보 이벤트는 `의뢰 접수`, `담당자 미배정`, `브랜드 답변 도착`, `승인/게시 지연`, `성과 수집 중단`이다. 기본 알림에는 의뢰/캠페인 번호·상태·관리 화면 링크만 넣고, 연락처·얼굴·개별 지급액·전체 대화·비공개 참고 파일은 넣지 않는다. 브랜드명은 해당 채널 접근 범위 확인 후 선택한다. 알림 클릭 후에도 웹 세션 권한을 다시 확인한다.

새 의뢰 저장과 알림 outbox를 같은 트랜잭션에 기록한다. 워커는 이벤트+채널별 중복 예약을 막고, 전송 상태·시도·다음 시각·실패 이유를 보관한다. 429는 Retry-After를 따르고, 권한 오류·폐기된 채널은 운영 작업으로 올린다. 수신 성공 뒤 응답이 끊긴 경우 Slack 중복 노출 가능성은 남으므로 정확히 한 번 발송을 보장한다고 쓰지 않는다. 알림 실패가 의뢰 접수를 취소하거나 중복 의뢰를 만들지 않아야 한다.

현재 문의의 저장 후 `after()` 발송을 그대로 성공 보장으로 취급하지 않는다. `lib/notify/worker.ts`의 lease·dedupe는 참고하되 소비자 유료 entitlement·마케팅 동의·일정 시간이 지난 알림 폐기 조건을 운영 알림에 적용하지 않는다.

시작은 특정 채널에 연결된 Incoming Webhook이면 충분하다. 메시지 수정·삭제·일관된 스레드 관리가 필요하면 봇 API를 선택한다. 웹훅 URL은 서버 비밀값이고 브라우저·PR·로그에 출력하지 않는다. [Slack Webhook](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/), [봇 메시지 API](https://docs.slack.dev/reference/methods/chat.postMessage/), [요청 제한](https://docs.slack.dev/apis/web-api/rate-limits/)

2026-09-20 읽기 전용 확인: 대표가 준 가비아 화면은 `yagiworkshop.xyz`를 편집하는 화면이었다. 로컬 DNS 조회에서 `twings.app` NS는 `meilani.ns.cloudflare.com`, `ricardo.ns.cloudflare.com`으로 확인됐다. 주소 결정 후 Vercel에서 해당 호스트를 등록하고 **그 프로젝트가 제시한 CNAME**을 권한 DNS에 추가한다. 기존 프로젝트의 값을 추측해서 복사하지 않는다. 호스트 라우팅·허용된 OAuth 복귀 URL·쿠키 범위·CSRF·인증서·조직 권한 검증을 함께 배포한다. 도메인 분리 자체가 권한 통제가 되지는 않는다. [Vercel 도메인 연결](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

이번에는 DNS/Vercel 설정 저장, Slack 채널 생성·메시지 발송, 외부 AI 생성 호출을 실행하지 않았다. 검토 가능한 설계·시안이 산출물이다.

작업: 일반 사용자가 본인 셀피로 기준 얼굴을 만들고 선택한 얼굴을 다음 영상 생성에 재사용하도록 구현한다.

범위: `lib/identity/**`, `lib/images/**`, 관련 업로드·계정·렌더 API와 화면, `components/twings/studio.tsx`의 얼굴 선택, KO/EN 사전·테스트·필요한 새 마이그레이션 파일. 기존 결제·제공사 검수는 유지한다. 실제 변경 경로는 착수 시 더 좁힌다.

읽기: AGENTS.md 전부, docs/TEMPLATES-IA.md §8.2·§12 자산 경로, 현재 법무의 본인 얼굴·보관 규칙, 이 문서 §2·§8과 프롬프트 v1, `lib/identity/service.ts`, `lib/images/engines.ts`·`openai.ts`, `lib/renders/service.ts`.

완료 기준: 확정된 무료 총횟수와 출력 규격으로 셀피→후보→선택→영상 재사용; 실패 미차감·중복/동시성·버전 고정·본인 소유권 보호; 본인 인증과 생성 이미지를 구분; 실제 얼굴 품질 직접 검토. 공개 플래그는 유지한다.

검증: AGENTS.md §3 전체 루프, 일반 사용자 모바일/데스크톱 흐름, N회 경계·실패·동시 요청·기존 자산 경로 회귀. 시크릿 및 동의 없는 얼굴을 PR 증거에 넣지 않는다.

브랜치: `codex/identity-portrait` 후보. 착수 시 선행 PR 병합 상태를 확인하고 별도 PR. main 직접 push 금지. 마이그레이션은 파일만 만들고 ‘클라우드 적용 필요’ 표시.
