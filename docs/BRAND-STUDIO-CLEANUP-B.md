# 브랜드 스튜디오 이름 정리·진입 닫기·에셋 통합 설계 (묶음 B)

## 1. 목표와 하지 않을 것

- **목표**
  1. 이미지·영상 생성 공간의 명칭을 레일·페이지 제목·빈 화면·안내 문구 전반에서 **`이미지 스튜디오` (`Image studio`)**와 **`비디오 스튜디오` (`Video studio`)**로 통일한다.
  2. 고객 셀프 스튜디오의 결과물 **‘리뷰에 올리기’** 버튼(뷰어·갤러리 더보기 메뉴)과 레일의 스튜디오 리뷰(`/brand/studio/review`) 진입을 닫는다.
  3. 고객 워크스페이스에서 용도가 불분명한 **‘브랜드 고정 기준’(`브랜드 키트`, `/brand/identity`)** 노출을 모두 숨긴다.
  4. 스튜디오 우측 ‘보관함’과 좌측 레일 ‘에셋(`/brand/library`)’의 명칭·역할 중복을 해소해 **‘에셋’ 하나로 통합**하고, 본화면에서는 검색·역할/매체 필터·연관 탐색·폴더·캠페인 납품본을 한눈에 다루며 스튜디오 우측은 참조를 끌어다 놓는 접이식 **에셋 서랍**으로 둔다.
  5. 2026-11-11 대표 반응을 `docs/design/TASTE.md`에 기록한다.
- **하지 않을 것**
  - 리뷰 관련 DB 테이블(`brand_studio_reviews` 등), `/api/brand-studio/review`, 공유 컴포넌트(`components/brand-studio/review/*`)는 삭제하지 않는다(프로젝트 룸 및 공유 링크 `/s/[token]`에서 재사용).
  - 브랜드 아이덴티티 DB 테이블(`brand_identities`, `brand_looks`, `brand_memory`), 관리자 콘솔(`/admin/brand-workspace/organizations/[id]`), 서버 프롬프트 보강기의 읽기 경로(`lib/brand-studio/prepare.ts`의 `confirmedIdentityFor`)는 변경·삭제하지 않는다.
  - 모픽(`Morphic`·`모픽`·샌드박스 ID) 및 `generative_media` 차단 조직의 기존 사이드바·보관함 마크업은 1바이트도 바꾸지 않는다.

## 2. 방향 조정 기록 (보관함 → 에셋 단일 허브 통합)

- **원래 요청**: 스튜디오 우측 ‘보관함’의 용도가 보이지 않으니 (a) 삭제, (b) 단순 저장소 유지, (c) 텍스트·이미지 유사도 및 이미지 맵 탐색 도구화(`visual-maker`·`cosmos.so` 참고), 또는 좌측 ‘에셋’ 메뉴와 합치는 안을 비교해 재정의할 것.
- **바꾼 방향**: ‘보관함’이라는 별도 이름을 없애고 **좌측 레일 `에셋(/brand/library)` 단일 허브로 통합**한다. `/brand/library` 본화면에서 업로드·생성 결과·폴더·좋아요·캠페인 납품본 통합 그리드와 텍스트(이름·태그·생성 프롬프트)·역할·매체·연관 항목 탐색 및 원클릭 스튜디오 연결(`이미지 스튜디오 참조`·`영상으로 만들기`·`참고 영상 리버스`)을 제공하고, 스튜디오 작업 화면 우측 패널은 같은 데이터를 공유하는 접이식 **‘에셋’ 빠른 참조 서랍**으로만 남긴다.
- **이유**: 기존에는 좌측 ‘에셋’을 누르면 캠페인 납품본만 보이는 ‘보관함’이 열리고, 스튜디오 우측에는 업로드·폴더만 보이는 또 다른 ‘보관함’이 떠 있어 두 공간이 단절되어 있었다. 하나의 ‘에셋’ 모델로 합치면 학습 비용 없이 넓은 화면 탐색과 작업 중 드래그 참조를 동시에 해결하며, 외부 임베딩 DB 추가 없이도 프롬프트·역할·태그·계보 기반 즉시 탐색(지연 0ms, 추가 원가 \$0)을 먼저 제공할 수 있다.

## 3. 검토한 대안과 버린 이유

1. **스튜디오 우측 패널을 완전히 삭제하는 안 (선택지 a)**
   - 버린 이유: 2026-11-10 대표 결정(`TASTE.md` #87)의 핵심인 “회사 에셋을 우측에서 바로 끌어다 참조로 넣는 편의성”이 사라져 프롬프트·부분 수정마다 파일 선택 창을 열어야 한다.
2. **초기부터 `pgvector` + 멀티모달 임베딩(CLIP/SigLIP/Gemini Embedding) 이미지 맵을 붙이는 안 (선택지 c 즉시 도입)**
   - 임베딩 저장·비용·지연 검토:
     - 저장 위치: Supabase Postgres `vector(768)`(`brand_studio_assets`·`outputs` 인덱스 포함 약 4KB/건) 또는 R2 JSON 인덱스.
     - 비용: Gemini Embedding 2 기준 1,000건당 약 \$0.01~0.02 수준이나, 업로드·생성 완료마다 비동기 인덱싱 큐가 필요하고 로컬 GPU 워커 사용 시 단일 PC 장애점(SPOF) 의존이 늘어난다.
     - 검색 지연: 텍스트→벡터 변환 API 왕복 120~350ms + DB HNSW 조회 5~15ms.
   - 버린 이유: 현재 조직당 에셋 수가 수십~수백 건 규모이므로 이름·역할·태그·생성 프롬프트·부모 계보 기반 즉시 필터링(<5ms)과 코스모스식 밀도 그리드가 더 빠르고 정확하다. 조직당 에셋이 1,000건 이상 쌓이는 시점에 `pgvector` 인덱스를 무중단 추가한다.
3. **`sectionVisibility.identity` 자체를 `false`로 고정하는 안**
   - 버린 이유: `sectionVisibility`는 조직 권한 정책(`brand_learning` 차단 여부)을 판정하는 도메인 함수이며 기존 권한 회귀 테스트가 이를 검증한다. 정책 함수는 유지하고 레이아웃·레일·페이지 라우트(`/brand/identity` → `notFound()`)에서 고객 화면 노출만 닫는 편이 안전하다.

## 4. 데이터 모델과 화면 흐름

- **스키마 변경 없음 (마이그레이션 0건)**: 기존 `brand_studio_assets`, `brand_studio_outputs`, `brand_studio_jobs`, `brand_studio_folders`, `brand_studio_folder_items`, `brand_studio_likes`, `brand_content_versions`를 그대로 읽는다.
- **`/brand/library` 분기 규칙**:
  - `brandStudioV2Open() && choice && studioV2Visible(choice, true)`인 일반 브랜드: 통합 **`BrandAssetHub`** 렌더 (`전체` · `업로드` · `생성 결과` · `폴더` · `좋아요` · `캠페인 납품본` 탭, 검색·역할·매체 필터, 연관 항목 필터, 폴더 관리, 파일 업로드, `?ref=` / `?from=` / `?start=reverse` 스튜디오 직행).
  - 모픽·생성 차단·캠페인 게스트·플래그 off: 기존 캠페인 납품본 `ContentLibrary` 마크업을 그대로 반환.
- **스튜디오 `?ref=` 수신**: `/brand/studio?organizationId=...&ref=a:<id>|o:<id>`로 진입하면 해당 이미지를 프롬프트 참조 트레이에 자동 첨부하고 URL 파라미터를 정리한다.

## 5. 실패했을 때의 동작 · 측정 지표 · 되돌리는 방법

- **실패 동작**:
  - `/brand/studio/review` 또는 `/brand/identity` 직접 주소 접근 시 인증 게이트 통과 후 즉시 `404`(`notFound()`)를 반환하며 내부 서비스 쿼리를 호출하지 않는다.
  - 통합 `에셋` 화면에서 스튜디오 API 일시 오류 시 오류 배너와 `다시 불러오기` 버튼을 노출하고, 캠페인 납품본 목록은 서버 렌더로 독립 표시한다.
- **측정할 숫자**:
  - `에셋(/brand/library)`에서 `이미지/비디오 스튜디오 참조로 열기` 클릭 비율.
  - 업로드 에셋의 역할·태그 지정 비율 및 폴더 사용 조직 수.
- **되돌리는 방법**:
  - 단일 PR 커밋 되돌리기(`git revert`)만으로 즉시 복구된다(DB 스키마·저장소 키 변경 없음).
