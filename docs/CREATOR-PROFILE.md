# 크리에이터 로그인과 캠페인 프로필

2026-10-08. 로그인 표시 개선과, 대표가 요청한 SNS·맞춤 캠페인 제안 구조를 구분한다.

## 이번 반영

- 공개 페이지의 헤더는 정적 HTML을 유지한다. 클라이언트에서 `/api/account/session`을 한 번 확인하고 이름·이니셜·내 프로필·내 작품·내 캠페인을 표시한다. 모바일에서도 로그인한 계정 버튼을 바로 노출한다.
- 응답은 서버에서 검증한 세션에 한하며 이름만 포함한다. 이메일, SNS, 토큰, 권한은 응답하지 않는다. 모든 응답은 `private, no-store`, `Vary: Cookie`, `noindex, nofollow`다. 주기적으로 조회하지 않으며 탭 복귀·브라우저 복원 시 갱신한다.
- `/account`에서 활동 이름을 수정하고 로그인 이메일, 기존 SNS, 알림 설정, 작품·지원 이력을 확인한다. 기존 `profiles` 컬럼만 사용한다. 새 스토리지·외부 API·DB 마이그레이션은 없다.
- SNS는 캠페인 지원서에서 **다음 지원에도 사용**을 선택한 경우에만 저장한다. 신청서·쓰기 기록·SNS 저장은 같은 트랜잭션이다. 다음 신청에는 본인의 저장 주소만 자동 입력한다. 신청별 확정 주소를 프로필보다 우선한다.
- 무료 크리에이터도 화면에 제공된 캠페인 알림 설정을 저장할 수 있다. 알림 전송은 기존 캠페인 모집 알림 경로를 유지한다.
- 세션 갱신 때 복제된 요청 헤더에도 새 쿠키를 전달한다. 갱신 응답과 리디렉션, OAuth 경로는 캐시하지 않는다.
- 활동 SNS 주소 등록은 계정 소유 인증이나 통계 연동이 아니다. 자동 매칭·자동 제안·자동 게시를 제공한다고 표시하지 않는다.

## 제안: 맞춤 캠페인 제안 신청

로그인 직후부터 입력을 강요하지 않는다. 템플릿을 둘러보거나 영상 제작을 먼저 할 수 있고, 프로필의 별도 카드에서 원하는 사람이 제안을 신청한다.

권장 문안: **내 채널에 맞는 캠페인을 제안받으세요.** 설명: **활동 계정과 관심 분야를 알려주세요. 어울리는 캠페인이 생기면 이메일로 연락드릴게요.** 초기에는 팀이 검토해 제안한다. 자동 매칭 알고리즘을 전제로 하지 않는다.

1. 활동 계정: Instagram·TikTok·YouTube 주소를 여러 개 등록. 비밀번호나 SNS 토큰을 입력받지 않는다. 일반 주소 등록과 OAuth로 확인된 계정은 별도 상태다.
2. 관심 분야: 뷰티·패션·라이프스타일 등 최소한의 선택 항목. 참여 희망 시장·제작 언어도 선택으로 둔다. 국적이나 주민번호는 받지 않는다.
3. 기본 연락: Google·Kakao로 로그인한 이메일. 계정 인증과 연락 채널 검증은 별개로 취급한다.
4. 휴대폰 번호: **선택**. 문안은 **빠른 연락을 원하시면 휴대폰 번호를 남겨주세요.** 입력하지 않아도 캠페인을 제안받을 수 있다. 번호를 남긴 사실을 문자 광고 수신 동의나 본인 인증으로 간주하지 않는다.
5. 제안받기: 기본 해제된 별도 선택 동의. 목적·항목·보유 기간·철회 경로를 같은 화면에서 확인한다. 일반 템플릿/캠페인 모집 알림 토글에 맞춤 제안 동의를 섞지 않는다.

본인의 프로필과 TWINGS 운영자에게만 보인다. 브랜드에 연락처를 공개하지 않는다. 브랜드 제공은 기존 지원·선정 절차와 별도 동의 범위만 따른다. 제안을 끄거나 계정을 삭제하면 해당 목적의 연락처·선호 데이터를 삭제하며, 계약·정산 기록의 보존과는 분리한다.

### 다음 구현 전에 필요한 결정

현재 개인정보처리방침은 SNS를 캠페인 지원·게시 시 수집하며, 전화번호는 브랜드 문의에만 명시한다. 따라서 크리에이터 전화번호·관심 분야·선제적 제안 수집을 곧바로 열지 않는다. 대표가 수집 목적·항목·보유 기간과 문안을 확정한 뒤 법률 문서에 반영한다. 이 문서는 공개 개인정보처리방침을 변경하지 않는다.

새 필드는 `creator_campaign_preferences` 등 전용 비공개 테이블로 분리한다. 제안 동의 버전·시각·철회 시각, 선택 연락처와 선호만 보관한다. 소유자 세션을 검사한 서버 경로에서만 쓰고 기존 RLS deny-all·서버 서비스 역할 패턴을 따른다. 클라우드 마이그레이션은 대표/Director가 적용한다. 첫 화면에 노출하기 전에 읽기·수정·철회·삭제·운영자 조회를 함께 검증한다.

### 실제 SNS 연동

Google 로그인으로 Instagram·TikTok·YouTube에 대한 권한이 생기지 않는다. 플랫폼 앱 등록·최소 범위 동의·심사·토큰 암호화와 갱신·연결 해제 처리가 필요하다. 처음에는 프로필 주소만 저장하고, API 승인이 확인된 플랫폼부터 추가한다. 통계는 수집 시각과 출처를 함께 보관하고 사용자 입력 수치를 API 검증 수치로 표시하지 않는다. 자동 게시 권한은 요청하지 않는다.

- [Meta의 Instagram API 공식 문서](https://developers.facebook.com/docs/instagram-platform/)
- [TikTok Display API 시작하기](https://developers.tiktok.com/doc/display-api-get-started/): Login Kit와 TikTok API 승인, `user.info.basic`·`video.list` 범위가 필요하다. 제안에 필요한 기본 프로필만 연결할 때는 영상 읽기 범위까지 요청하지 않는다.
- [YouTube channels.list 공식 문서](https://developers.google.com/youtube/v3/docs/channels/list): 인증 사용자의 채널은 `mine=true`와 OAuth 권한으로 조회한다. Google 로그인 권한과 분리한다.

## 검증

API의 익명·타인/알 수 없는 호스트 거부·개인정보 최소 응답·캐시 금지, 이름 수정의 소유권/유효성, 무료 계정 알림 저장, 탭 복귀/로그아웃/느린 응답 경쟁, SNS 저장 선택과 트랜잭션 롤백을 테스트한다. 운영 Google 계정의 새로운 OAuth 로그인은 대표가 직접 확인하며, 개발용 fixture를 실제 운영 로그인 증거로 사용하지 않는다.
