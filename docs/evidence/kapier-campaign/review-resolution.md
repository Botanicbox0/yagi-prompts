# Opus 리뷰 처리 기록

2026-10-16. 최초 리뷰는 `opus-source-review.md`, 입력 파일의 SHA256은 `opus-source-manifest.json`에 보존한다. 최초 리뷰 이후 수정한 파일은 후속 리뷰에서 별도로 확인해야 하며 최초 리뷰를 최종 코드 승인으로 표시하지 않는다.

## 저장소·운영 조회로 확인한 전제

- 멤버십 혼용 가설: 현재 운영 스키마에서 `brand_memberships`는 `organization_id,user_id,role,status`를 가진 조직 역할이다. 프로젝트 한정 게스트는 별도 `brand_project_members`에 저장된다. 코드 `0027`/`0031` 마이그레이션과 현재 information_schema 조회가 일치한다. 따라서 제기된 게스트의 조직 전체 승격 가설은 이 스키마에는 해당하지 않는다. 신규 협업/결제 서비스는 프로젝트 게스트를 조직 멤버로 인정하지 않는다.
- RLS: 운영 `pg_roles`에서 postgres/service_role은 BYPASSRLS, anon/authenticated는 false임을 읽기 전용 조회로 확인했다. 로컬에 구성된 클라우드 연결 문자열에서 비밀을 출력하지 않고 역할만 확인한 결과 postgres였다. Vercel의 실제 연결 역할은 운영 QA에서 별도 확인한다. `0132`의 불필요한 서비스 정책을 제거해 기존 저장소의 deny-all/no-policy 원칙을 유지했고, 테스트 서비스 역할을 실제 Supabase처럼 BYPASSRLS로 구성했다. 브라우저 거부·서비스 DELETE 거부 검사는 유지했다.
- 스토리지: `lib/storage/index.ts`의 `STAGING_BUCKET='content'`. 실제 Supabase driver의 `putStaging`도 같은 버킷에 `upsert:false`로 쓰고 `read('content',key)`로 읽는다. 버킷 불일치 가설은 해당하지 않는다. 이번 범위에 자동 파일 GC는 추가하지 않는다.
- 경합 검증: PGlite runner는 트랜잭션을 직렬화한다. Promise.all 테스트는 멱등성과 상태 결과를 확인하지만 실제 PostgreSQL 다중 연결 deadlock 검증은 아니다. 로컬 PostgreSQL/Docker 실행기를 확인하지 못했으며 운영 DB에 경합 실험을 하지 않는다. SQL의 락 순서를 명시적으로 통일한 뒤 별도 PostgreSQL 통합 검증이 필요하다.
- 비공개 범위: 비공개 포맷·대화·파일 권한을 보호한다. 초대는 공개 모집 캠페인 신청으로 이어지며 캠페인 자체를 초대 전용으로 전환하지 않는다. 공개 신청자도 TWINGS가 선정하면 참여할 수 있다. 초대만으로 선정·회원 권한을 부여하지 않는다.
- 자동 메시지 분석 고지는 검토용 법무 초안에 포함한다. 현재 정책을 승인 없이 바꾸지 않으며 위험 분석/발송 플래그는 off다. 운영 개방 전에 실제 고지·보관 기간·동의 체계를 확정한다.

## 수정 상태

최초 리뷰의 구체적인 결함에 아래 수정을 적용했다. 최종 검증 결과와 후속 Opus 판정은 `verification.md`와 `opus-final-review.md`에 별도로 기록한다.

| 항목 | 수정 내용 |
| --- | --- |
| P2-1 결제 키·승인 실패 | 복귀 화면의 명시적 확인 버튼, URL에서 키 제거, 확정 거절과 조회 404가 함께 입증된 경우에만 실패 처리. 불명확한 주문은 새 결제를 차단하며 운영자 대사 경로를 제공한다. 기존 키 이력은 덮어쓰지 않는다. |
| P2-2 만료된 수락 견적 | 미결제임을 확인한 관리자가 사유를 남겨 종료하고 새 견적을 발행할 수 있다. 원래 수락자·금액·조건은 보존한다. |
| P2-3 판매 중단 후 환불 | 신규 판매 플래그와 기존 결제 조회·환불의 환경 검사를 분리했다. |
| P2-4 환불 사전 조회 | lease만 먼저 확보하고, 실제 취소를 시작하기 전까지 paid/review 상태를 보존한다. 불명확한 취소는 재전송하지 않는다. |
| P2-5 비동기 입금 | awaiting_deposit 상태와 명시적 상태 확인·관리자 대사를 지원한다. 상시 스케줄러나 webhook은 운영 전 연결 대상으로 남긴다. |
| P2-6 잠금·파일 I/O | 쓰기는 campaign 우선 잠금, 읽기 행 잠금 제거. 파일 reserve → 트랜잭션 밖 업로드 → 재인가 finalize. 읽기도 저장소 I/O 이후 권한을 다시 확인한다. |
| P2-7 비로그인 초대 | 참여 랜딩 GET/HEAD는 로그인 전에 토큰을 임시 보관할 수 있다. OAuth query에는 토큰을 넣지 않는다. 외부 브라우저 전환 시 정확한 참여 링크에만 fragment를 복원한다. |
| P2-8 동의 증빙 | 전체 안내문·한국 시간 마감을 표시하고 수락 조건 원본 JSON과 해시를 불변 보관한다. |
| P2-9 기존 보상 비교 | 동일한 정규화 스키마로 비교하되, 무관한 제목 수정은 기존 보상 원본을 보존한다. |

그 밖에 수락한 초대 철회 거절, 초대 응답 유실 시 재발급 안내, 정확한 HTTP/관리자 오류, 한국어 미개방 안내, 감사 기록 삭제 권한 회수, 결제 GET의 읽기 전용화, funding 잠금 순서 통일, Slack UUID 링크로 검토 항목 찾기를 반영했다. 브랜드 보상 제안은 검토용이며 기존 약정 보상을 변경하지 않는다.

고정 의존성 검증은 공유 node_modules 연결을 분리하고 lockfile 그대로 `npm ci`한 Next 15.5.27 / Vitest 4.1.11 환경에서 수행한다. 이전 공유 버전 결과나 편집 중 실행된 전체 테스트 결과는 최종 통과 증거로 사용하지 않는다.

## 후속 리뷰에서 추가로 찾은 사례

`opus-final-review.md`는 최초 9개 P2의 수정을 확인했으나, 다른 주문의 paymentKey로 인한 고착 P2-A와 5개 P3를 지적했다. 이를 숨기거나 최초 리뷰의 통과로 대체하지 않는다.

- P2-A: 현재 구매자·주문 인가 후 제공사 키를 사전 조회한다. 다른 주문의 키는 DB 바인딩이나 confirm 이전에 거부한다. 네트워크 조회 이후 실제 claim 시 현재 권한을 다시 확인한다. 이미 잘못 묶인 기록은 제공사에서 다른 주문 소속이 확인된 경우에만 복구하며 외부 주문의 결제를 취소하지 않는다.
- P3-1: 협업 테이블 5개의 DELETE를 DB 소유자에게도 트리거로 거절한다. 기존 service_role 권한을 회수하고 SELECT/INSERT 및 필요한 열 UPDATE만 다시 부여한다. 이미 GRANT ALL이 있는 환경을 테스트한다.
- P3-2: 익명 초대 랜딩은 단일 SELECT의 같은 공개 값으로 표시 내용과 해시를 만들고 행 잠금을 사용하지 않는다.
- P3-3: 보상 제안은 캠페인 잠금 전에 현재 프로젝트·조직 역할을 읽기 전용으로 확인한 뒤, 정해진 잠금 순서 아래 권한을 재확인한다.
- P3-4: declined/withdrawn/expired 지원서가 있으면 명확한 안내와 409로 거절하고 초대를 소비하지 않는다. 선정이나 재신청을 자동으로 되살리지 않는다.
- P3-5: 보상 제안 오류를 invalid 400, unavailable 503, rate_limited 429로 구분한다.
- 견적 유효기간은 기존 브랜드 공통 KST 날짜·시각 포매터로 표시한다. 불명확한 환불/검토 상태는 `docs/qa/campaign-funding-recovery.md`에 운영 대조 절차를 남겼다.

이 수정 이후 소스를 다시 동결해 `opus-closure-manifest.json`의 변경 파일과 문맥으로 Opus 5.5 재검토를 요청했다. 최종 결론은 `opus-closure-review.md`이며 실행 검사와 운영 준비 상태는 `verification.md`로 구분한다.

## 종결 리뷰의 처리

Opus 5.5 종결 리뷰는 P1/P2 차단 결함 없음, P2-A와 P3-1~5 해결로 판정했다. 추가 비차단 P3-c(0134의 기존 서비스 권한)는 실제 PGlite에서 기존 GRANT ALL을 구성해 DELETE/TRUNCATE가 남는 실패를 재현한 뒤, service_role도 revoke 대상으로 추가했다. 회귀 테스트는 읽기·삽입 권한 유지와 삭제·TRUNCATE 회수를 확인한다. 이 두 파일은 `opus-permissions-review.md`로 별도 재검토한다.

나머지 비차단 후속 사항은 숨기지 않는다. 관리자 환불/해제는 인가 후 최대 15초의 제공사 조회 구간에서 관리자 권한을 다시 확인하지 않으며, 초대 발행과 일부 참여자 쓰기는 짧은 캠페인 잠금을 인가보다 먼저 획득한다. 운영 개방 전 권한 철회·경합 QA에서 다룬다. 일부 협업 상태 오류의 403/409 의미 정리도 후속 UI/API 개선이다. 기존 applied 지원자가 초대를 수락할 때는 기존 신청에 연결하며, 새 pitch/SNS로 지원서를 덮어쓰지 않는다. 종료된 지원서는 이 동작과 달리 거절한다.

리뷰가 확인하지 못한 견적 입력 시각은 부모가 `lib/admin/campaign-funding-operations.ts`에서 `${raw}+09:00` → ISO 변환을 확인했다. `formatBrandTimestamp`의 KST 날짜·시각 표시는 회귀 테스트에 포함했다. 로컬 sweep의 최초 56개 실패는 빌드의 기본 origin 3000과 검사 origin 3107의 불일치였다. 검사를 약화하지 않고 build/start/sweep의 origin을 3107로 일치시켜 재검증한다.
