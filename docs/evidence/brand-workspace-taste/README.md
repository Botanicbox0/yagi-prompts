# brand.twings.app 화이트 스튜디오 감도 (2026-10-29)

대표 피드백 "의문의 빨간색 등장, 감도가 전혀 느껴지지 않는다"에 대한 작업이다.

**2차 반영(같은 날 대표 지시):** "오른쪽 레일 죽여" → 홈의 오른쪽 활동 레일 제거, 최근 제작물은 캠페인 목록 아래로. 이어서 캠페인 콘텐츠 확인·브리프 탭 오른쪽에 붙던 대화 패널도 뺐다("Remove it too"). 대화는 "파일·대화" 탭에서 그대로 보인다(/admin은 기존 그대로). "블루는 좀 더 감각적인, 화이트 톤과 어울리는 블루로(추후 메인 키 컬러 변경 예정)" → `#0000EE` 대신 부드러운 울트라마린 `#4355E8`(oklch 0.53 0.22 271). 블루는 `--ys-accent` 토큰 하나에서만 `color-mix`로 파생하고, 네이티브 체크박스도 `accent-color`로 같은 색을 쓴다. 키 컬러가 바뀌면 이 한 줄만 고치면 된다. 아래 after 캡처는 2차 반영 뒤의 화면이다. 기준은 `docs/design/TOOLBOX.md`·`docs/design/TASTE.md`, Playbook 앱 화면 두 장(로컬, 커밋하지 않음), 브랜드 랜딩(`/brands`)의 흰 바탕·잉크·블루 `#0000EE`.

**3차 반영(대표 "우리의 블루"):** 대표가 콘플라워 블루 셔츠·파우더 블루 배경 사진을 보고 "흰 배경이랑 잘 어울리고 감각적"이라며 브랜드 블루를 정했다. 랜딩 세션이 측정한 값 `#3875C5`(사진 셔츠의 색상·채도, 흰 글자 4.65:1이 되도록 명도만 낮춤)로 `--ys-accent` 한 줄을 바꿨다. 이 값은 작은 글자로는 알라바스터 4.41:1, 자기 옅은 바탕 4.25:1로 AA에 못 미쳐서, 글자로 쓰는 블루는 같은 색상을 85%로 어둡게 섞은 `--ys-accent-text`(`#3063A7`)를 쓴다. 채움·링·포커스는 `--ys-accent`. after 캡처는 이 값으로 다시 찍었다.

## 무엇이 바뀌었나

- **빨강 제거.** 브랜드 강조로 쓰이던 빨강(로고 옆 점, 사이드바 현재 위치 막대, 탭 밑줄, "진행 중" 칩, 진행 막대, 상담 런처·아바타·말풍선 그라데이션, 포커스 링, 확인 필요 배지)을 블루(현재 `#3875C5`)나 잉크로 바꿨다. 진짜 오류·삭제만 낮은 채도의 `--ys-danger #a3392f`로 남긴다. `--color-blue`가 빨강으로 매핑돼 있던 버그도 고쳤다(포커스 링·`text-accent`가 빨갛게 나오던 원인).
- **토큰.** 알라바스터 `#F8F9FA`/흰 층위, 잉크, 블루 하나(`--ys-accent`, 나머지 블루는 모두 여기서 파생), 헤어라인, 4겹 daylight 그림자, 이중 링(바깥 헤어라인 + 안쪽 흰 림), 유리 2종(milky quartz, 미디어 위 다크), 스프링(`linear()` + `cubic-bezier(0.22,1,0.36,1)` 폴백), concentric radius. 공유 규칙은 Admin 값을 `var()` 폴백으로 남겨 `/admin`은 그대로다.
- **셸.** 알라바스터 위 큰 라운드 프레임(28px), 프레임 안 회색 사이드바 열, 조용한 회색 아이콘 + 흰 pill 현재 위치, 큰 볼드 제목 + 개수 칩, 한 줄 pill 툴바, 라운드 미디어 그리드, 썸네일 위 다크 유리 칩. 오른쪽 활동 레일은 두지 않는다(대표 2026-10-29).
- **#121 화면.** 후보 카드·비교 트레이·선별 표·범위 팝오버·일괄 처리 바를 같은 체계로 맞췄다. 390폭에서 선별 화면이 430–579px 가로로 넘치던 문제(그리드 트랙이 표 폭만큼 늘어남)와, 영어에서 "지표 자세히" 표가 카드 밖으로 잘리던 문제도 고쳤다.

대표 시각 지시 6개 적용 위치: 유리는 오버레이·떠 있는 HUD·사진 위 칩에만, 림 하이라이트는 버튼·패널·섬, 커서 조명은 카드, 에셋 색 번짐은 캠페인 상세와 스튜디오 결과, 그레인(정적, 약 1.8%)은 알라바스터 바탕과 사이드바에만, 떠 있는 island + 스프링은 비교 트레이·일괄 바·상담 런처.

**적용하지 않은 것:** 떠 있는 원형 이전/다음 버튼. 브랜드 워크스페이스에 이전/다음으로 넘기는 화면이 지금 없어서, 새 기능을 만들지 않는다는 범위에 따라 넣지 않았다. 브리프 엔진의 "도심 나이트" 룩북 팔레트에 있는 `#ED1E1E`는 화면 장식이 아니라 그 룩(레드 림라이트)을 설명하는 콘텐츠 데이터라 그대로 두었다.

## 캡처

`{before|after}-{화면}-{ko|en}-{1440|390}.webp`. 1440 캡처는 용량 때문에 절반 폭(720)으로 줄였다. `studio-*`는 스튜디오(TWINGS 운영자) 시점의 선별 화면이다. `interaction-*`: 카드 커서 조명, 키보드 포커스, 비교 트레이, 선별 일괄 바, 범위 팝오버.

화면: 홈, 캠페인 상세(개요·콘텐츠 확인), 참여자, 리포트, 크리에이터 후보, 셀프 스튜디오, 스튜디오 결과, 콘텐츠 보관함, 크리에이터, 팀, 브랜드 설정, 새 캠페인, 로그인, 스튜디오 선별·홈.

로그인(`/auth/choose`)은 `components/auth`(소비자 앱과 공유) 범위 밖이라 바꾸지 않았다. 원래 빨강이 없고 흰 바탕이라 before/after가 같다.

## 검증

- 로컬 픽스처만 사용: `npm run db:local` 스냅샷에 후보 8명(공개 5·제외 1·선호 1), 스튜디오 결과 1건, 캠페인 대표 이미지를 로컬에서만 추가했다(커밋하지 않은 스크립트, 실제 고객·크리에이터 데이터 없음). 계정은 `dev:free`(브랜드 관리자), `dev:admin`(TWINGS 운영자).
- `after-owner-checks.json`(56개), `after-studio-checks.json`(8개): 가로 넘침 0, 잘린 콘텐츠 0, 깨진 이미지 0, 페이지 오류 0. before에서는 스튜디오 선별 390폭만 가로 넘침 430px(ko)·579px(en)이었다.
- `a11y-checks.json`:
  - 유리 위 글자 대비(최악 배경 기준): 다크 유리 칩 5.81:1, 미디어 종류 칩 5.23:1, milky 유리 10.25:1, 일괄 바 11.69:1. 보조 글자 `#6e6e78` 흰 바탕 5.04:1, 알라바스터 4.78:1. 블루 `#3875C5` 위 흰 글자 4.65:1(채움·링), 글자용 `#3063A7` 흰 바탕 6.05:1·알라바스터 5.74:1·옅은 블루 바탕 5.53:1, danger 6.6:1.
  - reduced-motion: 전환 시간 0.01ms, 커서 조명 꺼짐, 탭 모핑 호출 0회. 기본 모션에서는 탭 모핑 1회, 커서 조명 좌표 갱신 확인.
  - 키보드: Tab 이동 시 모든 포커스가 2px 블루 외곽선(`#3875C5` 또는 글자용 `#3063A7`).
  - 동시에 흐리는 층(`backdrop-filter`): 홈 5, 비교 트레이를 연 후보 화면 7, 일괄 바를 연 선별 화면 7, 휴대폰 홈 2.
- 그레인 data URI가 실제 계산된 배경으로 들어가는 것을 확인했다(`body`, `.bw-sidebar`). 워크스페이스 CSP에는 `img-src` 제한이 없다.
